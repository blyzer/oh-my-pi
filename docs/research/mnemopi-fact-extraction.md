# Mnemopi model-free fact extraction (gap 2)

Slug `mnemopi-fact-extraction`. Ledger: gap 2, class c (`docs/research/upstream-gap-closure.md:13`). ADR: [0062](../adr/0062-mnemopi-fact-extraction.md).

Evidence base: omp2 at `f4186b783b` (the research branch changes only `docs/`; `crates/`, `extensions/` and `py/` are identical to it) and upstream at `c308970263` (v18.20.0). Citations are `path:line`; upstream paths carry the prefix `upstream:`. Nothing here ran on a Mac with Apple Intelligence, so device behaviour is marked `[INFERENCE]`. A local prototype of slice 1 exists as commit `daab333d13` (section 2.6).

## 1. Upstream

Upstream keeps a deterministic floor under its LLM fact extraction. `heuristicExtractFacts` turns eight English first-person patterns into at most five sentences (`upstream:packages/mnemopi/src/core/extraction.ts:276-315`), and `extractAndStoreFacts` adds pattern rows for metrics, dates, versions and "X uses Y" relations (`upstream:packages/mnemopi/src/core/beam/consolidate.ts:675-783`). They run when no model is available: `llmMode` is `none` (`upstream:packages/coding-agent/src/mnemopi/backend.ts:539`), or it is `smol` and no `memory` role model resolves ("continuing without LLM", `backend.ts:558-563`), which sends `extractFactCategories` down its `!llmAvailable()` branch (`extraction.ts:432-443`). A user who is offline, has no key, or turned the model off still gets recallable facts instead of none.

What shapes a port:

- **Patterns.** Text is whitespace-normalised and split into clauses on `.!?;`, " and " and " but " (`extraction.ts:278,283`). Per clause, case-insensitive regexes capture "my name is", "I am / I work as", "I work at/for", "I live in / am based in", "I use / am using", "I like / love / prefer / enjoy", "I hate / dislike / don't like", and "(I|you) always|never" (`extraction.ts:286-311`). The last needs an explicit subject because an unconstrained pattern stored assistant narrative as instructions (comment `extraction.ts:300-307`; test `upstream:packages/mnemopi/test/extraction.test.ts:220-231`). A hit becomes a sentence-cased string such as "The user prefers dark mode", kept only if longer than 10 characters and not already present (`extraction.ts:264-274`); the list is cut to five (`extraction.ts:72,313`).
- **Tier order.** A configured or host completion runs first. One that returns nothing falls to `localFallback`, whose last step is the heuristic (`extraction.ts:356,405,422,463`). One that raises returns an empty result with no fallback (`extraction.ts:399-404,424-429`). The model is called deterministically, temperature 0 (`extraction.ts:380-381`).
- **Pattern pass.** `extractAndStoreFacts` skips text longer than `PATTERN_FACT_EXTRACTION_MAX_INPUT_CHARS` outright (`consolidate.ts:66,692`). Otherwise it records up to 10 "number + unit" metrics keyed by up to three words before the number, cut at the nearest table pipe, backtick, sentence end or newline (`consolidate.ts:693-744`; regression tests `upstream:packages/mnemopi/test/beam-consolidate-unit.test.ts:357-490`); ISO dates, plus a timeline row when a cue word such as "release" or "deadline" is nearby (`consolidate.ts:747-755`); versions (`consolidate.ts:758-771`), where a bare "x.y" counts only after a version keyword, "v1.2" and "x.y.z" count alone, and slices of longer dotted runs such as IP addresses are rejected (`consolidate.ts:68,73-74,83-88`); the heuristic entity facts (`consolidate.ts:774`); and "X is / uses / runs / owns / depends on Y" relations (`consolidate.ts:776-780`). Negation and decision cues only increment counters; nothing is stored for them (`consolidate.ts:781-782`). It runs on consolidated episode summaries (`consolidate.ts:546`).
- **Storage shape.** Each pattern fact goes to `memoria_facts` and to the s/p/o `facts` table as `subject = key`, `predicate = factType`, `object = value`, with an id hashed from session, type, key, value and source (`consolidate.ts:289-314`). An entity fact is therefore `("fact", "entity", "The user prefers dark mode")` (`consolidate.ts:628`). Fixed confidences: 0.7 entity strings (`consolidate.ts:622`), 0.65 metrics (`:740`), 0.5 dates (`:750`), 0.6 versions (`:768`).
- **Language.** Upstream has a language detector (Russian, German and Spanish by markers; `consolidate.ts:555-612`, `upstream:packages/mnemopi/src/core/beam/helpers.ts:443`) and the model prompt takes a language hint (`extraction.ts:58`), but no heuristic regex is language-aware. Its setting has no local on-device mode (`upstream:packages/coding-agent/src/mnemopi/settings.ts:218-240`); a role-chain model with `api === "local-inference"` is called through `tinyModelClient` (`backend.ts:582-584`).

## 2. omp2 inventory

### 2.1 Extraction is a library seam with no caller

- **Types.** `ExtractionRequest { input, session_id, source_id }` where `input` is the "User-authored framed transcript only" and there is no timestamp (`crates/memory/src/extract.rs:19-28`). `ExtractionLane::complete(&ExtractionRequest) -> Result<Str>` is the "App-owned auxiliary completion boundary" that "resolves none/smol/remote/local-memory-model" (`extract.rs:30-35`). `ExtractedFact { id, subject, predicate, object, confidence }` has no expiry (`extract.rs:37-49`). `extract_and_store` bounds input and output (`extract.rs:70,74`), parses, and persists with `timestamp: None` (`extract.rs:65-93`, `:86`). Bounds: 256 KiB input and output, 16 jobs and 1 MiB per batch (`extract.rs:11,13,15,17`).
- **Protocol.** `parse_facts` accepts exactly five TAB fields (`extract.rs:97,106`), rejects empty or oversized fields (subject 512 B, predicate 256 B, object 4096 B; `extract.rs:113-122`), and derives the id from source id, line number and the triple (`extract.rs:125-133`). No prompt text that asks a model for this protocol exists anywhere in the tree: a search of `crates`, `extensions`, `py` and `docs` finds only the doc comment and the parser (`extract.rs:96,106`).
- **No consumer, no implementor.** Nothing outside `crates/memory/src` references `pending_extractions`, `pending_extraction_count`, `extraction_notifications`, `extract_and_store` or `ExtractionLane` (repository-wide search excluding `.git`, `target` and `docs/knowledge-base`: only `crates/memory/src/{extract,runtime,session,store}.rs`). `crates/envd/src/memory.rs:8-9` says "Prompt sampling and extraction lanes live above the environment, in the higher-level driver memory composition"; `crates/driver` has no such composition (its `omp_memory::` uses are the v1 importer, `crates/driver/src/v1_import/data/memory.rs:37`, and a test fixture, `crates/driver/src/headless/reflection.rs:160`).
- **Retention has no live caller either.** Nothing outside `crates/memory/src` calls `retain_settled`, `retain_periodic`, `retain_force`, `Retainer` or `SessionMemory::enqueue`; `SessionMemory` is named only in `crates/envd/src/memory.rs:21,101-102` (`RegisteredMemoryRuntime::session`, for which I found no caller). The finalizer slot `set_mnemopi` (`crates/driver/src/headless/finalize.rs:100-107`) has no production registrant, only a test (`finalize.rs:169`). What is live: the runtime itself (`crates/envd/src/server/session.rs:39-64`), the `recall`, `reflect` and `retain` tools (`crates/tools/src/memory.rs:186-222`), the `memory://` URL device (`crates/envd/src/tool_url/memory.rs`, runtime lookup `crates/envd/src/tool_url.rs:585`), and `/memory enqueue` (`crates/app/src/chat_services/misc.rs:144-147`, `crates/memory/src/runtime.rs:766`).

### 2.2 Queue, persistence, recall, migration

- **Retention to queue.** `Retainer::retain` builds the extraction text only when `extraction_enabled` (`crates/memory/src/retain.rs:132-135`), from user messages only (`retain.rs:177-187`), and `retain_window` stores the episode and one `extraction_jobs` row in one immediate transaction (`crates/memory/src/store.rs:485-555`, job insert `:531-536`). `SessionMemory` sets `extraction_enabled = llm_mode != None` (`crates/memory/src/session.rs:151,227`). The test `disabled_extraction_lane_retains_without_enqueuing` pins `none` to "no job" (`session.rs:384`).
- **Drain.** `pending_extractions` reads `input, session_id, source_memory_id` oldest first within the batch bounds, and not `created_at` (`store.rs:571-599`, query `:578`). `complete_extraction` inserts facts and deletes the job in one transaction, so "inference failures never call this method and therefore remain retryable" (`store.rs:712-722,724-760`, delete `:751`). Runtime wrappers and the coalesced wake-up channel: `crates/memory/src/runtime.rs:244-245,266,952-971`.
- **Facts table.** `facts(fact_id, session_id, subject, predicate, object, timestamp, source_memory_id, confidence)` (`store.rs:1740-1749`), FTS over `subject predicate object` (`store.rs:1666,1750-1757`). `NewFact` already has `timestamp: Option<&str>` ("Optional source timestamp", `store.rs:1374-1392`). Inserts are `INSERT OR IGNORE` (`store.rs:733-737`), so content-derived ids make replays idempotent.
- **Reads.** `search_facts` (`store.rs:826-857`) is the only recall read of facts (`crates/memory/src/recall.rs:205`, graph voice). Read-by-id falls through to `facts` (`store.rs:936-965`, query `:959`). Facts feed no graph triples: `link::reconcile` derives them from `store.list` records only, "exclusively from authoritative memory content" (`crates/memory/src/link.rs:33-58`). Eviction deletes jobs and facts with their source memory (`store.rs:1602-1605`).
- **Immutability.** "Saves immutable model-extracted facts" (`store.rs:706`); the `memory://` projection tells callers "Extracted facts are immutable; retain a corrected fact instead of editing this projection" (`crates/envd/src/tool_url/memory.rs:195-197`). Newer facts cannot expire older rows.
- **Migration.** `SCHEMA_VERSION = 3` (`store.rs:32`). `migrate` runs under an exclusive transaction, refuses a bank written by a newer version (`store.rs:1214-1219`) and, only when `version < SCHEMA_VERSION`, runs `migrate_authoritative_tables` (column additions; `store.rs:1259-1312`, facts at `:1302-1310`) and `RESET_REBUILDABLE_INDEXES`, which drops triggers, the FTS tables, `memory_embeddings`, `triples` and `memory_links` (`store.rs:1220-1223,1642-1658`), then rebuilds FTS and zeroes the vector and graph generations (`store.rs:1226-1234,1660-1667`). The module is documented "Multiprocess-safe" (`store.rs:1`).
- **Time.** `utc_timestamp()` is RFC 3339 (`store.rs:1548`); `jiff` is already a dependency (`crates/memory/Cargo.toml:24`).

- **Modes.** `MemoryLlmMode { None, Smol (default), Remote, LocalMemoryModel }` (`crates/memory/src/config.rs:113-123`); the field and its default (`config.rs:229,306`). `LocalMemoryModel` is documented as "the configured on-device memory model through the auxiliary lane" (`config.rs:121-122`).
- **Unreachable from a running omp2.** Production builds its settings with `HostSettings::from_con` (`crates/envd/src/server/session.rs:36,55-62`), which sets backend, database path, scoping, autolearn and worktree but not `llm_mode` (`crates/envd/src/host_settings.rs:204-234`). `HostSettings` is built only by `from_con` (`host_settings.rs:257`, `crates/driver/src/v1_import/data/memory.rs:111`, `session.rs:36`). The only reference to `llm_mode` outside `crates/memory/src` is one ADR sentence (`docs/adr/0028-bash-is-an-in-process-interpreter.md:432`). So `none`, `remote` and `local-memory-model` cannot be selected today, and production runs `smol` with `auto_retain = true` (`config.rs:193-195`).

- **Convar mechanism.** `omp_con::var!` with `default` and `flags: archive` (`crates/con/src/macros.rs:48-72`); a default-off bool example (`crates/driver/src/remote_build.rs:44-47`). The memory convars live in `crates/envd/src/host_settings.rs`: `ai_memory_backend` (`:74`) and `ai_mnemopi_scoping` (`:89`) carry `legacy.path` aliases to pi settings (`:85`); `ai_mnemopi_db_path` is at `crates/ai/src/settings.rs:1280`. ### 2.4 Apple FM backend

- **Entry points.** `AppleFm::{load, availability, availability_evidence, generate, complete, stream}` (`crates/ai/src/local/applefm.rs:383-451`). `generate(options, cancel)` takes the single admission permit and runs under `FRAMEWORK_TIMEOUT` = 30 s (`applefm.rs:97,428-435`). Admission does not queue: `apple_admit` uses `try_acquire` and maps a busy permit to `ConcurrentRequests` (`applefm.rs:100-101,1386-1391`), classified `ResourceExhausted` (`:1479`). A background caller therefore fails fast while a chat stream holds the permit.
- **Request.** `AppleFmOptions { prompt, system_prompt, permissive, temperature, max_tokens }` (`applefm.rs:307-318`, builders `:333-351`). The context budget is 4096 tokens, "Apple's documented on-device context budget from TN3193" (`applefm.rs:98-99`). There is no tokenizer; usage is `ceil(bytes / 4)` (`crates/ai/src/local/applefm/platform.rs:823-833`; `AppleFmGeneration` `applefm.rs:356-370`).
- **Availability and errors.** `AppleFmSupportState` has eight states (`applefm.rs:216-236`, classification `:1554-1574`). `AppleFmErrorCode` has fifteen codes, among them `TimedOut`, `ModelUnavailable`, `DeviceNotEligible`, `AppleIntelligenceNotEnabled`, `ModelNotReady`, `ContextOverflow`, `GuardrailBlocked`, `UnsupportedLocale`, `DecodingFailure`, `RateLimited`, `ConcurrentRequests` (`applefm.rs:113-147`). Non-macOS builds compile a stub whose availability is `unsupported_operating_system` and whose `generate` returns `ModelUnavailable` (`applefm.rs:63-95`).
- **Existing memory use.** `crates/memory/src/aux_lane.rs` re-ranks recall candidates through `aux_session()` and `AppleFmSession::respond`, falling back to the original order on any error (`aux_lane.rs:1-46`). `respond` has no token cap, temperature or cancellation and blocks on the runtime handle (`applefm.rs:507-537`). Feature chain: `omp-memory/apple-aux-memory` to `omp-ai/apple-aux-memory` to `local-applefm` (`crates/memory/Cargo.toml:18`, `crates/ai/Cargo.toml:20-21`). **No recipe or workflow builds `omp-memory` with that feature** (search of `justfile`, `.github`, `scripts`), so a lane under it is not exercised by CI today.
- **Chat path.** The driver composes the same backend as the `local` provider route (`crates/driver/src/registry.rs:1589-1604`, feature `local-applefm`, `crates/app/Cargo.toml:51`). A device smoke path exists (`crates/ai/examples/applefm_smoke.rs:1-14`, `crates/ai/Cargo.toml:12-14`).
- **Policy.** ADR 0023: chores go to the `tiny` role (`0023:22-24`); local inference runs under the same admission, cancellation and lifecycle (`:33-35`); "A pinned local tiny model is NEVER silently promoted to a hosted one ... fallback is an explicit caller policy" (`:36-38`). ADR 0042 extends the existing `omp-ai::local::applefm` boundary rather than adding another (`docs/adr/0042-apple-pcc-integration.md:9,22`).

### 2.5 Dependencies and conventions

`omp-memory` depends on jiff, serde, serde_json, thiserror, tokio, rusqlite and others (`crates/memory/Cargo.toml:20-34`), not on `regex` or `toml`; both are workspace dependencies (`Cargo.toml:215,253`). The crate's one lane error is the coarse `Error::AuxiliaryCompletion` (`crates/memory/src/lib.rs:63-65`).

## 3. Class

**c (port).** The capability exists upstream and is missing here: nothing in omp2 produces a fact without a model, and in the running product nothing produces facts at all (2.1, 2.3). It is not a, and not b: without it, a user who is offline or sets the model off gets no extracted facts, and the owner has asked for it.

The port is not literal, for three reasons. (1) Upstream stores key/value rows (`subject = "version"`, `predicate = "version"`; `consolidate.ts:307-313`), but omp2 indexes `subject predicate object` as text (`store.rs:1666`), so rows must be real triples. (2) Upstream's regexes are English first-person only and store nothing for decisions or dependencies (`consolidate.ts:781-782`). (3) The owner's requirements for Spanish, structured tool results first, `valid_until` and an Apple FM lane have no upstream counterpart. These ship as later slices of the same ADR; if the owner prefers to track them as class d, slices 3 to 6 separate cleanly.

## 4. Options

### 4.1 The rule extractor

- **A. Literal port** of `heuristicExtractFacts` and the `extractAndStoreFacts` patterns. Cost: low, one module. Fit: poor. English only; key/value rows would index as "version version 1.2.3"; no decisions, dependencies or `valid_until`.
- **B. Build on omp2's seams.** A pure `rules` module in `omp-memory` returning `ExtractedFact` triples over a closed predicate vocabulary; persisted through `NewFact` and `INSERT OR IGNORE`; run inline at retention in `none` mode and as a worker fallback. Upstream's guards and test vectors come across as test cases. Cost: medium. Fit: best; reuses `NewFact`, the id shape of `parse_facts` and the existing bounds.
- **C. Rules as an `ExtractionLane`** emitting `FACT` lines that `parse_facts` reads back. Cost: low. Fit: poor. It formats and re-parses text on every pass, loses typed fields, needs TAB and newline escaping, and `none` mode has no lane or queue to host it.
- **D. A model for Spanish and technical facts.** Rejected: against "deterministic rules first, a model only where rules cannot", against the owner's rule that rules run when no model is set, and useless offline.
- **E. A Python extension.** Rejected: the work belongs inside the retention transaction in Rust, and extensions (ADR 0036, `docs/adr/0036-python-for-extensions.md:37`) have no retention hook to join it.

**Choice: B**, carrying A's guards and vectors.

### 4.2 Storing expiry

- **(i) Additive nullable column, no version bump.** Chosen (prototype).
- **(ii) Bump `SCHEMA_VERSION` to 4.** The existing path. A bump drops `memory_embeddings`, `triples`, `memory_links` and the FTS tables and zeroes the vector and graph generations (`store.rs:1220-1234,1642-1658`), so every user re-embeds, and a bank opened by the new binary can no longer be opened by an older one (`store.rs:1217-1219`).
- **(iii) A side table** of expiries: a join on every recall and a second write path.
- **(iv) Encode expiry in text** (object or timestamp): not queryable, ambiguous.

**Choice (i).** The column is nullable, no existing statement, trigger or index names it (`facts_ai` and `facts_au` use only subject, predicate and object; `store.rs:1750-1757`), and old binaries keep working: their explicit-column INSERT and SELECT are unaffected, and they simply do not filter. The rule for later changes: an additive nullable column nothing else touches is added by `add_column_if_missing` on every open; anything that changes meaning or derived indexes bumps. This departs from the bump-per-change path and is recorded as an owner question (O3).

### 4.3 How tool results reach the extractor

- **(i) A typed `ToolObservation { tool, target, output }` input** with named-field parsers. Chosen. Additive: `RetentionMessage` and its literals are untouched (`retain.rs:43-52`).
- **(ii) Sniff `Tool`-role message text.** Rejected: `RetentionMessage` carries no tool name or path (`retain.rs:43-52`), so sniffing guesses structure.
- **(iii) Leave it to the model.** Rejected: contradicts the owner's "prefer structured tool results".

Trust: `ExtractionRequest.input` is user-authored only (`extract.rs:22`) and stays so; tool output feeds rules only, never a model lane.

### 4.4 Apple FM lane

- **Placement.** (a) A module beside `aux_lane.rs` behind `apple-aux-memory`: chosen; `omp-ai` cannot depend on `omp-memory` (the dependency runs the other way, `Cargo.toml:18,22`), and `crates/driver` has no memory composition yet. (b) A host-injected lane in `omp-driver`: closer to ADR 0049's direction that vendor names leave core crates (`docs/adr/0049-tiered-integration-architecture.md:15,47`), but it needs the composition that does not exist. Recorded as O7.
- **Call path.** (a) `AppleFm::generate` with `AppleFmOptions`: chosen. It gives a token cap, temperature, a cancellation token, the 30 s deadline and admission (`applefm.rs:428-435`). (b) `AppleFmSession::respond`: no cap or cancellation, hard-wired scoring prompt (`applefm.rs:507-537`). (c) The `local` provider route (`registry.rs:1589`): chat-event streaming for a one-shot job.

### 4.5 Fallback

Explicit policy, as ADR 0023 requires (`0023:36-38`). When the lane reports the model unavailable, run the rules (never another model). When it fails transiently, retry. Detailed in S5 and S6.

## 5. Plan

Six PR-sized slices. Every convar is declared in `crates/envd/src/host_settings.rs` beside `SV_WORKTREE_BASE` (`:139`), read in `HostSettings::from_con` (`:204-234`) and carried to the runtime in new `#[serde(default)]` fields of `MnemopiSettings` (pattern `config.rs:196-198`), so `omp-memory` gains no `omp-con` dependency. Names use the `sv_` prefix because they are omp2-native host policy with no upstream counterpart (the `ai_mnemopi_*` family carries pi aliases, `host_settings.rs:85`). All Rust verification runs remotely: `just remote-plain-test omp-memory` and a clippy run (`AGENTS.md:90-94`).

### S1. Expiring facts, gated

- **Contents.** Rebase `daab333d13` (base `b8032a94ad`) onto current omp2. Keep its pieces (2.6). Add: convar `sv_memory_fact_expiry` (bool, default false, `flags: archive`) and `MnemopiSettings.fact_expiry`; plumb it to `BankStore` (a builder like `with_working_policy`) and to `parse_facts` (an options argument; its only production caller is `extract.rs:77`). Off: a six-field line is rejected exactly as today (`extract.rs:106`), recall does not filter, no non-NULL `valid_until` comes from the model protocol. The column and the nine-column INSERT are unconditional; the column is inert while the gate is off. Document the sixth field on `parse_facts`.
- **Acceptance.** Gate off: the 12 existing `omp-memory` tests pass unchanged; a six-field line counts as rejected; an expired row is still returned by recall. Gate on: the prototype's 15 tests pass. `SCHEMA_VERSION` stays 3 and `user_version` is unchanged after migration. The old eight-column INSERT text succeeds against a migrated table. Two stores opening a pre-column bank at once leave exactly one column (the open holds an exclusive transaction, `store.rs:1215`). Read-by-id returns expired facts. `valid_until == now` is expired.
- **Tests.** The 15 prototype tests, plus gate-off identity, old-statement compatibility and concurrent-open tests.

### S2. Rule core, English identity and preference, inline in `none` mode

- **Contents.** A pure module `crates/memory/src/extract/rules/`: `extract(&RuleInput) -> Vec<ExtractedFact>`, no I/O and no clock. Pipeline: structured pass, then prose pass (the structured pass is empty until S3). English identity and preference family at upstream parity but emitting triples over a closed vocabulary: `name`, `is`, `works_at`, `lives_in`, `uses`, `prefers`, `dislikes`, `instruction` (the `user` subject). Guards: questions, hypotheticals ("if", "unless"), negation before the verb, fenced code, and any clause near a secret word (password, token, api key, secret). Caps: at most 32 facts per source memory (upstream caps at 5 and 10, `extraction.ts:313`, `consolidate.ts:744`), subject at most 128 B, object at most 240 B (inside the parser limits, `extract.rs:116-119`). Dedupe on the triple. Ids: `rule_` plus 24 hex of `Hash32` over source id, rule id and triple, so replays are idempotent (id shape as `extract.rs:125-133`). Confidence 0.7 (upstream 0.7, `consolidate.ts:622`). Wiring: `Retainer` builds the extraction text when `extraction_enabled || rule_facts`; when only rules are on it runs them and passes the facts in `RetainedWindow` so the episode and its facts commit in one transaction (`retain.rs:132-155`, `store.rs:485-555`), with `NewFact.timestamp` set to the episode time. Framing markers are stripped first (`strip_protocol_markers`, `retain.rs:212`).
- **Convars.** `sv_memory_rule_facts` (bool, default false) to `MnemopiSettings.rule_facts`; and `sv_memory_llm_mode` (default `smol`, today's value) to `MnemopiSettings.llm_mode`, offering `none` and `smol` only, because `none` is otherwise unreachable (2.3). Dependency: `regex.workspace = true` (refresh `Cargo.lock` with `cargo metadata --offline`).
- **Acceptance.** Gate off: `disabled_extraction_lane_retains_without_enqueuing` (`session.rs:384`) and all existing tests unchanged; no facts. Gate on and `none`: after retaining "My name is Ada. I work at Example Corp and I prefer dark mode." recall finds the three triples (upstream vector `extraction.test.ts:93-102`). Gate on and `smol`: no rule facts and the job is enqueued as today (owner decision D1). Retaining the same window twice leaves one row per fact. Eviction removes the rule facts with the episode (`store.rs:1602-1605`). Adversarial inputs (256 KiB of "I am " repeated, 1 MiB without separators) stay within 32 facts and finish (asserted on counts, not wall-clock).
- **Tests.** Upstream parity vectors (`extraction.test.ts:205-231`: Berlin and TypeScript; "never use semicolons" and "always wrap lines"; the subjectless narrative that must yield nothing), each with a negative; session-level tests through `retain_settled`.

### S3. Structured tool observations first

- **Contents.** `ToolObservation { tool, target, output }` and an additive `SessionMemory` and `Retainer` entry that takes observations next to messages. Named-field parsers over typed serde structs: `package.json` (name, version, dependencies, devDependencies, engines, packageManager), `Cargo.toml` (package name, version, rust-version; dependency keys with a version string, a table, or `workspace = true`), and version banners from `bash` observations whose command is exactly `<tool> --version`, `-V` or `version` for a closed tool set (rustc, cargo, node, npm, python, go, bun, git). Selection keys on tool and target, never on sniffing the output. Vocabulary added: `version`, `depends_on`, `dev_depends_on`, `requires_runtime`. Subject is the manifest's package name (or the tool). Confidence 0.9. Bounds: 1 MiB per observation, 64 dependencies per manifest, the 32-fact cap. Free-text fields (description, scripts, readme) and any key that looks like a credential are never read. Text a parser consumed is excluded from the prose pass.
- **Gate.** `sv_memory_rule_facts`.
- **Acceptance.** Golden facts for each parser and fixture. A manifest yields no prose facts. Malformed JSON or TOML yields zero facts and does not fail retention. A fixture containing `"token"` and `"password"` fields produces no fact containing either value. An observation with an unknown tool or target is ignored by the structured pass and not parsed as prose.

### S4. Technical and decision rules in English and Spanish, absolute dates, `valid_until` from rules

- **Contents.** Families, each in both languages and each with negatives: versions (upstream's `isVersionMention` guard ported, plus Spanish cue words "versión", "actualizamos", "subimos", "migramos"); dependencies ("depends on", "requires", "installed"; "depende de", "requiere", "instalamos"); decisions ("decided", "chose X over Y", "going with"; "decidimos", "elegimos X en lugar de Y", "optamos por", "nos quedamos con") producing `decided` and `rejected`; supersession ("no longer use", "dropped"; "ya no usamos", "dejamos de usar", "migramos de X a Y") producing `stopped_using` and `uses`; explicit bounds producing `deadline` or `status` with `valid_until` ("until", "expires", "deadline"; "hasta", "vence", "fecha límite"). Spanish identity and preference mirror the English family ("me llamo", "trabajo en", "vivo en", "uso", "me gusta", "prefiero", "odio"). Matching is accent-insensitive by listing both forms; neutral Spanish, no voseo. Dates: ISO, English month names, Spanish month names ("15 de marzo de 2027"), built on `jiff`; a date-only bound is valid through that UTC day. Numeric dates (`03/04/2027`) and relative expressions ("tomorrow", "mañana", "for two weeks") are **not** parsed in v1: a numeric date is ambiguous, and a relative one would resolve against the window's retention time because `RetentionMessage` has no timestamp (`retain.rs:43-52`).
- **Gate.** `sv_memory_rule_facts`. The recall filter that hides expired rule facts is `sv_memory_fact_expiry` (S1); with it off the bound is recorded but inert.
- **Acceptance.** Target vectors (paired English and Spanish): "We upgraded tokio to 1.40.0" and "Actualizamos tokio a la versión 1.40.0" give `(tokio, version, 1.40.0)`; "omp-memory depends on jiff" and "omp-memory depende de jiff" give `(omp-memory, depends_on, jiff)`; "We decided on SQLite instead of Postgres" and "Decidimos usar SQLite en lugar de Postgres" give `(project, decided, SQLite)` and `(project, rejected, Postgres)`; "The deadline is 2027-03-15" and "La fecha límite es el 15 de marzo de 2027" give `(project, deadline, 2027-03-15)` with `valid_until` `1805155200000` (2027-03-16T00:00Z, computed independently). Negatives: questions ("Do we use tokio 1.40?", "¿Usamos tokio 1.40?"), negation ("I don't use Postgres"), hypotheticals, a password sentence, and an IP address (`10.0.0.1`). Upstream version regressions are ported (`beam-consolidate-unit.test.ts:424,442,459,476,490`). Date tests include a leap day, a year rollover, invalid dates (`2027-02-30`) and each month name.

### S5. Extraction worker, typed lane faults, explicit fallback policy

- **Contents.** A typed `LaneFault { Unavailable, Rejected, Transient }` carried by a new `Error` variant (typed, no string payload, ADR 0035), leaving `AuxiliaryCompletion` in place. A bounded worker function in `omp-memory`: read `pending_extractions` (`store.rs:571-599`), call the lane, then `parse_facts` and `complete_extraction`. `Err(Unavailable)` with an explicit `FallbackPolicy::Rules` and `sv_memory_rule_facts` on runs the rules and completes the job; without the policy the job stays queued. `Rejected` (a refusal that will recur) runs the rules if allowed, else acknowledges the job with no facts so it cannot loop. `Transient` leaves the job queued and the pass continues with the next job; backoff and a per-pass job and time budget bound the loop. Cancellation leaves unprocessed jobs queued. `ExtractionReport` and tracing events record the extractor (model, rules, rules-fallback) and the typed reason. The job's `created_at` is read for the fallback's `NewFact.timestamp` (`store.rs:578`). Spawning the worker belongs to the host composition that does not exist yet (O2); this slice is library code and tests, inert until a host calls it.
- **Gate.** Inert without a caller; the first caller (S6) is gated.
- **Acceptance (fake lane).** `Ok` stores model facts and removes the job. `Unavailable` with the rules policy stores rule facts and removes the job. `Unavailable` without it leaves the job queued. `Transient` leaves it queued while other jobs complete. `Rejected` acknowledges. Cancellation mid-pass leaves unprocessed jobs queued. No fact is stored from a failed lane. The pass honours its job and byte budget. A replay creates no duplicate rows. A test asserts that `Unavailable` never reaches any other lane (ADR 0023 rule 4).

### S6. Apple FM lane for `local-memory-model`

- **Contents.** A module `crates/memory/src/aux_extract.rs` behind `apple-aux-memory`, an `ExtractionLane` over `AppleFm::generate`. One availability probe per pass (`availability_evidence`, `applefm.rs:406-424`). One bounded request per chunk: input split on paragraph then sentence boundaries into chunks of at most 4 KiB, at most 8 chunks per job (rules cover nothing beyond that in v1), each request `AppleFmOptions::new(chunk).system_prompt(PROTOCOL).temperature(0.0).max_tokens(512)` under the 30 s deadline with a cancellation token tied to worker shutdown. The system prompt is fixed and golden-tested: the `FACT` line protocol with the closed vocabulary from S2 to S4, and the optional sixth field only when `sv_memory_fact_expiry` is on. The lane keeps only lines starting with `FACT` plus TAB, so extra prose is dropped and `parse_facts` stays the single parser. Fault mapping: unavailable (`UnsupportedOperatingSystem`, `UnsupportedArchitecture`, `FrameworkUnavailable`, `DeviceNotEligible`, `SettingsDisabled`, `ModelNotReady`, and `ModelUnavailable` at request time) maps to `Unavailable`, so the rules run; `ContextOverflow` splits the chunk in half and retries once, then skips it; `GuardrailBlocked`, `UnsupportedLocale`, `DecodingFailure` skip the chunk (counted in the report); `TimedOut`, `RateLimited`, `ConcurrentRequests`, `Runtime`, `Cancelled` map to `Transient` for the whole job. A job that skipped chunks keeps the other chunks' facts. Selecting `local-memory-model` is exposed by widening `sv_memory_llm_mode`.
- **Chunk budget.** The window is 4096 tokens for instructions, prompt and answer (`applefm.rs:99`); there is no tokenizer and the backend estimates `ceil(bytes / 4)` (`platform.rs:823-833`). Reserving about 1 KiB for instructions, 512 tokens of answer and a quarter of the window as margin leaves roughly 2300 tokens. A 4 KiB chunk plus the prompt stays under the window even at 1.5 bytes per token (about 3.9k of 4.1k tokens). The figure is conservative and `[INFERENCE]` until measured on a device with `applefm_smoke`.
- **Gate.** `sv_memory_local_extraction` (bool, default false), plus `llm_mode = local-memory-model`, plus the `apple-aux-memory` cargo feature. Anything missing resolves to `Unavailable`.
- **Acceptance.** With a fake generator (the `apple-aux-memory` build compiles on Linux against the non-macOS stub, `applefm.rs:63-95`): every row of the fault table maps as above; every chunk is at most 4 KiB, on a character boundary, at most 8 per job, and the chunks reassemble to the input apart from trimmed whitespace; the prompt matches its golden; a busy permit never blocks and the job stays queued; output lines that are not `FACT` lines are dropped; unavailability runs the rules and never another model. **CI:** add a recipe that tests `omp-memory` with `--features apple-aux-memory` and wire it into the Linux check, because no job builds that feature today (2.4). A macOS-only `#[ignore]` smoke test, modelled on `applefm_smoke`, runs a real extraction on a device.

## 6. Open questions

- **O1. Meaning of "no memory model is set".** I read it as: `llm_mode = none`, or the configured lane reports `Unavailable` and the explicit policy is `Rules`. That matches upstream (`backend.ts:539,558-563`) and the Apple FM requirement. The narrow reading (`none` only) leaves the rules unreachable under the default `smol`. A model that is available and fails transiently is retried, not replaced (`store.rs:712-715`, ADR 0023 rule 4). Needs confirmation.
- **O2. Wiring is outside this work.** No code calls settled-turn or shutdown retention, no worker drains the queue, no lane exists, and `llm_mode` has no control (2.1, 2.3). Slices 2 to 6 are tested at the `omp-memory` boundary but a user sees nothing until a host composes retention, the worker and a lane. Who owns that composition?
- **O3. No `SCHEMA_VERSION` bump.** The prototype adds the column without bumping, a departure from the bump-per-change path (`store.rs:1220-1223`). Reasons in 4.2. Alternative: bump to 4 and accept the index reset and the older-binary lock-out.
- **O4. Date-only bounds are UTC.** "Valid through that day" means until the next UTC midnight. Local time is the alternative.
- **O5. Relative and numeric dates are out of v1.** Needs message timestamps in `RetentionMessage` and a locale rule for numeric dates.
- **O6. Supersession.** Facts are immutable (`store.rs:706`, `tool_url/memory.rs:195-197`), so a newer fact cannot expire an older one. The rules emit `stopped_using` and `uses` facts instead. No mutation path is proposed.
- **O7. ADR 0049 and the vendor name in a core crate.** The lane follows the `aux_lane.rs` precedent in `omp-memory` because `omp-ai` cannot depend on `omp-memory` and the driver has no memory composition. Moving it behind a host-injected lane is the alternative once that composition exists.
- **O8. Tool observations.** No producer exists (`RetentionMessage` has no tool name or path). Trust: tool text feeds rules through named-field parsers only, never a model lane. Provenance is carried by the `rule_` id prefix; a `facts.extractor` column is the alternative.
- **O9. Apple FM guardrails.** `permissive` is off (framework guardrails) in the plan; `GuardrailBlocked` skips a chunk. Whether to use the permissive content-transformations mode needs device evidence. Per-chunk rule coverage for skipped chunks would need a richer lane return type.
- **O10. Chunk size and token budget** need device measurement (2.4, S6).
- **O11. Gate granularity.** Four convars (`sv_memory_fact_expiry`, `sv_memory_rule_facts`, `sv_memory_llm_mode`, `sv_memory_local_extraction`). Alternative: one enum.
- **O12. Languages.** Spanish only in this ADR. Upstream's detector knows Russian and German (`consolidate.ts:555-612`); each language needs reviewed test vectors.
- **O13. Constants.** The 32-fact cap and the confidence bands (0.9 structured, 0.7 prose, 0.6 decisions and bounds) are starting values anchored on upstream's 0.5 to 0.7 (`consolidate.ts:622,740,750,768`).
- **Constraint check.** Additive only: every gate is default-off or default-unchanged, and no existing tool, skill, convar, hook, URL scheme or CLI command changes; the one departure from an existing path is O3. Vendor code: no new vendor name enters core beyond the existing `aux_lane.rs` precedent (O7). ADR 0024: no tool or roster family added. ADR 0036: Rust only, no extension. ADR 0006: the rules execute nothing and read no files. ADR 0023: fallback is an explicit policy and never reaches a hosted model. No `pi` identity: crates, convars and ids are `omp-*`, `sv_*` and `rule_`.

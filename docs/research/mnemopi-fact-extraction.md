## 1. Upstream

Upstream keeps a deterministic floor under its LLM fact extraction. `heuristicExtractFacts` turns eight English first-person patterns into at most five sentences (`upstream:packages/mnemopi/src/core/extraction.ts:276-315`), and `extractAndStoreFacts` adds pattern rows for metrics, dates, versions and "X uses Y" relations (`upstream:packages/mnemopi/src/core/beam/consolidate.ts:675-783`). They run when no model is available: `llmMode` is `none` (`upstream:packages/coding-agent/src/mnemopi/backend.ts:539`), or it is `smol` and no `memory` role model resolves ("continuing without LLM", `upstream:packages/coding-agent/src/mnemopi/backend.ts:558-563`), which sends `extractFactCategories` down its `!llmAvailable()` branch (`upstream:packages/mnemopi/src/core/extraction.ts:432-443`). A user who is offline, has no key, or turned the model off still gets recallable facts instead of none.

What shapes a port:

- **Patterns.** Text is whitespace-normalised and split into clauses on `.!?;`, " and " and " but " (`upstream:packages/mnemopi/src/core/extraction.ts:278,283`). Per clause, case-insensitive regexes capture "my name is", "I am / I work as", "I work at/for", "I live in / am based in", "I use / am using", "I like / love / prefer / enjoy", "I hate / dislike / don't like", and "(I|you) always|never" (`upstream:packages/mnemopi/src/core/extraction.ts:286-311`). The last needs an explicit subject because an unconstrained pattern stored assistant narrative as instructions (comment `upstream:packages/mnemopi/src/core/extraction.ts:300-307`; test `upstream:packages/mnemopi/test/extraction.test.ts:220-227`). A hit becomes a sentence-cased string such as "The user prefers dark mode", kept only if longer than 10 characters and not already present (`upstream:packages/mnemopi/src/core/extraction.ts:264-274`); the list is cut to five (`upstream:packages/mnemopi/src/core/extraction.ts:72,313`).
- **Tier order.** A configured or host completion runs first. One that returns nothing falls to `localFallback`, whose last step is the heuristic (`upstream:packages/mnemopi/src/core/extraction.ts:356,405,422,463`). One that raises returns an empty result with no fallback (`upstream:packages/mnemopi/src/core/extraction.ts:399-404,424-429`). The model is called deterministically, temperature 0 (`upstream:packages/mnemopi/src/core/extraction.ts:380-381`).
- **Pattern pass.** `extractAndStoreFacts` skips text longer than `PATTERN_FACT_EXTRACTION_MAX_INPUT_CHARS` outright (`upstream:packages/mnemopi/src/core/beam/consolidate.ts:66,692`). Otherwise it records up to 10 "number + unit" metrics keyed by up to three words before the number, cut at the nearest table pipe, backtick, sentence end or newline (`upstream:packages/mnemopi/src/core/beam/consolidate.ts:693-744`; regression tests `upstream:packages/mnemopi/test/beam-consolidate-unit.test.ts:357-490`); ISO dates, plus a timeline row when a cue word such as "release" or "deadline" is nearby (`upstream:packages/mnemopi/src/core/beam/consolidate.ts:747-755`); versions (`upstream:packages/mnemopi/src/core/beam/consolidate.ts:758-771`), where a bare "x.y" counts only after a version keyword, "v1.2" and "x.y.z" count alone, and slices of longer dotted runs such as IP addresses are rejected (`upstream:packages/mnemopi/src/core/beam/consolidate.ts:68,73-74,83-88`); the heuristic entity facts (`upstream:packages/mnemopi/src/core/beam/consolidate.ts:774`); and "X is / uses / runs / owns / depends on Y" relations (`upstream:packages/mnemopi/src/core/beam/consolidate.ts:776-780`). Negation and decision cues only increment counters; nothing is stored for them (`upstream:packages/mnemopi/src/core/beam/consolidate.ts:781-782`). It runs on consolidated episode summaries (`upstream:packages/mnemopi/src/core/beam/consolidate.ts:546`).
- **Storage shape.** Each pattern fact goes to `memoria_facts` and to the s/p/o `facts` table as `subject = key`, `predicate = factType`, `object = value`, with an id hashed from session, type, key, value and source (`upstream:packages/mnemopi/src/core/beam/consolidate.ts:289-314`). An entity fact is therefore `("fact", "entity", "The user prefers dark mode")` (`upstream:packages/mnemopi/src/core/beam/consolidate.ts:628`). Fixed confidences: 0.7 entity strings, 0.65 metrics, 0.5 dates and 0.6 versions (`upstream:packages/mnemopi/src/core/beam/consolidate.ts:622,740,750,768`).
- **Language.** Upstream has a language detector (Russian, German and Spanish by markers; `upstream:packages/mnemopi/src/core/beam/consolidate.ts:555-612`, `upstream:packages/mnemopi/src/core/beam/helpers.ts:443`) and the model prompt takes a language hint (`upstream:packages/mnemopi/src/core/extraction.ts:58`), but no heuristic regex is language-aware. Its setting has no local on-device mode (`upstream:packages/coding-agent/src/mnemopi/settings.ts:218-240`); a role-chain model with `api === "local-inference"` is called through `tinyModelClient` (`upstream:packages/coding-agent/src/mnemopi/backend.ts:582-584`).

## 2. omp2 inventory

### 2.1 The seam, its protocol and the prompt that exists

- **Types.** `ExtractionRequest { input, session_id, source_id }` where `input` is the "User-authored framed transcript only" and there is no timestamp (`crates/memory/src/extract.rs:19-28`). `ExtractionLane::complete(&ExtractionRequest) -> Result<Str>` is the "App-owned auxiliary completion boundary" that "resolves none/smol/remote/local-memory-model" (`extract.rs:30-35`). `ExtractedFact { id, subject, predicate, object, confidence }` has no expiry (`extract.rs:37-49`). `extract_and_store` bounds input and output (`extract.rs:70,74`), parses, and persists with `timestamp: None` (`extract.rs:65-93`, `:86`). Bounds: 256 KiB input and output, 16 jobs and 1 MiB per batch (`extract.rs:11,13,15,17`).
- **Protocol.** `parse_facts` accepts exactly five TAB fields (`extract.rs:97,106`), rejects empty or oversized fields (subject 512 B, predicate 256 B, object 4096 B; `extract.rs:113-122`), and derives the id from source id, line number and the triple (`extract.rs:125-133`).
- **The prompt that exists does not match.** `crates/agent/prompts/modes/memory-pipeline.md:1-9` is "a precise long-term memory extractor" that must "output one short plain-text fact per line with no bullets, numbering, labels, JSON, or commentary" and "exactly NO_FACTS" when nothing qualifies. `parse_facts` rejects that output (it needs five TAB fields, `extract.rs:106`). No source references the file by name (search of `.rs`, `.md`, `.py`, `.toml`, `.kdl`; a generic prompt-directory loader would still expose it and I did not check one). No prompt asks for the `FACT` protocol; its only mention is the doc comment (`extract.rs:96`). The lane's prompt is therefore new work; the existing file is not edited.

### 2.3 Queue, persistence, recall, migration, durability

- **Retention to queue.** `Retainer::retain` builds the extraction text only when `extraction_enabled` (`retain.rs:132-135`), from user messages only (`retain.rs:177-187`), and `retain_window` stores the episode and one `extraction_jobs` row in one immediate transaction (`store.rs:485-555`, job insert `:531-536`). It needs the complete transcript: it counts user turns against a durable cursor and slices from the first unretained one (`retain.rs:109-127`). `SessionMemory` sets `extraction_enabled = llm_mode != None` (`session.rs:151,227`). The test `disabled_extraction_lane_retains_without_enqueuing` pins `none` to "no job" (`session.rs:384`).
- **Drain.** `pending_extractions` reads `input, session_id, source_memory_id` oldest first within the batch bounds, and not `created_at` (`store.rs:571-599`, query `:578`). `complete_extraction` inserts facts and deletes the job in one transaction, so "inference failures never call this method and therefore remain retryable" (`store.rs:712-722,724-760`, delete `:751`). Runtime wrappers and the coalesced wake-up channel: `runtime.rs:244-245,266,952-971`.
- **Facts table.** `facts(fact_id, session_id, subject, predicate, object, timestamp, source_memory_id, confidence)` (`store.rs:1740-1749`), FTS over `subject predicate object` (`store.rs:1666,1750-1762`). `NewFact` already has `timestamp: Option<&str>` ("Optional source timestamp", `store.rs:1374-1392`). Inserts are `INSERT OR IGNORE` (`store.rs:733-737`), so content-derived ids make replays idempotent.
- **Reads.** `search_facts` (`store.rs:826-857`) is the only recall read of facts (`recall.rs:205`, graph voice). Read-by-id falls through to `facts` (`store.rs:936-965`, query `:959`). Facts feed no graph triples: `link::reconcile` derives them from `store.list` records only (`link.rs:33-58`).
- **Durability.** Working-memory eviction deletes an episode's embeddings, jobs, facts, triples and links with it (`store.rs:1599-1613`) after 24 hours or beyond 1000 rows per session (`config.rs:263-268`). Consolidation promotes working rows to episodic rows with the same ids (`store.rs:611-640`) and is run by `MemoryRuntime::enqueue` (`runtime.rs:764-778`), which `SessionMemory::enqueue` calls after a forced retention (`session.rs:160-169`). `SessionMemory::shutdown_flush` is the bounded close-time force retention (30 s default, `config.rs:281-283`; `session.rs:171-209`) and does not consolidate. So extracted facts outlive a day only when their episode was consolidated.
- **Immutability.** "Saves immutable model-extracted facts" (`store.rs:706`); the `memory://` projection tells callers "Extracted facts are immutable; retain a corrected fact instead of editing this projection" (`crates/envd/src/tool_url/memory.rs:195-197`). Newer facts cannot expire older rows.
- **Migration.** `SCHEMA_VERSION = 3` (`store.rs:32`). `migrate` runs under an exclusive transaction, refuses a bank written by a newer version (`store.rs:1214-1219`) and, only when `version < SCHEMA_VERSION`, runs `migrate_authoritative_tables` (column additions; `store.rs:1259-1312`, facts at `:1302-1310`) and `RESET_REBUILDABLE_INDEXES`, which drops triggers, the FTS tables, `memory_embeddings`, `triples` and `memory_links` (`store.rs:1220-1223,1642-1658`), then rebuilds FTS and zeroes the vector and graph generations (`store.rs:1226-1234,1660-1667`). The module is documented "Multiprocess-safe" (`store.rs:1`).
- **Time.** `utc_timestamp()` is RFC 3339 (`store.rs:1548`); `jiff` is already a dependency (`crates/memory/Cargo.toml:24`).

### 2.5 Apple FM backend

- **Entry points.** `AppleFm::{load, availability, availability_evidence, generate, complete, stream}` (`applefm.rs:383-451`). `generate(options, cancel)` takes the single admission permit and runs under `FRAMEWORK_TIMEOUT` = 30 s (`applefm.rs:97,428-435`). Admission does not queue: `apple_admit` uses `try_acquire` and maps a busy permit to `ConcurrentRequests` (`applefm.rs:100-101,1386-1391`), classified `ResourceExhausted` (`:1479`). A background caller therefore fails fast while a chat stream holds the permit.
- **Request.** `AppleFmOptions { prompt, system_prompt, permissive, temperature, max_tokens }` (`applefm.rs:307-318`, builders `:333-351`). The context budget is 4096 tokens, "Apple's documented on-device context budget from TN3193" (`applefm.rs:98-99`). There is no tokenizer; usage is `ceil(bytes / 4)` (`platform.rs:823-833`; `AppleFmGeneration` `applefm.rs:356-370`).
- **Availability and errors.** `AppleFmSupportState` has eight states (`applefm.rs:216-236`, classification `:1554-1574`). `AppleFmErrorCode` has fifteen codes, among them `TimedOut`, `ModelUnavailable`, `DeviceNotEligible`, `AppleIntelligenceNotEnabled`, `ModelNotReady`, `ContextOverflow`, `GuardrailBlocked`, `UnsupportedLocale`, `DecodingFailure`, `RateLimited`, `ConcurrentRequests` (`applefm.rs:113-147`). - **Existing memory use, and it is never compiled.** `aux_lane.rs` re-ranks recall candidates through `aux_session()` and `AppleFmSession::respond` behind `apple-aux-memory` (`aux_lane.rs:1-46`); `respond` has no token cap, temperature or cancellation and blocks on the runtime handle (`applefm.rs:507-537`). The feature chain is `omp-memory/apple-aux-memory` to `omp-ai/apple-aux-memory` to `local-applefm` (`crates/memory/Cargo.toml:18`, `crates/ai/Cargo.toml:20-21`), but no manifest enables `omp-memory/apple-aux-memory`: the workspace dependency has `default-features = false` (`Cargo.toml:156`) and the app and driver enable only `omp-memory/local-embedding` (`crates/app/Cargo.toml:56`, `crates/driver/Cargo.toml:25`). The required Linux check runs `just remote-heavy`, a default-feature workspace build (`justfile:154-157`), so no build or test compiles the lane.
- **Chat path.** The driver composes the same backend as the `local` provider route (`registry.rs:1589-1604`, feature `local-applefm` at `crates/driver/Cargo.toml:24` and `crates/app/Cargo.toml:51`). A device smoke path exists (`crates/ai/examples/applefm_smoke.rs:1-14`, `crates/ai/Cargo.toml:12-14`).
- **Policy.** ADR 0023: chores go to the `tiny` role (`0023:22-24`); local inference runs under the same admission, cancellation and lifecycle (`:33-35`); "A pinned local tiny model is NEVER silently promoted to a hosted one ... fallback is an explicit caller policy" (`:36-38`). ADR 0042 extends the existing `omp-ai::local::applefm` boundary rather than adding another (`docs/adr/0042-apple-pcc-integration.md:9,22`). ADR 0049: vendor integration (acting on a vendor's account or service API) leaves core and the vendor-name prohibition reaches every core crate (`docs/adr/0049-tiered-integration-architecture.md:14-15,47,129`), but "Inference and search transports" are Class B and stay, governed by providers-as-data (`:130`). The Apple FM backend is a Class B transport.

## 3. Class

**c (port).** The capability exists upstream and is missing here: nothing in omp2 produces a fact without a model, and in the running product nothing produces facts at all (2.2). It is not a, and not b: without it, a user who is offline or sets the model off gets no extracted facts, and the owner has asked for it. Upstream's pipeline is wired into the product, so wiring is part of the port.

The port is not literal, for three reasons. (1) Upstream stores key/value rows (`subject = "version"`, `predicate = "version"`; `upstream:packages/mnemopi/src/core/beam/consolidate.ts:307-313`), but omp2 indexes `subject predicate object` as text (`store.rs:1666`), so rows must be real triples. (2) Upstream's regexes are English first-person only and store nothing for decisions or dependencies (`upstream:packages/mnemopi/src/core/beam/consolidate.ts:781-782`). (3) The owner's requirements for Spanish, structured tool results first, `valid_until` and an Apple FM lane have no upstream counterpart. These ship as later slices of the same ADR; if the owner prefers to track them as class d, slices 3 to 5 separate cleanly.

## 4. Options

### 4.1 The rule extractor

- **A. Literal port** of `heuristicExtractFacts` and the `extractAndStoreFacts` patterns. Cost: low, one module. Fit: poor. English only; key/value rows would index as "version version 1.2.3"; no decisions, dependencies or `valid_until`.
- **B. Build on omp2's seams.** A pure `rules` module in `omp-memory` returning `ExtractedFact` triples over a closed predicate vocabulary, run by the extraction drain worker in every mode and persisted through `complete_extraction` and `INSERT OR IGNORE`. Upstream's guards and test vectors come across as test cases. Cost: medium. Fit: best; one path for rules and for models, reusing `NewFact`, the id shape of `parse_facts`, the existing bounds and the retryable-job contract.
- **C. Rules as an `ExtractionLane`** emitting `FACT` lines that `parse_facts` reads back. Cost: low. Fit: poor. It formats and re-parses text on every pass, loses typed fields, and needs TAB and newline escaping.
- **D. Rules inline in the retention transaction.** Atomic with the episode, but a second path next to the worker that the wiring needs anyway, and it cannot serve the "model unavailable" fallback. Rejected for one path.
- **E. A model for Spanish and technical facts.** Rejected: against "deterministic rules first, a model only where rules cannot", against the owner's rule that rules run when no model is set, and useless offline.
- **F. A Python extension.** Rejected: the work belongs in the Rust extraction path, and an extension runs on the embedded interpreter, outside the memory transaction (ADR 0036, `docs/adr/0036-python-for-extensions.md:37`).

**Choice: B**, carrying A's guards and vectors.

### 4.2 Storing expiry

- **(i) Additive nullable column, no version bump.** Chosen (prototype).
- **(ii) Bump `SCHEMA_VERSION` to 4.** The existing path. A bump drops `memory_embeddings`, `triples`, `memory_links` and the FTS tables and zeroes the vector and graph generations (`store.rs:1220-1234,1642-1658`), so every user re-embeds, and a bank opened by the new binary can no longer be opened by an older one (`store.rs:1217-1219`).
- **(iii) A side table** of expiries: a join on every recall and a second write path.
- **(iv) Encode expiry in text** (object or timestamp): not queryable, ambiguous.

**Choice (i).** The column is nullable, no existing statement, trigger or index names it (`facts_ai` and `facts_au` use only subject, predicate and object; `store.rs:1750-1762`), and old binaries keep working: their explicit-column INSERT and SELECT are unaffected, and they simply do not filter. The rule for later changes: an additive nullable column nothing else touches is added by `add_column_if_missing` on every open; anything that changes meaning or derived indexes bumps. This departs from the bump-per-change path and is recorded as an owner question (O3).

### 4.3 How tool results reach the extractor

- **(i) A typed `ToolObservation { tool, target, output }` input** with named-field parsers, built by the retention Director from `Input` and `Result` DOM nodes. Chosen. Additive: `RetentionMessage` and its literals are untouched (`retain.rs:43-52`).
- **(ii) Sniff `Tool`-role message text.** Rejected: `RetentionMessage` carries no tool name or path (`retain.rs:43-52`), so sniffing guesses structure.
- **(iii) Leave it to the model.** Rejected: contradicts the owner's "prefer structured tool results".

Trust: `ExtractionRequest.input` is user-authored only (`extract.rs:22`) and stays so; tool output feeds rules only, never a model lane.

### 4.4 Apple FM lane

- **Placement.** (a) A module beside `aux_lane.rs` behind `apple-aux-memory`: chosen. The backend is a Class B inference transport that stays in `omp-ai` (`docs/adr/0049-tiered-integration-architecture.md:130`); the lane is an inference consumer, not a vendor client acting on an account, so the vendor-name prohibition (`:14-15`) does not reach it. `omp-ai` cannot depend on `omp-memory` (the dependency runs the other way, `crates/memory/Cargo.toml:18,22`). (b) A host-injected lane in `omp-driver`: equally allowed, but it needs a composition that S1 creates anyway; kept as the path if the owner wants the module out of `omp-memory`.
- **Call path.** (a) `AppleFm::generate` with `AppleFmOptions`: chosen. It gives a token cap, temperature, a cancellation token, the 30 s deadline and admission (`applefm.rs:428-435`). (b) `AppleFmSession::respond`: no cap or cancellation, hard-wired scoring prompt (`applefm.rs:507-537`). (c) The `local` provider route (`registry.rs:1589`): chat-event streaming for a one-shot job.
- **Compiling it.** The lane must be built where Apple FM is: `crates/driver/Cargo.toml:24` `local-applefm` gains `omp-memory/apple-aux-memory` (the app forwards it, `crates/app/Cargo.toml:51`), and CI gains a recipe for `omp-memory --features apple-aux-memory` (2.5).

### 4.5 Fallback

Explicit policy, as ADR 0023 requires (`0023:36-38`). When the lane reports the model unavailable, run the rules (never another model). When it fails transiently, retry. Detailed in S1 and S5.

### 4.6 Where the wiring lives

- **A. A driver-owned Director plus tasks, gated.** Chosen. A `MemoryRetention` Director in `omp-driver` (the "higher-level driver memory composition", `crates/envd/src/memory.rs:8-9`) registered by `compose_kernel` beside stream rules (`kernel.rs:2905-2919`), observing turns through `observe_turn` (`crates/contract/src/director.rs:686-689`), handing a settled-transcript snapshot over a bounded channel to a retention task and a worker. It follows the Director rule (`AGENTS.md:535-550`) and keeps `omp-agent` free of memory.
- **B. A flag in the agent loop**, as autolearn does (`crates/agent/src/loop.rs:1925-1935`). Rejected: the loop is a generic hook surface (`AGENTS.md:545-550`) and this would couple `omp-agent` to `omp-memory`.
- **C. A hook in the app's session runner.** Rejected: it covers the interactive owner only (`crates/app/src/session_runner.rs:65`), and headless owners would duplicate it.
- **D. A daemon-side hook behind a new wire message.** Right for project daemons, but no memory message exists in any `.proto` (2.2); deferred as O2.
- **E. A Python extension (`@omp.director`).** Rejected: it cannot reach the in-process runtime handle and would put the durable write path in an extension (ADR 0036).

Shutdown: **(i) the finalizer's Mnemopi phase, called by the top-level owners** (chosen; `finalize.rs:100-136`); **(ii) drop the task and lose unretained turns at exit** (they are retained on resume, because the cursor is durable, but unconsolidated episodes expire after 24 hours, `config.rs:266-268`); **(iii) skip**. Chosen (i): it is the only way episodes become durable.

## 5. Plan

Five PR-sized slices, ordered so the wiring lands with the first extractor and nothing ships unreachable. Three convars, all declared in `host_settings.rs` beside `SV_WORKTREE_BASE` (`:139`), read in `HostSettings::from_con` (`:204-234`) and carried to the runtime in new `#[serde(default)]` fields of `MnemopiSettings` (pattern `config.rs:196-198`), so `omp-memory` gains no `omp-con` dependency: `sv_memory_session_retention` (bool, off), `sv_memory_llm_mode` (default `smol`, today's value) and `sv_memory_fact_expiry` (bool, off). Names use the `sv_` prefix because they are omp2-native host policy with no upstream counterpart (the `ai_mnemopi_*` family carries pi aliases, `host_settings.rs:85`). All Rust verification runs remotely (`just remote-plain-test omp-memory`, a clippy run, and `just remote-plain-test omp-driver`; `AGENTS.md:90-94`).

### S1. Wire retention and the extraction drain, with the first extractor

- **Gate.** `sv_memory_session_retention` (default off). Off: no Director is registered, no task runs, no memory call is made; behaviour is byte-identical to today.
- **Convars and settings.** Add `sv_memory_session_retention` and `sv_memory_llm_mode` (offering `none` and `smol`). `from_con` sets `mnemopi.llm_mode` from the latter and a new `mnemopi.rule_facts` from the former. In `omp-memory`, `extraction_enabled = llm_mode != None || rule_facts` (`session.rs:151,227`); with `rule_facts` false it is today's predicate, so `disabled_extraction_lane_retains_without_enqueuing` (`session.rs:384`) passes unchanged.
- **Rule core.** A pure module `crates/memory/src/extract/rules/`: `extract(&RuleInput) -> Vec<ExtractedFact>`, no I/O and no clock. English identity and preference family at upstream parity, emitting triples over a closed vocabulary (`name`, `is`, `works_at`, `lives_in`, `uses`, `prefers`, `dislikes`, `instruction`; subject `user`). Guards: questions, hypotheticals ("if", "unless"), negation before the verb, fenced code, clauses near a secret word (password, token, api key, secret). Caps: at most 32 facts per source memory (upstream caps at 5 and 10, `upstream:packages/mnemopi/src/core/extraction.ts:313`, `upstream:packages/mnemopi/src/core/beam/consolidate.ts:744`), subject at most 128 B, object at most 240 B (inside the parser limits, `extract.rs:116-119`). Ids `rule_` plus 24 hex of `Hash32` over source id, rule id and triple. Confidence 0.7. Framing markers are stripped first (`strip_protocol_markers`, `retain.rs:212`). Dependency `regex.workspace = true` (refresh `Cargo.lock` with `cargo metadata --offline`).
- **Typed faults and the drain.** `LaneFault { Unavailable, Rejected, Transient }` in a new typed `Error` variant (ADR 0035; no string payload), beside `AuxiliaryCompletion` (`lib.rs:63-65`). A worker function `drain_once` in `omp-memory` reads `pending_extractions` (`store.rs:571-599`), calls the lane, then `parse_facts` and `complete_extraction`. With no lane bound (the case for every mode in S1) the lane reports `Unavailable` and the explicit `FallbackPolicy::Rules` the composition passes runs the rules and completes the job. `Transient` leaves the job queued and the pass moves on; `Rejected` runs the rules, else acknowledges the job so it cannot loop. Backoff, a per-pass job and time budget, and cancellation bound the loop. `ExtractionRequest` gains `observed_at` (the job's `created_at`, read at `store.rs:578`) for `NewFact.timestamp`. `ExtractionReport` and tracing events record the extractor and the typed reason.
- **The Director and tasks (`omp-driver`).** `crates/driver/src/headless/memory_retention.rs`: a `MemoryRetention` Director whose `observe_turn` snapshots the settled transcript from the DOM (`User`, `Assistant` and `Result` nodes, stable id from the node) only when user turns since the last retention reach `retain_every_n_turns`, and hands it to a retention task over a bounded `flume` channel with `try_send`, so it never blocks the loop. The task calls `SessionMemory::top_level(runtime).retain_settled` on a blocking thread; `retain_settled` wakes the worker (`session.rs:155`). The worker loop drains once at start, so jobs recovered from an earlier process are handled (`runtime.rs:952-971`), then on each wake-up. `compose_kernel` registers and engages the Director beside stream rules (`kernel.rs:2905-2919`) only when the gate is on, the backend is active, the session is top-level and the environment hands out an in-process runtime (`crates/envd/src/lib.rs:1338`); otherwise it logs once and registers nothing.
- **Close.** A `MemoryLifecycle` handle on `ComposedInference` exposes `finish(budget)`. The top-level owners (`crates/app/src/chat_cmd.rs:753`, `crates/app/src/chat_control.rs:3073`, `crates/app/src/chat_services/session_ops.rs:275`) call `HeadlessFinalizerHandle::finalize` with the Mnemopi slot registered (`finalize.rs:100-136`): `SessionMemory::shutdown_flush` (bounded force retention, `session.rs:171-209`) then consolidation (`MemoryRuntime::enqueue`, `runtime.rs:766-778`), inside `budget.mnemopi`. Subagents, adw, cleanse, compress and standalone tools never retain (`SessionMemory` is top-level only, `session.rs:132`).
- **Known limit.** Project-daemon sessions are inert (no memory message exists on the wire, 2.2); see O2.
- **Acceptance.** The end-to-end test `crates/driver/tests/memory_retention.rs`, built on `memory_reflect.rs` (real `ProjectEnvironment`, scripted `Inference`, real journal and session). Gate off (default): a scripted two-turn session leaves `pending_extraction_count()` at 0, no working-memory rows, retention cursor 0, and no `memory-retention` Director in the journal. Gate on, `llm_mode = none`: a settled user turn "My name is Ada. I work at Example Corp and I prefer dark mode." followed by `drain_once` yields the three triples through recall (upstream vector `upstream:packages/mnemopi/test/extraction.test.ts:93-103`) and one episode; replaying the window leaves one row per fact. Gate on, `smol` with no lane: the same facts (lane `Unavailable` runs the rules). Close with fewer turns than the interval: the Mnemopi phase retains the trailing turns and consolidates, and the episode and its facts survive a working-memory eviction pass. A subagent session and a project-daemon environment retain nothing.
- **Tests.** The end-to-end rows above; Director unit tests (snapshots only at the interval, never blocks, user-only extraction text); worker tests with a fake lane (each fault maps as above, cancellation leaves jobs queued, budgets hold, no fact from a failed lane, `Unavailable` never reaches another lane); rule-core tests with upstream's vectors (`upstream:packages/mnemopi/test/extraction.test.ts:205-227`: Berlin and TypeScript; "never use semicolons" and "always wrap lines"; the subjectless narrative that must yield nothing), each with a negative; adversarial inputs (256 KiB of "I am " repeated, 1 MiB without separators) stay within 32 facts (asserted on counts).

### S2. Expiring facts, with the first rules that set them

- **Gate.** `sv_memory_fact_expiry` (default off) for the recall filter. Recording `valid_until` from the rules is not gated: the column is inert while the filter is off.
- **Contents.** Rebase `daab333d13` (base `b8032a94ad`) onto current omp2. Keep: `ExtractedFact.valid_until`, `NewFact.valid_until`, the nullable column added by `add_column_if_missing` on every open without a version bump (D3), the nine-column INSERT, `search_facts_at` with the filter ahead of `LIMIT`, and the date-to-instant conversion (next UTC midnight, with the last-day overflow guard) as a shared helper. Add `sv_memory_fact_expiry`, `MnemopiSettings.fact_expiry` and a `BankStore` builder. Add the explicit-bound rules in English and Spanish ("until", "through", "expires", "deadline"; "hasta", "vence", "fecha límite") over absolute dates (ISO, English month names, Spanish month names such as "15 de marzo de 2027") on `jiff`, producing `deadline` and `status` facts with `valid_until`. The sixth-`FACT`-field grammar stays out of this slice: until a lane emits it, that branch would be unreachable (it lands in S5).
- **Acceptance.** End-to-end: "The deadline is 2027-03-15" and "La fecha límite es el 15 de marzo de 2027" each store `(project, deadline, 2027-03-15)` with `valid_until` `1805155200000` (2027-03-16T00:00Z, computed independently); with the gate on, recall hides the fact once the injected clock reaches that instant and read-by-id still returns it; with the gate off recall still returns it. Numeric dates (`03/04/2027`) and relative expressions ("tomorrow", "mañana", "for two weeks") are not parsed in v1: a numeric date is ambiguous, and a relative one would resolve against the window's retention time because `RetentionMessage` has no timestamp (`retain.rs:43-52`).

### S3. Structured tool observations first

- **Gate.** `sv_memory_session_retention`.
- **Contents.** `ToolObservation { tool, target, output }` and an additive `SessionMemory` entry that takes observations next to messages; the Director builds them from `Input` and `Result` DOM nodes (tool name, path or command, output). Named-field parsers over typed serde structs: `package.json` (name, version, dependencies, devDependencies, engines, packageManager), `Cargo.toml` (package name, version, rust-version; dependency keys with a version string, a table, or `workspace = true`), and version banners from `bash` observations whose command is exactly `<tool> --version`, `-V` or `version` for a closed tool set (rustc, cargo, node, npm, python, go, bun, git). Selection keys on tool and target, never on sniffing the output. Vocabulary added: `version`, `depends_on`, `dev_depends_on`, `requires_runtime`. Subject is the manifest's package name (or the tool). Confidence 0.9. Bounds: 1 MiB per observation, 64 dependencies per manifest, the 32-fact cap. Free-text fields (description, scripts, readme) and credential-like keys are never read. Text a parser consumed is excluded from the prose pass.
- **Acceptance.** End-to-end: a scripted `read` of a `package.json` fixture inside a settled turn stores `depends_on` facts through recall. Golden facts per parser. A manifest yields no prose facts. Malformed JSON or TOML yields zero facts and does not fail retention. A fixture containing `"token"` and `"password"` fields produces no fact containing either value. An observation with an unknown tool or target is ignored by the structured pass and not parsed as prose.

### S4. Technical and decision rules in English and Spanish

- **Gate.** `sv_memory_session_retention`.
- **Contents.** Families, each in both languages and each with negatives: versions (upstream's `isVersionMention` guard ported, plus Spanish cue words "versión", "actualizamos", "subimos", "migramos"); dependencies ("depends on", "requires", "installed"; "depende de", "requiere", "instalamos"); decisions ("decided", "chose X over Y", "going with"; "decidimos", "elegimos X en lugar de Y", "optamos por", "nos quedamos con") producing `decided` and `rejected`; supersession ("no longer use", "dropped"; "ya no usamos", "dejamos de usar", "migramos de X a Y") producing `stopped_using` and `uses`. Spanish identity and preference mirror the English family ("me llamo", "trabajo en", "vivo en", "uso", "me gusta", "prefiero", "odio"). Matching is accent-insensitive by listing both forms; neutral Spanish, no voseo. Confidence 0.7 prose, 0.6 decisions.
- **Acceptance.** End-to-end rows, paired English and Spanish: "My name is Ada" and "Me llamo Ada" give `(user, name, Ada)`; "We upgraded tokio to 1.40.0" and "Actualizamos tokio a la versión 1.40.0" give `(tokio, version, 1.40.0)`; "omp-memory depends on jiff" and "omp-memory depende de jiff" give `(omp-memory, depends_on, jiff)`; "We decided on SQLite instead of Postgres" and "Decidimos usar SQLite en lugar de Postgres" give `(project, decided, SQLite)` and `(project, rejected, Postgres)`. Negatives: questions ("Do we use tokio 1.40?", "¿Usamos tokio 1.40?"), negation ("I don't use Postgres"), hypotheticals, a password sentence, and an IP address (`10.0.0.1`). Upstream version regressions are ported (`upstream:packages/mnemopi/test/beam-consolidate-unit.test.ts:424,442,459,476,490`).

### S5. Apple FM lane for `local-memory-model`

- **Gate.** `sv_memory_llm_mode` gains `local-memory-model` (its validate hook rejects it in a build without `apple-aux-memory`); no further convar, because selecting the mode is the opt-in. Default stays `smol`.
- **Contents.** A module `crates/memory/src/aux_extract.rs` behind `apple-aux-memory`, an `ExtractionLane` over `AppleFm::generate`, bound by the driver composition when the mode is selected. One availability probe per pass (`availability_evidence`, `applefm.rs:406-424`). One bounded request per chunk: input split on paragraph then sentence boundaries into chunks of at most 4 KiB, at most 8 chunks per job, each request `AppleFmOptions::new(chunk).system_prompt(PROTOCOL).temperature(0.0).max_tokens(512)` under the 30 s deadline with a cancellation token tied to worker shutdown. The system prompt is new, fixed and golden-tested (2.1): the `FACT` line protocol with the closed vocabulary from S1 to S4, "only what the user explicitly states" and "output only the latest value" carried over from `memory-pipeline.md` (`:3-5`), and the optional sixth field only when `sv_memory_fact_expiry` is on. The sixth-field grammar and its tests from the prototype land here (five or six fields, RFC 3339 or `YYYY-MM-DD`, no-expiry spellings, malformed rejects). The lane keeps only lines starting with `FACT` plus TAB, so `parse_facts` stays the single parser. Fault mapping: unavailable (`UnsupportedOperatingSystem`, `UnsupportedArchitecture`, `FrameworkUnavailable`, `DeviceNotEligible`, `SettingsDisabled`, `ModelNotReady`, and `ModelUnavailable` at request time) maps to `Unavailable`, so the rules run; `ContextOverflow` splits the chunk in half and retries once, then skips it; `GuardrailBlocked`, `UnsupportedLocale`, `DecodingFailure` skip the chunk (counted in the report); `TimedOut`, `RateLimited`, `ConcurrentRequests`, `Runtime`, `Cancelled` map to `Transient` for the whole job. A busy permit never blocks: the job stays queued behind the user's chat. A job that skipped chunks keeps the other chunks' facts.
- **Build and CI.** `crates/driver/Cargo.toml:24` `local-applefm` gains `omp-memory/apple-aux-memory` (the app forwards it, `crates/app/Cargo.toml:51`), so the shipped Apple build compiles the lane. A new recipe `test-memory-apple` runs `cargo nextest run -p omp-memory --features apple-aux-memory --locked` and the matching clippy, and `remote-heavy` and `test` call it (`justfile:154-157,282-284`), because today no build compiles the feature (2.5). The non-macOS stub (`applefm.rs:63-95`) lets it compile and run on Linux.
- **Chunk budget.** The window is 4096 tokens for instructions, prompt and answer (`applefm.rs:99`); there is no tokenizer and the backend estimates `ceil(bytes / 4)` (`platform.rs:823-833`). Reserving about 1 KiB for instructions, 512 tokens of answer and a quarter of the window as margin leaves roughly 2300 tokens. A 4 KiB chunk plus the prompt stays under the window even at 1.5 bytes per token (about 3.9k of 4.1k tokens). The figure is conservative and `[INFERENCE]` until measured on a device with `applefm_smoke`.
- **Acceptance.** With a fake generator: every row of the fault table maps as above; every chunk is at most 4 KiB, on a character boundary, at most 8 per job, and the chunks reassemble to the input apart from trimmed whitespace; the prompt matches its golden; a busy permit never blocks and the job stays queued; non-`FACT` lines are dropped; a six-field line stores `valid_until` end to end. End-to-end on Linux: `llm_mode = local-memory-model` with the Apple stub reports `Unavailable` and the rules store the English and Spanish facts (the fallback, exercised). The new recipe passes in the required Linux check. A macOS-only `#[ignore]` smoke test, modelled on `applefm_smoke`, runs a real extraction on a device.

## 6. Open questions

- **O1. Meaning of "no memory model is set".** I read it as: `llm_mode = none`, or the configured lane reports `Unavailable` and the composition passes `FallbackPolicy::Rules`. That matches upstream (`upstream:packages/coding-agent/src/mnemopi/backend.ts:539,558-563`) and the Apple FM requirement, and it is what makes the rules reachable under the default `smol`, for which no lane exists. The narrow reading (`none` only) would leave them unreachable by default. A model that is available and fails transiently is retried, not replaced (`store.rs:712-715`, ADR 0023 rule 4). Needs confirmation.
- **O2. Project-daemon sessions.** No wire message carries memory (2.2), so S1 leaves a session attached to a project daemon inert. Recommendation: a follow-up ADR adds a memory lifecycle message; rules need no inference, so a daemon-side worker would work once turns reach it.
- **O3. No `SCHEMA_VERSION` bump.** The prototype adds the column without bumping, a departure from the bump-per-change path (`store.rs:1220-1223`). Reasons in 4.2. Alternative: bump to 4 and accept the index reset and the older-binary lock-out.
- **O4. Date-only bounds are UTC.** "Valid through that day" means until the next UTC midnight. Local time is the alternative.
- **O5. Relative and numeric dates are out of v1.** Revisit when `RetentionMessage` carries message timestamps.
- **O6. Supersession.** Facts are immutable (`store.rs:706`, `crates/envd/src/tool_url/memory.rs:195-197`), so a newer fact cannot expire an older one. The rules emit `stopped_using` and `uses` facts instead. No mutation path is proposed.
- **O7. Tool observations.** Tool text feeds rules through named-field parsers only, never a model lane. Provenance is carried by the `rule_` id prefix; a `facts.extractor` column is the alternative.
- **O8. Gate granularity.** Three convars; alternative is one enum. Recommendation: three, each independently reversible.
- **O9. Apple FM device evidence.** Guardrail mode (`permissive` stays off), the chunk size and token budget, and rule coverage for chunks the model skips (which would need a richer lane return type). Measure with `applefm_smoke` before changing a default.
- **O10. Languages.** Spanish only. Upstream's detector also knows Russian and German (`upstream:packages/mnemopi/src/core/beam/consolidate.ts:555-612`); each language needs reviewed vectors.
- **O11. Constants.** The 32-fact cap and the confidence bands (0.9 structured, 0.7 prose, 0.6 decisions and bounds) are starting values anchored on upstream's 0.5 to 0.7 (`upstream:packages/mnemopi/src/core/beam/consolidate.ts:622,740,750,768`).
- **Constraint check.** Additive only: every gate is default-off or default-unchanged, and no existing tool, skill, convar, hook, URL scheme or CLI command changes; the one departure from an existing path is O3. Vendor rule: ADR 0049 keeps inference transports in core (Class B, `docs/adr/0049-tiered-integration-architecture.md:130`), and no vendor client is added; the lane sits behind the existing `apple-aux-memory` feature. ADR 0024: no tool or roster family added. ADR 0036: Rust only, no extension. ADR 0035: typed errors, no string payloads (`docs/adr/0035-rust-for-the-engine.md:54-55,75`). ADR 0006: the rules execute nothing and read no files. ADR 0023: fallback is an explicit policy and never reaches a hosted model. No `pi` identity: crates, convars and ids are `omp-*`, `sv_*` and `rule_`.

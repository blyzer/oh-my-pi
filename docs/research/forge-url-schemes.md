## Review (EGM, 2026-11-13)

A fresh-context reviewer (zoom-out and design critic) settled the open items:

1. **Class.** Accepted: class a for the goal (ADR 0049 D2.5 already routes `pr://` and `issue://` through `ForgeResolver<Delegated<ForgeBackend>>`, `crates/envd/src/tool_url.rs:637-649`), class b for the literal move (ADR 0049 `docs/adr/0049-tiered-integration-architecture.md:168` and ADR 0050 `docs/adr/0050-extension-declared-url-schemes.md:48,136` reject new built-in forge schemes).
2. **Legacy GitHub REST branch.** Delete it, in two steps. Static tracing shows it is unreachable: `peel_selector` (`crates/forge/src/scheme.rs:249-266`) consumes the `/diff` forms and `Target::parse` rejects other trailing segments, so `numbered_ref` never yields the `MissingNumber` case that reaches `fetch` (`crates/envd/src/forge_url.rs:431`). List reads already go through `forge.search` (`forge_url.rs:520-525`). Step 1 replaces `fetch` and `fetch_comments` with an invalid-input fault and runs the forge tests on BuildBuddy with `cap-forge`. Step 2 deletes the branch, `Target::api_url`, `ForgeRepo::api_url`, `api_url_for_host`, the bridge's GitHub spec and the **five** `api_url` assertions (`forge_url.rs:1646, 1651, 1654, 1678, 1685`), keeping the identity assertions and `numeric_tail_disambiguates_host_from_diff_suffix`. Fix the module doc (`forge_url.rs:1-16`) and `TASKS.md:166`, which still describe the REST client as live. This removes dead code only; no reachable behaviour changes.
3. **ADR 0049 D2.7 residue.** Schedule as a gated follow-up, not part of this gap: `GITHUB_COM_TOKEN_VARS`, `DEFAULT_FORGE_HOST`, `FetchHost::github` (`crates/envd/src/fetch_host.rs:67,122`, live egress routing with a protobuf variant at `:294,313`, so any rename needs a wire-compatibility plan), and `crates/app/src/update_cmd.rs:487-490` (GitHub tokens for release metadata, which needs its own class decision).
4. **`?at=` snapshot pin and `mr://`.** Not adopted. `mr://` is rejected by ADR 0049 and ADR 0050; `?at=` needs a cache-generation design with no current user need.
5. **`INTERNAL_PREFIXES` gap.** A real but latent defect in the `omp-edit` library only. `crates/edit/src/path_policy.rs:19` lists ten prefixes and omits `pr`, `issue`, `history`, `memory`, `omp`, `job`, `attachment`, `conflict`, `http` and `https`, so `resolve()` (`:69`) joins `pr://1` onto the working directory. The shipped tools are not affected: `write` rejects it at `crates/tools/src/write.rs:848` via `reject_uri_like_target` (`:1257`), and the envd edit path rejects non-file schemes (`crates/envd/src/tool_document.rs:881`). `omp_edit::Session` has no production constructor. Fix: replace the fixed list with a rule that treats any valid `scheme://` other than `local:`, `file:` or a Windows drive as internal, with one test per previously missing scheme in `crates/edit`. The behaviour change is confined to the library (`resolve()` errors instead of joining the working directory).

Follow-up slices: S17.2 (unreachability test) and S17.3 (two-step deletion) are approved; the `INTERNAL_PREFIXES` fix is its own small slice; the D2.7 residue waits for its own ADR 0049 follow-up.

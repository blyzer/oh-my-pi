## 2. What Saetta actually implements

**Source-verified, runtime-unverified in this environment.** The inspected Saetta is a substantial native coding harness and model-specific inference engine, not merely a small loop around an HTTP client.

**Reliability boundaries:** `run_agent` uses bounded exponential retry and abortable sleep, while `run_turns` distinguishes error/abort from ordinary tool completion. Source inspection proves these branches exist, not cancellation latency or recovery reliability under load. Saetta's global-abort/threading design is not a security sandbox or a drop-in replacement for OMP2's cancellation tree, process authority or durable journal.

## 3. Native inference: real implementation, restricted portability

### Model execution and data movement

[`model.h:1–17`](https://github.com/antonellof/saetta/blob/c6ce9f9f533bcf18709e380bf32b2e34d424a52c/src/model.h#L1-L17) describes token execution in serial Metal command buffers and model-specific host work. The concrete API dispatches by the pack's `model_type`, not by an arbitrary graph compiler: [`model_api.c:36–59`](https://github.com/antonellof/saetta/blob/c6ce9f9f533bcf18709e380bf32b2e34d424a52c/src/model_api.c#L36-L59) chooses compiled architectures, refuses unknown types, and routes to model-specific implementations. This pin includes Qwen3.8 Flash-Next/27B, DeepSeek-V4-Flash and Inkling 2 paths; this statement does not establish every quantization/kernel/model variant as correct or benchmarked.

Weights are mapped read-only/private by [`metal/shim.m:23–42`](https://github.com/antonellof/saetta/blob/c6ce9f9f533bcf18709e380bf32b2e34d424a52c/src/metal/shim.m#L23-L42). [`gpu.c:72–93`](https://github.com/antonellof/saetta/blob/c6ce9f9f533bcf18709e380bf32b2e34d424a52c/src/gpu.c#L72-L93) checks pack fit, creates a Metal device and either wraps weights or selected segments. [`metal/shim.m:108–136`](https://github.com/antonellof/saetta/blob/c6ce9f9f533bcf18709e380bf32b2e34d424a52c/src/metal/shim.m#L108-L136) exposes recommended working set/current allocation, wraps mapped bytes with `newBufferWithBytesNoCopy`, and zero-initializes newly allocated shared buffers.

This avoids a duplicate copy for the wrapped weight path. It does **not** make the entire pipeline zero-copy: scratch allocations, model-specific conversions and streamed expert staging remain. [`xcache.c:23–64,82–94`](https://github.com/antonellof/saetta/blob/c6ce9f9f533bcf18709e380bf32b2e34d424a52c/src/xcache.c#L23-L94) has bounded expert slots/LRU metadata, loader threads and staging buffers, then copies staged reads into GPU slots. Those bytes, file cache, CPU/GPU shared allocations and thread stacks compete for the same physical unified memory.

### KV, speculation, LoRA and conversation reuse

[`model.h:78–140`](https://github.com/antonellof/saetta/blob/c6ce9f9f533bcf18709e380bf32b2e34d424a52c/src/model.h#L78-L140) separates per-conversation KV/checkpoint data from shared session scratch, supports f16/f32 KV and speculative rollback slots. [`spec.c:17–37,68–98`](https://github.com/antonellof/saetta/blob/c6ce9f9f533bcf18709e380bf32b2e34d424a52c/src/spec.c#L17-L98) implements prompt-lookup draft candidates and explicitly frees their buffers. The public header declares prefill, verification chunks, greedy/sample verification and MTP interfaces; [`model_api.c:115–120`](https://github.com/antonellof/saetta/blob/c6ce9f9f533bcf18709e380bf32b2e34d424a52c/src/model_api.c#L115-L120) dispatches LoRA load/selection. These have concrete source implementations and model-specific Metal kernels; no numerical/performance result was executed here.

[`session_reusable_in`, `model_api.c:197–219`](https://github.com/antonellof/saetta/blob/c6ce9f9f533bcf18709e380bf32b2e34d424a52c/src/model_api.c#L197-L219) selects an exact token-prefix checkpoint and longest common prefix point. [`server.c:140–194`](https://github.com/antonellof/saetta/blob/c6ce9f9f533bcf18709e380bf32b2e34d424a52c/src/server.c#L140-L194) considers adapter identity, reuse, memory room, empty/new slots and LRU replacement. Changing LoRA invalidates affected state. This is local execution-state reuse. Stable prompt ordering helps remote providers, but OMP2 cannot import these local KV buffers into Claude/Bedrock or assume remote continuation accepts only a suffix.

### 16 GB M1 Pro assessment

Normal Saetta model admission explicitly reserves **12 GiB** for macOS, other programs, GPU scratch and minimal context (`FIT_RESERVE_GB`, [`fit.h:1–35`](https://github.com/antonellof/saetta/blob/c6ce9f9f533bcf18709e380bf32b2e34d424a52c/src/fit.h#L1-L35)). [`fit.c:54–78`](https://github.com/antonellof/saetta/blob/c6ce9f9f533bcf18709e380bf32b2e34d424a52c/src/fit.c#L54-L78) refuses insufficient physical memory and returns no default model below 32 GiB. The built-in downloadable normal packs start at 32 GB; Inkling Mini is also marked 32 GB in [`download.c:46–81`](https://github.com/antonellof/saetta/blob/c6ce9f9f533bcf18709e380bf32b2e34d424a52c/src/download.c#L46-L81).

**Decision:** do not adopt these normal packs on the 16 GB target and do not set `SAETTA_IGNORE_MEMORY` to manufacture a successful demo. Streamed expert modes deliberately follow separate admission paths (`model_api.c:53–59`); that exception is not measured evidence that a large streamed pack is practical alongside OMPv1, OMP2, IDE, browsers and compilation on this machine. SSD-backed expert reads also introduce bandwidth/latency/thermal and swap contention. A 1 TB SSD is capacity, not a guarantee of acceptable paging latency.

The transferable idea is workload-specific admission with an explicit coexistence reserve, not copying the 12 GiB constant. Derive OMP2's thresholds from physical footprint, active child accounting, pressure/compression/swap observations and measured reconstruction cost. Keep remote inference first-class; only small optional embeddings/rerank/classifier workloads should enter local feasibility trials, after existing providers have been evaluated.

## 4. Frink and other optional backend choices

Frink is a different architectural reference, not a requirement. Its [`frink-inference/src/lib.rs:1–55`](https://github.com/antonellof/frink/blob/55f122a85132d7d22f9e4f0e6496968a50b4f353/crates/frink-inference/src/lib.rs#L1-L55) is a Rust facade, and [`Cargo.toml:21–38`](https://github.com/antonellof/frink/blob/55f122a85132d7d22f9e4f0e6496968a50b4f353/crates/frink-inference/Cargo.toml#L21-L38) has no default GPU feature. CPU/native Rust reuse can therefore use the same-toolchain compilation model; independently compiled Rust trait objects are not an implied ABI.

[`frink-gguf/src/lib.rs:424–435`](https://github.com/antonellof/frink/blob/55f122a85132d7d22f9e4f0e6496968a50b4f353/crates/frink-gguf/src/lib.rs#L424-L435) maps files into reference-counted ownership. The actual loader documents and implements mapped quantized weights with owned F32 materialization where appropriate ([`loader.rs:1–23`](https://github.com/antonellof/frink/blob/55f122a85132d7d22f9e4f0e6496968a50b4f353/crates/frink-models/src/loader.rs#L1-L23)). Its capability errors refuse unimplemented/unaudited architectures and unread required tensors rather than silently approximate them ([`loader.rs:63–105`](https://github.com/antonellof/frink/blob/55f122a85132d7d22f9e4f0e6496968a50b4f353/crates/frink-models/src/loader.rs#L63-L105)). Those are useful validation principles; this audit does not certify the entire engine or turn its advertised backend matrix into measurements.

Frink's local KV identity includes model, parent/history, tokens and extra adapter/media keys with length-delimited fields and a versioned hash domain ([`kv_block.rs:12–48`](https://github.com/antonellof/frink/blob/55f122a85132d7d22f9e4f0e6496968a50b4f353/crates/frink-core/src/kv_block.rs#L12-L48)). Its implementation has a bounded disk tier configuration, async reads and explicit store budgets (`kv_disk.rs:553–583,1208–1383`). The comments in `kv_block.rs:33–35` still call the consumer future work, illustrating why source callers must outrank stale comments. Its caller salt uses a 64-bit `DefaultHasher` namespace ([`cache_salt.rs:18–45`](https://github.com/antonellof/frink/blob/55f122a85132d7d22f9e4f0e6496968a50b4f353/crates/frink-server/src/cache_salt.rs#L18-L45)); do not import that hash as OMP2's security identity or replace journal CAS.

## 5. OMP2 equivalents already present

Do not propose Saetta mechanisms as missing without acknowledging these implemented seams:

- [`crates/ai/Cargo.toml:16–35`](https://github.com/blyzer/oh-my-pi/blob/fda1315052b8b4074f9ea5acc842b2cc0b08b2b2/crates/ai/Cargo.toml#L16-L35) defaults local inference features off and separately gates Apple, embeddings, speech recognition and synthesis.
- [`crates/ai/src/local/mod.rs:1–40`](https://github.com/blyzer/oh-my-pi/blob/fda1315052b8b4074f9ea5acc842b2cc0b08b2b2/crates/ai/src/local/mod.rs#L1-L40) exposes verified artifacts, device preferences, `AdmissionControl`, `MemoryPool`, `RuntimeLease` and `LocalRuntime`.
- [`LocalRuntime::acquire`, `runtime.rs:285–311`](https://github.com/blyzer/oh-my-pi/blob/fda1315052b8b4074f9ea5acc842b2cc0b08b2b2/crates/ai/src/local/runtime.rs#L285-L311) checks cancellation, admits work, locks the shared state, reserves memory before load, records failed load, and issues a lease. [`unload_if_idle`, 335–353](https://github.com/blyzer/oh-my-pi/blob/fda1315052b8b4074f9ea5acc842b2cc0b08b2b2/crates/ai/src/local/runtime.rs#L335-L353) rechecks active admission while holding the state lock before dropping the engine. This is already the right reusable lifecycle boundary; it is not evidence every backend returns all physical pages instantly.
- [`crates/ai/tests/local_runtime.rs:23,50,78`](https://github.com/blyzer/oh-my-pi/blob/fda1315052b8b4074f9ea5acc842b2cc0b08b2b2/crates/ai/tests/local_runtime.rs#L23-L110) contains cancellation-before-load, reservation release, admission/receipt and idle-unload tests. Their existence is source verification; this chapter did not run them.
- [`crates/memory/src/embedding/supervisor.rs:58–86,200–240`](https://github.com/blyzer/oh-my-pi/blob/fda1315052b8b4074f9ea5acc842b2cc0b08b2b2/crates/memory/src/embedding/supervisor.rs#L58-L86) constructs an unloaded supervisor and spawns a child on demand. A second embedding process/model registry is unnecessary.
- [`omp-core::Str`, `crates/core/src/str.rs:1–5`](https://github.com/blyzer/oh-my-pi/blob/fda1315052b8b4074f9ea5acc842b2cc0b08b2b2/crates/core/src/str.rs#L1-L5) already uses inline short strings and O(1) refcounted long-string cloning; blanket replacement with arenas would trade away existing cheap sharing.
- OMP2's renderer already retains a previous frame, offers damage-limited presentation, reports changed-cell/run metrics and bounds pending output (`crates/tui/src/renderer.rs:47–81,323–359,571–633`). Saetta's row comparison is therefore a **comparison workload**, not justification to replace OMP2's retained renderer.

ADR 0036 remains unchanged: “Every extension host and every eval session is a killable child process” and “The engine process NEVER executes extension Python on its own thread” (`docs/adr/0036-python-for-extensions.md`, Decision item 5). Trusted first-party Rust inference can be statically compiled into its existing native contract without introducing a third-party extension ABI. Any optional library becomes part of the host trust boundary; an independently killable worker may instead be selected for crash/resource reclamation, with existing authority/protocols. Neither choice permits arbitrary Rust symbol loading, a second external extension language or replacing embedded CPython.

## 7. Independent testing, performance evidence and executable experiments

Saetta's [`verify.c:173–181`](https://github.com/antonellof/saetta/blob/c6ce9f9f533bcf18709e380bf32b2e34d424a52c/src/verify.c#L173-L181) distinguishes a forced-layer numerical test from functional free-running behavior, measuring logits/layer error, KL divergence and greedy argmax agreement outside defined near ties. Those answer different questions: local kernel error isolation versus accumulated model behavior. `src/test/{model,spec,weights,fit,gpu_fit,code_prompt,code_oai,code_tools,verify}.c` supplies targeted test implementations. The Makefile's verification targets can skip absent model/golden datasets (`Makefile:57–85`), so a target exit status must be accompanied by executed/skipped dataset counts.

OMP2 should adapt fixture provenance, separate numerical/functional gates and explicit executed-count reporting against **OMP2's own** contracts. Golden traces must pin source, model/tokenizer/adapter, precision, sampling seed/settings and schema. Normalize only permitted nondeterministic fields. Record tool/event order, cancellation boundaries and durable source identity; never normalize away missing approval, skipped checks or changed tool results. Remote provider recordings are suitable for deterministic harness tests; they cannot certify an unobserved provider implementation or local tensor kernel.

## 8. Resulting recommendation

Use Saetta primarily as an **architectural and testing reference**. Reuse stable-prefix experiments, explicit allocation lifetimes, model-aware admission and numerical/behavioral verification methodology. Retain OMP2's existing typed native architecture, remote providers, retained TUI, cancellation and killable CPython extensions. Preserve upstream-derived ADR rationale while rejecting Pi compatibility as a target.

Do not port Saetta wholesale, transplant its JSON ownership boundaries, bypass its memory safeguards, adopt its normal model catalog on this machine, promise a stable library ABI from internal headers, or add Frink/MLX/llama.cpp solely because they exist. The smallest high-value next slice is instrumenting an existing context/lifecycle seam and evaluating a bounded candidate against an immutable OMP2 baseline.

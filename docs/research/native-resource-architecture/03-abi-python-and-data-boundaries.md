No production change, ABI experiment or native runtime benchmark was executed for this chapter. ## 2. Verified native and external execution architecture

OMP2 already addresses the native Rust ABI issue by compiling workspace components together with its pinned toolchain and communicating through typed Rust APIs. The manifest's normal Rust crate dependencies do not constitute an independently loadable Rust binary ABI. `dyn Trait` within that build is a dispatch mechanism, not a cross-compiler contract. `rlib` is a Rust compilation artifact, `staticlib`/`cdylib` can expose selected foreign ABI entry points, and `dylib` does not stabilize arbitrary `Vec`, trait-object, async-future or Rust-layout types. `repr(C)` specifies layout constraints for a type; `extern "C"` selects a calling convention; neither proves ownership safety, version compatibility or isolation.

### Actual ADR implementation tension, not a proposed replacement

`EvalChild::spawn` has an explicit alternate interpreter branch: the default selector is `embedded:cpython-3.14t` (`eval/process.rs:74`); `:592-610` can execute a configured external Python after a >=3.10 version check and stage `external_runner.py`. This is **implemented** and is a genuine tension with ADR 0036's “NEVER depends on a host-installed interpreter”/one embedded runtime wording. The embedded default does not erase the alternate branch, and the branch does not authorize changing the ADR. Trace configuration reachability and intended exception with the owner in a follow-up; preserve current behavior during research. Do not remove this functionality simply because it resembles another harness.

There is also a recoverability detail in `omp_py::Builder::init`: `INITIALIZED.swap(true)` precedes `CString` validation (`crates/py/src/lib.rs:179-204`). A NUL path returns `InvalidPath` after setting the one-shot flag. Source therefore predicts a retry in that same process returns `AlreadyInitialized` even though CPython has not booted. This is a bounded fault-injection candidate, not evidence of measured production startup failures.

### A directly actionable large-data inefficiency

`BlobStoreAuthority::read_range` in `crates/envd/src/tool_url/artifact.rs:143-161` calls `BlobStore::get`, which `fs::read`s the **entire** blob, and then returns `bytes.slice(start..end)`. `Bytes::slice` avoids copying the selected range but keeps the complete backing allocation alive. Thus a small selected read can both read and retain a much larger blob. This observation follows the implementation; production frequency/peak footprint are **unmeasured**. Existing `BlobStore::open_range` can supply a bounded read without a new format, store, IPC or mmap dependency. Range validation must retain exact endpoint/error behavior rather than silently adopt `open_range`'s clamping semantics.

### crABI status and foundational ABI distinctions

`#[repr(transparent)]` gives a wrapper the layout/ABI of its single nontrivial
field under Rust's documented constraints; it does not stabilize the wrapped
field's unspecified layout. Neither it nor `#[repr(C)]` makes allocator ownership,
trait objects, generics or callback lifetimes portable by itself. Foreign entry
points must define their panic/error policy; do not unwind Rust panics across an
ordinary C boundary or change the whole host to abort merely to shrink a build.
See the primary [Rust type-layout reference](https://doc.rust-lang.org/reference/type-layout.html)
and [external-block ABI reference](https://doc.rust-lang.org/reference/items/external-blocks.html).

The exact linked [compiler-team issue #631](https://github.com/rust-lang/compiler-team/issues/631) is titled “Experimental feature gate for `extern \"crabi\"` ABI” and was **closed**, last updated 2026-04-14. Its body explicitly says a full RFC and ABI specification are needed before stabilization. The [RFC #3470](https://github.com/rust-lang/rfcs/pull/3470) was **open/unmerged** when inspected, head `337e891e5cc1544492bb7f91d104f6fb8ab701ac`, last updated 2026-10-02. Compiler-team repository pin `6cf981d16c1852074b397eee544adc3d1a7eb6b6`; RFC repository current main pin `f43d5789b838fb0d80962e3d4b45fb9ddfcc9a07`. An issue closing is not language-feature stabilization. Neither reference establishes a production supported cross-toolchain ABI for OMP2.

| Guarantee | What OMP2 needs | What does not establish it |
| --- | --- | --- |
| Source/API compatibility | Rust/Python source and declared typed interface revisions obey contracts. | Same symbol names or matching JSON field names alone. |
| Binary ABI/layout compatibility | Only at actual FFI edges: exact target, representation, calling convention, ownership/free functions and panic/unwind policy. | `repr(C)` on one wrapper around unspecified Rust internals; a library file extension. |
| Compiler compatibility | Same pinned compatible Rust build for native internal components; supported selected CPython/native wheel build. | A proposed RFC or a crate's marketing “stable ABI” label. |
| Protocol compatibility | Negotiated/versioned messages, bounds, schema evolution, authorization and framing. | A shared native struct's machine layout. |
| Security | Existing trust/capability/sandbox/kill boundaries. | Stable ABI, runtime layout validation, or a subprocess without OS policy. |

A minimal trusted C ABI can be appropriate for a separately versioned, already existing inference library: opaque context handles, explicit API version, borrowed read-only slices valid for the call, producer-owned destructor/free functions, status codes, documented thread safety, callback cancellation and no unwinding across foreign frames. First compare static C linkage or an existing native worker. Do **not** create that interface just to move a native Rust crate out of the executable. Symbol-loading validation cannot make a malicious function pointer safe.

## 5. Python Stable ABI is not the current embedding contract

Research sources: `PyO3/pyo3@aa2eb17b75f0fa7a865233635a98d725eca41777` (current main version 0.30.0, MIT/Apache-2.0 texts) and `python/cpython@b8d2f65fb1a540dd415747df7b16c39aded25305` (PSF/history license in actual root LICENSE; includes inherited components). These are separate from OMP2's selected PyO3 0.29.2 and CPython 3.14t build.

`PyO3/guide/src/building-and-distribution.md:253-279` and CPython `Doc/c-api/stable.rst:60-90` distinguish ordinary **abi3**, for non-free-threaded builds, from **abi3t**, introduced for Python 3.15/free-threaded builds. This research must not claim free-threaded stable ABI never exists, nor backport the newer contract to OMP2's 3.14 build. Limited API/Stable ABI describe allowed API/ABI surfaces; neither makes arbitrary full-API `PyConfig`, `_frozen` structures, native wheels or embedding configuration interchangeable. OMP2 deliberately uses the selected full embedding API, its own build manifest and configured static runtime. Changing interpreter version/API restrictions requires explicit compatibility/build tests; no evidence here justifies that migration for footprint alone.

Thread attachment remains required under free-threading: `Python::attach` proves attachment, not “the GIL serializes every operation”; reference counting, Python object allocation, callbacks and exceptions still have costs. Do not turn off free-threaded-safety checks or share borrowed Python references across incompatible thread/lifetime boundaries. Subinterpreters do not supply equivalent independent process address-space or hard-kill guarantees. Interpreter reuse is already present **inside** approved child-process boundaries; retaining arbitrary namespace state and evicting it are different semantic choices.

## 6. Control/data plane and alternative formats

Current APIs already contain most of the proposed control/data-plane split: hash-referenced blobs, scoped blob authority, range/resumable network streaming, native worker OOB buffers and spill. A new `rkyv`, FlatBuffers, Cap'n Proto, Arrow or shared-memory store is therefore **not P0**. External format implementations/maturity are compared in the technology chapter; their placement decisions here are workload-specific:

| Candidate workload | Smallest first experiment | Conditional alternative only if the baseline loses materially | Required invariants |
| --- | --- | --- | --- |
| Tiny control/registration/cancellation | Keep Prost/current framed JSON and borrowed/native APIs; measure encode/decode/allocation. | Existing buffer reuse or more selective fields. | Current version negotiation, bounds, capability identity, cancellation and errors unchanged. |
| Large artifact range | Existing `BlobStore::open_range` behind existing `BlobAuthority`. | Read-only mmap only when repeat/random access warrants page/lease cost. | Source/hash provenance, exact range errors, authorization, file/GC lifetime and full-vs-range integrity semantics. |
| Rust-only derived symbol/index snapshot | Current graph/Postcard plus selective partition load. | `rkyv` prototype with checked archives if immutable random access materially lowers materialization/heap cost. | Schema/toolchain/format version, alignment/endian validation, corruption rebuild, relative references, no unvalidated archived-pointer dereference. |
| Cross-language immutable dataset | Existing blob references and selective queries/chunks. | FlatBuffers if cross-language field access demonstrates real value; Cap'n Proto if its representation/validated access wins, not to replace the existing RPC stack. | End-to-end encode/validate/transport/materialize cost, schema evolution, cancellation and ownership measured. |
| Embedding batches genuinely columnar | Existing typed vectors/bounded batches. | Arrow only for columnar/vectorized operations that use its layout. | Offset/buffer validity, alignment, null semantics, schema and footprint; no row graph forced into columns. |
| Shared memory | Reuse existing immutable file/blob refs and OS page cache first. | Explicit read-only shared mappings only if full-path benchmark defeats simpler streaming/querying. | Validation before use, immutable ownership, process/GC leases, crash recovery, retained-access/revocation limits and TOCTOU defenses. |

Even a validated zero-copy accessor may still require initial encoding, framing, socket copies, page faults, cache misses and output materialization. A mapping cannot be revoked merely by deleting its filename. Dynamic library unloading cannot reclaim live allocator arenas, worker threads, TLS, callbacks or still-held objects by assumption. Measure physical footprint and process-tree memory, not just encoded size/RSS.

## 8. Findings that should not become implementation commitments

- No source evidence requires a stable **external Rust ABI** for compiled-together native components. Keep crates/modules/direct calls/traits; lazy runtime state is a separate concern from executable linkage.
- Do not adopt `abi_stable`, Stabby or xabi merely because Rust ABI is unstable. Especially do not equate `abi_stable` RootModule loading with unloadable memory.
- Do not replace CPython/PyO3; it is already the chosen combination. `abi3t` research is not authorization to change the 3.14 embedding contract.
- Do not bulk migrate Protobuf/JSON/Postcard or add one archive format per conceptual IR. Existing range/spill/query work comes first.
- Do not use shared memory to bypass authority/validation, or use subinterpreters to weaken hard process cancellation.
- Do not call every `clone()` a deep clone: `ProcessEvalExec`/`Arc` handles and `Bytes` slices share ownership, while the backing allocation's retained size may still matter.
- Before local benchmarking on a 16 GB M1 Pro, reserve memory for other tools/processes and explicitly cap fixtures/concurrency. Never allocate the protocol's maximum as a “stress test” on that development machine.

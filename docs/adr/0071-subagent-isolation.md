# 0071. Copy-on-write tree cloning serves `/wt` worktrees from a private `omp-vcs` module; subagent isolation keeps its per-file view; ovnfs is not adopted

Status: Proposed 2026-11-14; EGM round 1 resolved, rounds 2-3 pending
Date: 2026-11-13 (revised 2026-11-14 after EGM round 1)
Area: runtime

Research: [docs/research/subagent-isolation.md](../research/subagent-isolation.md) (Gap 1 of the upstream gap closure). This record states decisions; the note holds the evidence. The note predates the round-1 revision: where they differ (crate shape, forge checkout, O1), this record wins. Upstream pin `c308970263` (v18.20.0); omp2 base `origin/omp2 9cb6fd6389`. Citations: `upstream:` is the OMPv1 pin; `ovnfs@c43f05a:` is `stencil-hq/ovnfs` at `c43f05a517`, re-read from a fresh clone on 2026-11-14; bare paths are omp2. Everything below comes from reading; nothing was built, run or timed, and claims that rest on inference are marked [INFERENCE].

## Context

### What OMPv1 does

- `pi-iso` is a cross-platform isolation layer with eight backends: APFS `clonefile`, btrfs snapshot, ZFS clone, Linux `FICLONE` tree, kernel overlayfs with a `fuse-overlayfs` fallback, Windows block clone, ProjFS and an always-available `Rcopy` (`upstream:crates/pi-iso/src/lib.rs:8-13`, `upstream:crates/pi-iso/src/lib.rs:51-71`). One `IsolationBackend` trait fronts them, with a per-OS fallback order (`upstream:crates/pi-iso/src/lib.rs:136-148`, `upstream:crates/pi-iso/src/lib.rs:267-299`). It is 5,094 lines in 12 files with 15 tests, none in the btrfs, zfs, reflink-tree, block-clone or file-clone modules (counted).
- Two product features use it. Isolated subagents get a copy-on-write view of the repo; `isolation.backend` picks a backend and `ensureIsolation` walks the candidates (`upstream:packages/coding-agent/src/task/settings.ts:41-44`, `upstream:packages/coding-agent/src/task/worktree.ts:629-674`). New worktrees (`/wt`, `github pr_checkout`, `git worktree add` in bash) are copy-on-write clones of the source checkout "so ignored build artifacts (node_modules, target) carry over", on by default (`upstream:crates/pi-shell/src/git/mod.rs:17-22`, `upstream:packages/coding-agent/src/task/settings.ts:83-94`, `upstream:packages/coding-agent/src/session/session-worktree.ts:150-155`).
- The worktree path clones the tree minus `.git`, registers the worktree, copies the index, rewrites only the paths that differ from the target, and prunes directories holding `pyvenv.cfg` or `CMakeCache.txt` (`upstream:crates/pi-vcs/src/git/mutate.rs:678-696`, `upstream:crates/pi-vcs/src/git/mutate.rs:759-790`, `upstream:crates/pi-vcs/src/git/mutate.rs:1842-1872`). A failed backend is recorded as `clone_error = Some(err.to_string())` (`upstream:crates/pi-vcs/src/git/mutate.rs:691`). `WorktreeClone::Prefer(kind)` exists for one caller, the napi shim, which builds it from a backend the TypeScript setting names (`upstream:crates/pi-vcs/src/types.rs:110-119`, `upstream:crates/pi-natives/src/vcs.rs:886-892`). Six integration tests and four unit tests cover the clone path (`upstream:crates/pi-vcs/tests/worktree_clone_carry.rs:103-362`, `upstream:crates/pi-vcs/src/git/mutate.rs:2943`, `:3025`, `:3056`, `:3114`).
- ovnfs is not a crate. It is the external Go program `stencil-hq/ovnfs` (`ovnfs@c43f05a:go.mod:1-3`). When its binary is on PATH and `isolation.backend` is `auto`, isolated subagents run in ovnfs checkouts, and failures are reported with "no silent fallback to native isolation" (`upstream:packages/coding-agent/src/task/structured-subagent.ts:907-911`, `upstream:packages/coding-agent/src/task/ovnfs.ts:1-3`, `upstream:packages/coding-agent/src/task/ovnfs.ts:260-264`). The adapter is four TypeScript files (1,014 lines) and 25 upstream files mention ovnfs (counted); the only Rust mention is the shell's git guard hint (`upstream:crates/pi-shell/src/git/guard.rs:5`, `:12`, `:192`).
- `pi-vfs` is not ovnfs and not isolation. It is the embedded shell's injectable async filesystem, with host paths plus `scheme://` providers (`upstream:crates/pi-vfs/src/lib.rs:1-17`, `upstream:packages/coding-agent/src/internal-urls/url-filesystem.ts:1-14`). No file under `upstream:crates/pi-vfs` mentions ovnfs (searched).

### What omp2 has

- Subagent isolation (ADR 0007, implemented). Every child gets a manifest-driven per-file view: `clonefile` on macOS, `FICLONE` on Linux, a hard-link-then-copy fallback elsewhere (`crates/envd/src/workspace/operations.rs:673-746`, `crates/envd/src/workspace/operations.rs:2041-2128`). `CreateWorktree` has no backend field, and the selector convar was deleted because it advertised backends that did not exist (`crates/proto/proto/omp/env/v1/env.proto:1154-1160`, `docs/adr/0007-subagent-filesystem-isolation.md:94`). The walk keeps regular files that git does not ignore (`crates/envd/src/workspace/operations.rs:1036-1038`, `:1053`); the owner confirmed on 2026-11-01 that gitignored files are not copied (`docs/adr/0007-subagent-filesystem-isolation.md:89`, `:93`).
- What the isolation lifecycle spends, from reading: `hash_file` reads and stages every file whose in-memory fingerprint is not cached, the cache is keyed by absolute path, and a merge takes two full-tree snapshots (`crates/envd/src/workspace/operations.rs:1182-1218`, `:210-250`, `:805`, `:821`). [INFERENCE, unmeasured] That costs more than the clone syscalls. The repo records no timing; W7 measures isolated-slot creation (`crates/e2e/src/baseline/workloads.rs:795-830`).
- `/wt`. It shells to the git binary: `git stash create`, `git worktree add -b`, `stash apply --index` with a plain-apply fallback, then copies untracked files that are not ignored (`git ls-files --others --exclude-standard`), so ignored caches stay behind (`crates/app/src/chat_services/workspace.rs:35-92`). Its base comes from `SV_WORKTREE_BASE`, read through `state.con` (`crates/app/src/chat_services/workspace.rs:111-118`). `omp-app` already depends on `omp-vcs` (`crates/app/Cargo.toml:112`).
- Forge checkout. `checkout` fetches a change request's head from its `clone_url` and creates a worktree for it under `<envd state>/forge-worktrees/cr-<n>` (`crates/envd/src/forge_worktree.rs:21-35`, `:133-177`, `:248-249`, `:304-306`). The checked-out code comes from the forge, possibly a fork, not from the user's checkout.
- `omp-vcs`. `worktree_add(path, ref, detach)` has no clone option and none of upstream's clone helpers (`crates/vcs/src/git/mutate.rs:446-496`; tests `:1604-1645`). It depends on `omp-core`, `gix`, `jj-lib`, `tokio` and, on Unix, `libc` (`crates/vcs/Cargo.toml:18-30`). The only worktree convar is `sv_worktree_base` (`crates/envd/src/host_settings.rs:138-148`).
- Sandbox read denials. `sv_sandbox_read_deny` lists absolute paths the kernel sandbox makes unreadable (`crates/envd/src/exec_settings/sandbox.rs:297-302`, applied at `crates/envd/src/exec_sandbox.rs:1337-1338`); `sv_sandbox_read_deny_globs` adds globs "when supported by the selected sandbox backend" (`crates/envd/src/exec_settings/sandbox.rs:314-319`). Neither static is re-exported from `omp_envd::exec_settings` today (`crates/envd/src/exec_settings/mod.rs:3-14`).
- Two private copies of the per-file clone FFI exist, in `omp-envd` and `omp-sandbox` (`crates/envd/src/workspace/operations.rs:2059`, `:2076`; `crates/sandbox/src/runtime/macos.rs:178-196`). Neither is in scope here (D6).
- No accepted record plans another consumer of a tree or file clone: ADR 0054's `cp` slice does not mention reflink (`docs/adr/0054-shell-builtins.md:70`), and D1 below keeps the envd view as it is.
- Platforms. CI runs `ubuntu-24.04` and macOS and has no Windows job; embedded CPython bundles exist only for macOS arm64 and Linux (`.github/workflows/ci.yml:128`, `:457`, `:654`; `AGENTS.md:116-118`).
- ovnfs. No code, extension, script or CI file mentions it. The records are ADR 0007's amendment and `docs/adr/TASKS.md:217` (OPEN, "README read only") (`docs/adr/0007-subagent-filesystem-isolation.md:82-84`).

### Rules that bind

- Additive only. No existing tool, skill, convar, hook, URL scheme or CLI command changes behaviour, name, schema or revision.
- ADR 0007 governs subagent views. Its title and decision are about "a subagent that may write" (`docs/adr/0007-subagent-filesystem-isolation.md:1`, `:26`), and "no gitignored path is safe to copy" is stated of the subagent snapshot walk in `snapshot_at` (`docs/adr/0007-subagent-filesystem-isolation.md:93`). A tracked-only view must not be presented as full isolation (`:53-54`).
- ADR 0035: library errors are `thiserror` enums with typed sources; formatted error strings are rejected and counted by the lintx ratchet (`docs/adr/0035-rust-for-the-engine.md:55-56`, `:89-90`).
- ADR 0049 D1: vendor integration code never enters core, and a vendor tool is a T2 extension (`docs/adr/0049-tiered-integration-architecture.md:41-54`). ADR 0036: extensions are Python and there is no TypeScript runtime (`docs/adr/0036-python-for-extensions.md:40-41`). ADR 0024: the roster is small and fixed, and nothing here adds a model-facing tool (`docs/adr/0024-small-permanent-roster.md:33-44`).
- PHILOSOPHY: refuse splits that carry no weight, and "a surface nobody has consumed is a guess" (`PHILOSOPHY.md:120-124`, `:140-141`).
- AGENTS.md: enums before `dyn` (`AGENTS.md:368`); a new crate brings a README, a labeler entry and lints on both OSes (`AGENTS.md:113-121`, `:160-164`); pre-release code is moved, not copied (`AGENTS.md:133-134`).

## Decision

Part (a), copy-on-write backends, is class c narrowed to the tree-clone slice of pi-iso and one consumer, `/wt`. Part (b), ovnfs, is class b.

**D1. Subagent isolation keeps its per-file view. It gets no new backend and no backend selector.** The manifest-driven view is the equivalent of pi-iso for this consumer, and it is the only shape that keeps ADR 0007's ignored-file rule: a whole-tree `clonefile`, a btrfs or ZFS snapshot and an overlay mount all expose ignored files too (`upstream:crates/pi-iso/src/apfs.rs:3-8`, `upstream:crates/pi-iso/src/btrfs.rs:1-6`, `upstream:crates/pi-iso/src/overlayfs.rs:1-6`). `omp-envd` keeps its private clone code unchanged.

**D2. The clone primitives are a private module of `omp-vcs`, not a new crate.** They live in `crates/vcs/src/cow/` (`mod.rs`, `apfs.rs`, `linux_reflink.rs`, `tree.rs`), declared `pub(crate) mod cow`. The module uses an enum and `match`, not trait objects, and adds no dependency: `libc` is already a Unix dependency of `omp-vcs` (`crates/vcs/Cargo.toml:29-30`). Its one public type is `BackendKind`, re-exported from `omp_vcs::types` because `WorktreeAddResult` names it. Failures are a `thiserror` enum `CowError` with the `io::Error` as `#[source]` and the backend and path as named fields; no message is formatted (ADR 0035). These are the backends, exactly:

| Upstream piece | Decision | Reason |
|---|---|---|
| APFS `clonefile`, whole tree and top-level entries with a skip list (`upstream:crates/pi-iso/src/apfs.rs:3-8`, `upstream:crates/pi-iso/src/apfs.rs:118-172`) | **ported** | Tree clone for worktrees; macOS is the user platform. |
| Linux `FICLONE` tree: directories and symlinks recreated, `FICLONE` per file, mode and times copied (`upstream:crates/pi-iso/src/linux_reflink.rs:1-9`, `upstream:crates/pi-iso/src/linux_reflink.rs:157-170`) | **ported** | Same consumer; omp2 already uses `FICLONE` per file (`crates/envd/src/workspace/operations.rs:2067-2085`). |
| File-level `cow` and its errno classes (`upstream:crates/pi-iso/src/cow.rs:54`, `:75`, `:260`, `:283`) | **ported, Unix half** (`upstream:crates/pi-iso/src/cow.rs:1-286`) | The tree walk's per-file step. The Windows half is `upstream:crates/pi-iso/src/cow.rs:287-436`. |
| `diff` (`upstream:crates/pi-iso/src/diff.rs:1-14`) | covered | omp2's content-addressed manifest diff (`crates/envd/src/workspace/operations.rs:820`, `:1426`). |
| Windows block clone (`upstream:crates/pi-iso/src/windows_block_clone.rs:1-9`) | dropped | No Windows CI job and no CPython bundle. Trigger: a Windows job. |

| overlayfs and `fuse-overlayfs` (`upstream:crates/pi-iso/src/overlayfs.rs:1-15`) | dropped | Needs a mount privilege or FUSE (`upstream:crates/pi-iso/src/overlayfs.rs:8-11`); upstream fixed a leaked mount and daemon (`upstream:packages/coding-agent/CHANGELOG.md:684`). |

| `Rcopy` (`upstream:crates/pi-iso/src/rcopy.rs:1-12`) | dropped | Its `git worktree add --detach` is a tracked-only view, which ADR 0007 prohibits as isolation (`docs/adr/0007-subagent-filesystem-isolation.md:53-54`); omp2 already has a native `worktree_add` (`crates/vcs/src/git/mutate.rs:447`). |
| napi shim, auto order, `isolation.backend`, `WorktreeClone::Prefer` (`upstream:crates/pi-natives/src/iso.rs:103-150`, `upstream:crates/pi-natives/src/vcs.rs:886-892`, `upstream:packages/coding-agent/src/task/settings.ts:41-44`) | dropped | omp2 deleted its selector convar; selection is by probing (`docs/adr/0007-subagent-filesystem-isolation.md:94`). `Prefer`'s only caller is the shim, so it has no omp2 caller. |

Why not a crate now: the record has one consumer in scope, `omp-vcs`'s `worktree_add_with` (D3). A leaf crate would be a split that carries no weight (`PHILOSOPHY.md:120-124`) and an API nobody else consumes (`:140-141`), and it would add a README, labeler entry and notices entry for that one caller (`AGENTS.md:120-121`, `:160-164`).

Extraction rule: the first accepted record that gives the primitives a second consumer (`cp` reflink under ADR 0054, the envd view, or the sandbox copy) moves `crates/vcs/src/cow/` into a leaf crate `crates/iso` (package `omp-iso`, `libc` only) in that consumer's first slice. It is a move, not a copy (`AGENTS.md:133-134`), and `omp-vcs` then depends on the crate. `omp-shell-builtins` must not take an `omp-vcs` dependency to reach the module, because it would pull in `gix` and `jj-lib` (`crates/vcs/Cargo.toml:20-21`).

**D3. The one consumer is clone-first `/wt`, behind `sv_worktree_clone`, off by default.** `GitRepo::worktree_add_with(path, ref, &WorktreeAddOptions)` sits beside the unchanged `worktree_add` (`crates/vcs/src/git/mutate.rs:447`), ported from `upstream:crates/pi-vcs/src/git/mutate.rs:620-860` and `:1747-1998`. Its types:

- `WorktreeClone { Off, Auto }`. `Auto` tries the host's candidates in upstream's order for the OS. `Prefer` is not ported (D2 table).
- `WorktreeAddOptions<'a> { detach: bool, clone: WorktreeClone, keep_changes: bool, withhold: &'a [PathBuf] }`. `withhold` is a list of absolute paths (D4).
- `WorktreeAddResult { cloned_with: Option<BackendKind>, clone_skipped: Option<CloneSkipped>, withheld: Vec<PathBuf> }`. `CloneSkipped` is a `thiserror` enum: `SparseCheckout`, `SplitIndex` and `SourceIndexMissing` as unit variants (`upstream:crates/pi-vcs/src/git/mutate.rs:768-778`), `NoBackend`, and `Backend { kind, #[source] source: CowError }`. Upstream's string `clone_error` (`upstream:crates/pi-vcs/src/git/mutate.rs:691`) is not ported, because it formats an error (ADR 0035).

`/wt` uses it only when the convar is on. Any clone failure falls back to the ordinary checkout inside `worktree_add_with`, and the result says why. With the convar off nothing changes.

**D4. Ignored files a clone carries: forge checkout never clones, and `/wt` withholds credentials and read-denied paths.**

- Forge checkout keeps its ordinary checkout and is not a consumer of D3. It materializes a change request's head fetched from the forge (`crates/envd/src/forge_worktree.rs:248-249`, `:304-306`). A clone of the user's checkout would put its ignored files (`.env`, `.npmrc`, keys) into a directory of code from that change request, where its build or test scripts can read them. Upstream does clone PR checkouts (`upstream:packages/coding-agent/src/task/settings.ts:91-92`); omp2 does not. Re-entry needs the owner (O11).
- `/wt` with the convar on withholds an ignored path when (a) its file or directory name is in a fixed credential-name table, or (b) it lies at or below an absolute path in `sv_sandbox_read_deny`. The table is data in `crates/vcs/src/git/` and holds the names ovnfs documents for its `secret` predicate: `.env` and `.env.*` (except `.example`, `.sample`, `.template`, `.dist`), `.netrc`, `.npmrc`, `.pypirc`, `.git-credentials`, `credentials`, `credentials.json`, `credentials.toml`, `id_rsa`, `id_dsa`, `id_ecdsa`, `id_ed25519`, `*.pem`, `*.key`, `*.p12`, `*.pfx`, and the directories `.ssh`, `.gnupg`, `.aws`, `.kube`, `.docker` (`ovnfs@c43f05a:docs/configuration.md:103`). Withheld paths are removed from the clone in the same pass as the `pyvenv.cfg` and `CMakeCache.txt` prune (`upstream:crates/pi-vcs/src/git/mutate.rs:1842-1872`), before the worktree is registered, and are listed in `WorktreeAddResult::withheld`.
- Tracked files and untracked files that git does not ignore are never withheld. The off path carries them today (`crates/app/src/chat_services/workspace.rs:63-90`), so the on path matches it; only the ignored files are new.
- Why: ADR 0007's rule does not bind `/wt` (Rules that bind; O1), so ignored caches may be carried. But a path the user denied to the sandbox must not reappear readable at a new path under the worktree base, and credential files are what ADR 0007's owner decision and ovnfs's own `local secret` rule both single out (`docs/adr/0007-subagent-filesystem-isolation.md:93`, `ovnfs@c43f05a:docs/configuration.md:76`). `sv_sandbox_read_deny_globs` is not applied (O12).

**D5. ovnfs is not adopted.** `pi-vfs` is unrelated to it (Context). ovnfs is not tied to a host filesystem: it keeps its own copy-on-write layer, with an NFSv3 loopback mount on macOS and a FUSE mount on Linux (`ovnfs@c43f05a:README.md:12-14`, `ovnfs@c43f05a:README.md:96-97`, `ovnfs@c43f05a:docs/platforms.md:5-9`), and it uses host block cloning only to capture files over 1 MiB (`ovnfs@c43f05a:docs/internals.md:143-146`). So the brief's test for class b, "it only helps on a filesystem this project's users do not have", does not apply, and the decision rests on these grounds instead:

- No need is shown that the per-file view fails to meet; ovnfs's claim is a checkout "ready in about a second at any size" (`upstream:packages/coding-agent/src/task/settings.ts:175-176`) and omp2 records no creation time.
- Its defaults cross ADR 0007's ignored-file rule. The built-in rules end `local secret`, `cache … node_modules | .venv …`, `cache ignored & dir`, `local ignored`, `source *` (`ovnfs@c43f05a:docs/configuration.md:75-81`), and `cache` and `local` paths show "the folder, live until the checkout writes the path" (`ovnfs@c43f05a:docs/configuration.md:47-60`). So by default every ignored path and every credential-named file is readable inside a checkout, which ADR 0007 forbids for a subagent view (`docs/adr/0007-subagent-filesystem-isolation.md:93`). A checkout also gets a private git directory where omp2's view has no `.git` (`ovnfs@c43f05a:README.md:96-98`, `crates/envd/src/workspace/operations.rs:1038`).
- It needs a second daemon and a visible mount, `~/checkouts` by default (`ovnfs@c43f05a:docs/configuration.md:5-8`). macOS relies on a `mount_nfs` socket form its docs call undocumented (`ovnfs@c43f05a:docs/platforms.md:15-20`); Linux needs `fusermount3` and a mount below `$HOME`, `/mnt`, `/media` or `/tmp` (`ovnfs@c43f05a:docs/configuration.md:10-11`), and a forced stop fails in "some unprivileged containers" (`ovnfs@c43f05a:docs/platforms.md:52-54`).
- Network-filesystem behaviour is documented: client-local NFSv3 locks and cache invalidation that can lag up to 60 s (`ovnfs@c43f05a:docs/limitations.md:28-30`, `:40-43`); upstream recorded a file watcher that looped on ovnfs checkouts (`upstream:packages/coding-agent/CHANGELOG.md:85`).
- It is not a sandbox (`ovnfs@c43f05a:docs/limitations.md:3`, `ovnfs@c43f05a:README.md:103`); under omp-sandbox the checkout path would be a declared writable scope (`crates/sandbox/src/spec.rs:87-90`).
- Core has no seam for it (`crates/proto/proto/omp/env/v1/env.proto:1154-1160`), the upstream adapter spans 25 files and speaks admin protocol version 5 (`upstream:packages/coding-agent/src/ovnfs/client.ts:21`, `upstream:packages/coding-agent/src/task/ovnfs.ts:67-68`), and it cannot be ported as TypeScript (`docs/adr/0036-python-for-extensions.md:40-41`).

What the user does instead: install `ovnfs` and copy its agent skill into the skills directory (`ovnfs@c43f05a:README.md:114`; omp2 discovers `SKILL.md` skills under `.omp/skills` and `<config root>/agent/skills`, `crates/driver/src/discovery/skills.rs:1-12`). Agents then run `ovnfs new`, `diff` and `apply` through the bash tool. Subagents keep the per-file view. ovnfs reads its user rules from `~/.o2/ovnfs.yml` (`ovnfs@c43f05a:docs/configuration.md:12`, `:85`), inside omp2's config root (`AGENTS.md`, "User configuration lives in `~/.o2`"); omp2 loads `config.cfg` and cfg scripts there, so a foreign `ovnfs.yml` is not read by omp2 [INFERENCE: cfg discovery was not traced]. Re-entry triggers: (i) a recorded W7 or equivalent shows creation or merge over a budget the owner sets, with the clone step as the cost; (ii) the owner decides isolated views should see ignored build caches read-only, which is ovnfs's `cache` class; (iii) isolation across machines becomes roadmap (`ovnfs@c43f05a:README.md:9-10`, `:66-68`); (iv) Linux ext4 desktops become a primary platform and copy cost is reported. If re-opened, the shape is a Python extension (ADR 0036, ADR 0049) over a neutral isolation-provider seam, returning work as `ovnfs diff --binary` patches (`upstream:packages/coding-agent/src/task/ovnfs.ts:171-181`), with a `hidden` rule for credential and ignored paths, after a macOS spike (O9).

**D6. Out of this record.** Forge checkout through clones (D4, O11); bash `git worktree add` served through clones (upstream `PI_SMART_GIT`, `upstream:crates/pi-shell/src/git/mod.rs:3-22`; omp2's `crates/shell` and `crates/shell-builtins` have no worktree handling); the shared-checkout guard; moving the envd view or the sandbox copy onto the `cow` module; a standalone `omp-iso` crate (D2 extraction rule); Windows block clone; and `pi-vfs`, which Gap 6 declined (`docs/adr/0054-shell-builtins.md:19`, `:51`).

## Rejected options

| Option | Why rejected |
|---|---|
| Do nothing | Keeps ADR 0007 intact but leaves macOS users with cold worktrees, the one user-visible difference pi-iso makes (`upstream:crates/pi-shell/src/git/mod.rs:17-22`). |
| Port all of `pi-iso` | 5,094 lines plus `async-trait`, `tokio` and `pi-diff` (`upstream:crates/pi-iso/Cargo.toml:13-26`); eight backends behind trait objects where AGENTS asks for enums before `dyn` (`AGENTS.md:368`); four backends have no tests upstream; it breaks ADR 0007 twice (ignored files, and `Rcopy`'s tracked-only view). |
| A new leaf crate `omp-iso` now (round-1 draft) | One consumer in scope (D2). The crate is the extraction target once a second consumer is accepted, not before. |
| Put the primitives in `omp-core` | Every consumer already depends on it, but it puts `unsafe` FFI in the crate everything rebuilds on (`docs/adr/0049-tiered-integration-architecture.md:88-101`). |
| Clone-first forge checkout (upstream) | Carries the user's ignored credentials into a checkout of change-request code (D4). |
| Carry every ignored file into `/wt` (upstream) | A `sv_sandbox_read_deny` path would reappear readable under the worktree base (D4). |

## Consequences

- macOS users who turn the convar on get `/wt` worktrees that keep ignored build caches and start without writing the tracked files, minus credential-named and read-denied ignored paths. With it off, the default, nothing changes.
- Forge checkout stays a cold checkout. A user who wants caches there copies them by hand.
- Subagent isolation is untouched, and so is its cost: snapshot hashing and the merge-time re-hash remain. This record promises no speedup there.
- No new crate. About 1,000 lines of ported Rust in `omp-vcs`'s `cow` module, about 550 in its worktree code and about 650 of tests. The per-file clone FFI then exists in three places (envd, sandbox, `omp-vcs`); folding them together waits for the D2 extraction rule.
- `omp-vcs` gains `unsafe` FFI behind `cfg(target_os)` gates; both lint jobs see it (`AGENTS.md:113-116`).
- Only the macOS job can prove clone success. [INFERENCE] No Linux job has a reflink-capable filesystem, so Linux CI proves the fallback, the capability probe and the withhold table.
- With the convar on, `/wt` carries staged hunks by copying the index, not by `git stash create` and `apply --index` (`upstream:crates/pi-vcs/src/git/mutate.rs:709-757`, `crates/app/src/chat_services/workspace.rs:63-79`); S3's parity test covers it.
- ovnfs stays opt-in through its CLI and skill. Nothing in core mentions it.
- On acceptance, ADR 0007's sentence that btrfs or ZFS snapshots, overlayfs, ProjFS, block clone and a git-worktree or recursive-copy backend are "future targets" (`docs/adr/0007-subagent-filesystem-isolation.md:33-36`) and its OVNFS proposal (`docs/adr/0007-subagent-filesystem-isolation.md:82-84`) are marked superseded by D1, D2 and D5. This record does not edit ADR 0007.
- Attribution: `crates/vcs/NOTICE` carrying Can Bölük's and Mario Zechner's copyright lines.

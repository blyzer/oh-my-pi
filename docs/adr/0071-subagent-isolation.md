# 0071. Copy-on-write tree cloning lives in a small leaf crate and serves worktrees; subagent isolation keeps its per-file view; ovnfs is not adopted

Status: Proposed 2026-11-13
Date: 2026-11-13
Area: runtime

Research: [docs/research/subagent-isolation.md](../research/subagent-isolation.md) (Gap 1 of the upstream gap closure). This record states decisions; the note holds the evidence. Upstream pin `c308970263` (v18.20.0); omp2 base `origin/omp2 f4186b783b`. Citations: `upstream:` is the OMPv1 pin; `ovnfs@c43f05a:` is `stencil-hq/ovnfs` at `c43f05a517`; bare paths are omp2. Everything below comes from reading; nothing was built, run or timed, and claims that rest on inference are marked [INFERENCE].

## Context

### What OMPv1 does

- `pi-iso` is a cross-platform isolation layer with eight backends: APFS `clonefile`, btrfs snapshot, ZFS clone, Linux `FICLONE` tree, kernel overlayfs with a `fuse-overlayfs` fallback, Windows block clone, ProjFS and an always-available `Rcopy` (`upstream:crates/pi-iso/src/lib.rs:8-13`, `upstream:crates/pi-iso/src/lib.rs:51-71`). One `IsolationBackend` trait fronts them, with a per-OS fallback order (`upstream:crates/pi-iso/src/lib.rs:136-148`, `upstream:crates/pi-iso/src/lib.rs:267-299`). It is 5,094 lines in 12 files with 15 tests, none in the btrfs, zfs, reflink-tree, block-clone or file-clone modules (counted).
- Two product features use it. Isolated subagents get a copy-on-write view of the repo; `isolation.backend` picks a backend and `ensureIsolation` walks the candidates (`upstream:packages/coding-agent/src/task/settings.ts:44`, `upstream:packages/coding-agent/src/task/worktree.ts:629-674`). New worktrees (`/wt`, PR checkout, `git worktree add` in bash) are copy-on-write clones of the source checkout, "so ignored build caches come along for free", on by default (`upstream:crates/pi-shell/src/git/mod.rs:17-22`, `upstream:packages/coding-agent/src/task/settings.ts:82-94`, `upstream:packages/coding-agent/src/session/session-worktree.ts:150-155`).
- The worktree path clones the tree minus `.git`, registers the worktree, copies the index, rewrites only the paths that differ from the target, and prunes directories holding `pyvenv.cfg` or `CMakeCache.txt` (`upstream:crates/pi-vcs/src/git/mutate.rs:678-696`, `upstream:crates/pi-vcs/src/git/mutate.rs:759-790`, `upstream:crates/pi-vcs/src/git/mutate.rs:1839-1872`). Six integration tests and four unit tests cover it (`upstream:crates/pi-vcs/tests/worktree_clone_carry.rs:103-362`, `upstream:crates/pi-vcs/src/git/mutate.rs:2943`, `:3025`, `:3056`, `:3114`).
- ovnfs is not a crate. It is the external Go program `stencil-hq/ovnfs`. When its binary is on PATH and `isolation.backend` is `auto`, isolated subagents run in ovnfs checkouts, with no fallback once it is found (`upstream:packages/coding-agent/src/task/structured-subagent.ts:910-911`, `upstream:packages/coding-agent/src/task/ovnfs.ts:1-3`, `upstream:packages/coding-agent/src/task/ovnfs.ts:260-264`). The adapter is four TypeScript files (1,014 lines) and 25 upstream files mention ovnfs (counted).
- `pi-vfs` is not ovnfs and not isolation. It is the embedded shell's injectable async filesystem, with host paths plus `scheme://` providers (`upstream:crates/pi-vfs/src/lib.rs:1-17`, `upstream:packages/coding-agent/src/internal-urls/url-filesystem.ts:1-14`).

### What omp2 has

- Subagent isolation (ADR 0007, implemented). Every child gets a manifest-driven per-file view: `clonefile` on macOS, `FICLONE` on Linux, a hard-link-then-copy fallback elsewhere (`crates/envd/src/workspace/operations.rs:673-746`, `crates/envd/src/workspace/operations.rs:2041-2128`). `CreateWorktree` has no backend field, and the selector convar was deleted because it advertised backends that did not exist (`crates/proto/proto/omp/env/v1/env.proto:1154-1160`, `docs/adr/0007-subagent-filesystem-isolation.md:94`). The walk keeps regular files that git does not ignore (`crates/envd/src/workspace/operations.rs:1036-1038`, `:1053`); the owner confirmed on 2026-11-01 that gitignored files are not copied (`docs/adr/0007-subagent-filesystem-isolation.md:89`, `:93`).
- What the isolation lifecycle spends, from reading: `hash_file` reads and stages every file whose in-memory fingerprint is not cached, the cache is keyed by absolute path, and a merge takes two full-tree snapshots (`crates/envd/src/workspace/operations.rs:1182-1218`, `:210-250`, `:805`, `:821`). [INFERENCE, unmeasured] That costs more than the clone syscalls. The repo records no timing; W7 measures isolated-slot creation (`crates/e2e/src/baseline/workloads.rs:795-830`).
- User worktrees. `/wt` uses the git binary and leaves ignored caches behind (`crates/app/src/chat_services/workspace.rs:26-92`). Forge checkout calls `omp-vcs` `worktree_add` (`crates/envd/src/forge_worktree.rs:304-306`). `worktree_add` has no clone option and none of upstream's clone helpers (`crates/vcs/src/git/mutate.rs:446-496`). The only worktree convar is `sv_worktree_base` (`crates/envd/src/host_settings.rs:138-148`).
- Two private copies of the per-file clone FFI exist, in `omp-envd` and `omp-sandbox` (`crates/envd/src/workspace/operations.rs:2059`, `:2076`; `crates/sandbox/src/runtime/macos.rs:178-196`). They cannot share code: `omp-envd` depends on `omp-sandbox`, `omp-shell-builtins` and `omp-vcs`, `omp-sandbox` on `omp-core` only, and `omp-vcs` on `omp-core`, `gix` and `libc` (`crates/envd/Cargo.toml:48`, `:69-70`, `:76`; `crates/sandbox/Cargo.toml:18`; `crates/vcs/Cargo.toml:19-20`, `:30`; `crates/shell-builtins/Cargo.toml:51-54`).
- Platforms. CI runs `ubuntu-24.04` and macOS and has no Windows job; embedded CPython bundles exist only for macOS arm64 and Linux (`.github/workflows/ci.yml:128`, `:457`, `:654`; `AGENTS.md:116-118`).
- ovnfs. No code, extension, script or CI file mentions it. The records are ADR 0007's amendment and `docs/adr/TASKS.md:217` (OPEN, "README read only") (`docs/adr/0007-subagent-filesystem-isolation.md:82-84`).

### Rules that bind

- Additive only. No existing tool, skill, convar, hook, URL scheme or CLI command changes behaviour, name, schema or revision.
- ADR 0007: a subagent's view holds no gitignored file, and a tracked-only view must not be presented as full isolation (`docs/adr/0007-subagent-filesystem-isolation.md:53-54`, `:93`).
- ADR 0049 D1: vendor integration code never enters core, and a vendor tool is a T2 extension (`docs/adr/0049-tiered-integration-architecture.md:41-54`). ADR 0036: extensions are Python and there is no TypeScript runtime (`docs/adr/0036-python-for-extensions.md:40-41`). ADR 0024: the roster is small and fixed, and nothing here adds a model-facing tool (`docs/adr/0024-small-permanent-roster.md:33-44`).
- AGENTS.md: enums before `dyn`; crate and dependency conventions; lint on both macOS and Linux (`AGENTS.md:368`, `AGENTS.md:160-164`, `AGENTS.md:113-116`).

## Decision

Part (a), copy-on-write backends, is class c narrowed to the tree-clone slice of pi-iso and its first consumer. Part (b), ovnfs, is class b.

**D1. Subagent isolation keeps its per-file view. It gets no new backend and no backend selector.** The manifest-driven view is the equivalent of pi-iso for this consumer, and it is the only shape that keeps ADR 0007's ignored-file rule: a whole-tree `clonefile`, a btrfs or ZFS snapshot and an overlay mount all expose ignored files too (`upstream:crates/pi-iso/src/apfs.rs:3-8`, `upstream:crates/pi-iso/src/btrfs.rs:1-6`, `upstream:crates/pi-iso/src/overlayfs.rs:1-6`). `omp-envd` keeps its private clone code unchanged. It is not moved onto `omp-iso`.

**D2. A new leaf crate, `omp-iso`, clones files and trees and does nothing else.** It lives in `crates/iso` (package `omp-iso`), depends on `libc` only, uses an enum and `match` rather than trait objects, and has no `tokio` or `async-trait`. These are the backends, exactly:

| Upstream piece | Decision | Reason |
|---|---|---|
| APFS `clonefile`, whole tree and top-level entries with a skip list (`upstream:crates/pi-iso/src/apfs.rs:3-8`, `upstream:crates/pi-iso/src/apfs.rs:118-172`) | **ported** | Tree clone for worktrees; macOS is the user platform. |
| Linux `FICLONE` tree: directories and symlinks recreated, `FICLONE` per file, mode and times copied (`upstream:crates/pi-iso/src/linux_reflink.rs:1-9`, `upstream:crates/pi-iso/src/linux_reflink.rs:157-170`) | **ported** | Same consumer; omp2 already uses `FICLONE` per file (`crates/envd/src/workspace/operations.rs:2067-2085`). |
| File-level `cow` and its errno classes (`upstream:crates/pi-iso/src/cow.rs:54`, `:75`, `:260`, `:283`) | **ported, Unix half** (`upstream:crates/pi-iso/src/cow.rs:1-286`) | Shared primitive. The Windows half is `upstream:crates/pi-iso/src/cow.rs:287-436`. |
| `diff` (`upstream:crates/pi-iso/src/diff.rs:1-14`) | covered | omp2's content-addressed manifest diff (`crates/envd/src/workspace/operations.rs:820`, `:1426`). |
| Windows block clone (`upstream:crates/pi-iso/src/windows_block_clone.rs:1-9`) | dropped | No Windows CI job and no CPython bundle. Trigger: a Windows job. |
| btrfs snapshot, ZFS clone (`upstream:crates/pi-iso/src/btrfs.rs:1-6`, `upstream:crates/pi-iso/src/zfs.rs:1-6`) | dropped | CLI plus subvolume or dataset root only (`upstream:crates/pi-iso/src/btrfs.rs:117-130`, `upstream:crates/pi-iso/src/zfs.rs:118-128`), no tests upstream, and they copy ignored files. |
| overlayfs and `fuse-overlayfs` (`upstream:crates/pi-iso/src/overlayfs.rs:1-15`) | dropped | Needs a mount privilege or FUSE (`upstream:crates/pi-iso/src/overlayfs.rs:8-11`); upstream fixed a leaked mount and daemon (`upstream:packages/coding-agent/CHANGELOG.md:684`). |
| ProjFS (`upstream:crates/pi-iso/src/projfs.rs:1-6`) | dropped | Windows only; 978 lines with 46 occurrences of `unsafe`. |
| `Rcopy` (`upstream:crates/pi-iso/src/rcopy.rs:1-12`) | dropped | Its `git worktree add --detach` is a tracked-only view, which ADR 0007 prohibits as isolation (`docs/adr/0007-subagent-filesystem-isolation.md:53-54`); omp2 already has a native `worktree_add` (`crates/vcs/src/git/mutate.rs:447`). |
| napi shim, auto order, `isolation.backend` (`upstream:crates/pi-natives/src/iso.rs:103-150`, `upstream:packages/coding-agent/src/task/settings.ts:44`) | dropped | omp2 deleted its selector convar; selection is by probing (`docs/adr/0007-subagent-filesystem-isolation.md:94`). |

It is a new crate, not an extension of the existing isolation code and not a module of `omp-core`. The existing clone code is private to `operations.rs` in `omp-envd`, and `omp-vcs`, `omp-shell-builtins` and `omp-sandbox` are all dependencies of `omp-envd`, so none of them can use it. `omp-core` reaches every crate and carries `libc` (`crates/core/Cargo.toml:37`), but everything rebuilds when it changes, which ADR 0049 D3 treats as a cost (`docs/adr/0049-tiered-integration-architecture.md:88-101`). The API is an enum, three functions and an error type, with `omp-vcs` as the first consumer and the envd view, the sandbox copy and the `cp` builtin of ADR 0054 (Gap 6) as likely later ones (`docs/adr/0054-shell-builtins.md:58`). The name follows the gap ledger (`docs/research/upstream-gap-closure.md`) and upstream lineage (O10); its README must say it clones files and trees and nothing else (`AGENTS.md:160-164`).

**D3. The first consumer is clone-first worktrees in `omp-vcs`, behind `sv_worktree_clone`, off by default.** `GitRepo::worktree_add_with(path, ref, options)` sits beside the unchanged `worktree_add` (`crates/vcs/src/git/mutate.rs:447`), ported from `upstream:crates/pi-vcs/src/git/mutate.rs:620-860` and `:1747-1960`. `/wt` and forge checkout use it only when the convar is on. Any clone failure falls back to the ordinary checkout and reports why. With the convar off nothing changes.

**D4. ovnfs is not adopted.** `pi-vfs` is unrelated to it, and ovnfs is not tied to a host filesystem: it keeps its own copy-on-write layer, with an NFSv3 loopback mount on macOS and a FUSE mount on Linux (`ovnfs@c43f05a:README.md:12-14`, `ovnfs@c43f05a:README.md:96-97`, `ovnfs@c43f05a:docs/platforms.md:5-9`). The decision rests on these grounds instead:
- No need is shown that the per-file view fails to meet; ovnfs's claim is a checkout "ready in about a second at any size" (`upstream:packages/coding-agent/src/task/settings.ts:175-176`) and omp2 records no creation time.
- Its defaults cross ADR 0007's ignored-file rule. `cache` and `local` paths, "build outputs, ignored files, secrets", read through to the live folder (`ovnfs@c43f05a:README.md:87-92`), and a checkout gets a private git directory where omp2's view has no `.git` (`ovnfs@c43f05a:README.md:96-98`, `crates/envd/src/workspace/operations.rs:1038`). The rule table was not read.
- It needs a second daemon and a visible mount, `~/checkouts` by default (`ovnfs@c43f05a:docs/configuration.md:5-8`). macOS relies on a `mount_nfs` socket form its docs call undocumented (`ovnfs@c43f05a:docs/platforms.md:15-20`); Linux needs `fusermount3` and a mount below `$HOME`, `/mnt`, `/media` or `/tmp` (`ovnfs@c43f05a:docs/configuration.md:10-11`), and a forced stop fails in "some unprivileged containers" (`ovnfs@c43f05a:docs/platforms.md:52-54`).
- Network-filesystem behaviour is documented: client-local NFSv3 locks and cache invalidation that can lag up to 60 s (`ovnfs@c43f05a:docs/limitations.md:28-30`, `:40-43`); upstream recorded a file watcher that looped on ovnfs checkouts (`upstream:packages/coding-agent/CHANGELOG.md:85`).
- It is not a sandbox (`ovnfs@c43f05a:docs/limitations.md:3`, `ovnfs@c43f05a:README.md:103`); under omp-sandbox the checkout path would be a declared writable scope (`crates/sandbox/src/spec.rs:87-90`).
- Core has no seam for it (`crates/proto/proto/omp/env/v1/env.proto:1154-1160`), the upstream adapter spans 25 files and speaks admin protocol version 5 (`upstream:packages/coding-agent/src/ovnfs/client.ts:21`, `upstream:packages/coding-agent/src/task/ovnfs.ts:67-68`), and it cannot be ported as TypeScript (`docs/adr/0036-python-for-extensions.md:40-41`).

What the user does instead: install `ovnfs` and copy its agent skill into the skills directory (`ovnfs@c43f05a:README.md:114`; omp2 discovers `SKILL.md` skills under `.omp/skills` and `<config root>/agent/skills`, `crates/driver/src/discovery/skills.rs:1-12`). Agents then run `ovnfs new`, `diff` and `apply` through the bash tool. Subagents keep the per-file view. Re-entry triggers: (i) a recorded W7 or equivalent shows creation or merge over a budget the owner sets, with the clone step as the cost; (ii) the owner decides isolated views should see ignored build caches read-only, which is ovnfs's `cache` class; (iii) isolation across machines becomes roadmap (`ovnfs@c43f05a:README.md:9-10`, `:66-68`); (iv) Linux ext4 desktops become a primary platform and copy cost is reported. If re-opened, the shape is a Python extension (ADR 0036, ADR 0049) over a neutral isolation-provider seam, returning work as `ovnfs diff --binary` patches (`upstream:packages/coding-agent/src/task/ovnfs.ts:171-181`), after a macOS spike (O9).

**D5. Out of this record.** Bash `git worktree add` served through clones (upstream `PI_SMART_GIT`, `upstream:crates/pi-shell/src/git/mod.rs:3-22`; omp2's `crates/shell` and `crates/shell-builtins` have no worktree handling); the shared-checkout guard; moving the envd view or the sandbox copy onto `omp-iso`; Windows block clone; and `pi-vfs`, which Gap 6 declined (`docs/adr/0054-shell-builtins.md:18`, `:38`).

## Rejected options

| Option | Why rejected |
|---|---|
| Do nothing | Keeps ADR 0007 intact but leaves macOS users with cold worktrees, the one user-visible difference pi-iso makes (`upstream:crates/pi-shell/src/git/mod.rs:17-22`). |
| Port all of `pi-iso` | 5,094 lines plus `async-trait`, `tokio` and `pi-diff` (`upstream:crates/pi-iso/Cargo.toml:13-26`); eight backends behind trait objects where AGENTS asks for enums before `dyn` (`AGENTS.md:368`); four backends have no tests upstream; it breaks ADR 0007 twice (ignored files, and `Rcopy`'s tracked-only view). |
| A private clone module inside `omp-vcs` | Cheaper, but only `omp-vcs` can use it. The envd view and the sandbox copy keep their private copies, and `cp` cannot reach it without `omp-shell-builtins` depending on `omp-vcs`, which pulls in `gix` (`crates/vcs/Cargo.toml:20`). |
| Put the primitives in `omp-core` | Every consumer already depends on it, but it puts `unsafe` FFI in the crate everything rebuilds on (`docs/adr/0049-tiered-integration-architecture.md:88-101`). |
| Carry only the ignored directories: keep today's checkout and, with the convar on, clone ignored directories into the new worktree | About 150 to 250 lines and no index work (estimate), but the checkout still writes every tracked file, carried build outputs would be older than the freshly written sources so mtime-based tools may rebuild [INFERENCE], and there is nothing upstream to port or test against. Kept as the fallback if S2's index reconciliation proves too risky. |
| New backends for subagent isolation (btrfs, ZFS, overlayfs, ProjFS, block clone, a selector convar) | D1 and D2: they cannot keep ADR 0007's rule, need privileges or CLIs the users do not have, and omp2 deleted the selector on purpose (`docs/adr/0007-subagent-filesystem-isolation.md:94`). |
| ovnfs as a Python extension over a new isolation-provider seam | A seam in `CreateWorktree` or a device family, about 1,000 lines of Python to track the admin protocol, daemon lifecycle and sandbox grants, and a macOS spike first (estimate). Consistent with ADR 0036 and ADR 0049, but pays for a gain nobody has measured. Revisit on a trigger in D4. |
| A Rust virtual-filesystem crate, or embedding the Go code | A reimplementation of a daemon, or a second language. |

## Slices

Each slice is one PR; tests are written first and not edited to pass. S1 and S2 are inert until S3 wires them. Only S3 changes behaviour, and only behind a default-off convar.

**S1. `omp-iso`: copy-on-write file and tree cloning.** A new crate, `crates/iso` (directories are unprefixed, packages are `omp-` prefixed, `AGENTS.md:160-161`). Contents: `BackendKind { Apfs, LinuxReflink }` dispatched by `match`; `clone_candidates()`; `clone_tree(kind, lower, merged, skip)`; `cow::clone_file` and `cow::is_unsupported`; `IsoError::{Unavailable, Other}`. Ported from `upstream:crates/pi-iso/src/apfs.rs`, `upstream:crates/pi-iso/src/linux_reflink.rs`, `upstream:crates/pi-iso/src/tree.rs`, `upstream:crates/pi-iso/src/cow.rs:1-286` and the matching parts of `lib.rs`: about 1,000 of 5,094 lines. Housekeeping: `libc` only (`Cargo.toml:101`), `[lints] workspace = true`, a `description`, a README, a copy of upstream's `LICENSE`, one `area/*` entry (`.github/labeler.yml:51-64`, under `area/tools` beside `vcs` and `walker`) and a `THIRD-PARTY-NOTICES.txt` entry (`AGENTS.md:120-122`).
- Tests: `apfs_clone_tree_skips_top_level_entry_and_preserves_symlink` (from `upstream:crates/pi-iso/src/apfs.rs:186-240`), `apfs_clone_tree_refuses_a_non_empty_destination`, `apfs_clone_tree_failure_removes_the_partial_destination`, `is_unsupported_matches_the_errno_table_per_os`, `linux_clone_tree_without_reflink_is_unavailable_and_leaves_no_destination`, `linux_clone_tree_shares_extents_on_a_reflink_filesystem`. The errno test is table-driven with `io::Error::from_raw_os_error`, so it runs on Linux CI: Linux `EXDEV`, `EOPNOTSUPP`, `ENOTTY`, `EINVAL`, `ENOSYS`; macOS `ENOTSUP`, `EOPNOTSUPP`, `EXDEV`; false for `ENOENT`, `EACCES`, `ENOSPC` (`upstream:crates/pi-iso/src/cow.rs:260`, `:283`). The capability-dependent tests detect the filesystem first and print SKIP when it cannot clone, as `upstream:crates/pi-vcs/tests/worktree_clone_carry.rs:88-108` does.
- Acceptance: the crate builds and lints clean on both lint jobs (`.github/workflows/ci.yml:645`, `:697`), and the tests pass on the macOS job and on `ubuntu-24.04`.
- Gate: none needed, because no crate depends on it yet. It is not a `cap-*` feature: it has one dependency, `libc`, and `cap-*` gates build weight (`docs/adr/0049-tiered-integration-architecture.md:88-101`). Behaviour is gated by S3's convar.

**S2. `omp-vcs`: clone-first worktree add.** `WorktreeClone` (`Off`, `Auto`, `Prefer`), `WorktreeAddOptions { detach, clone, keep_changes }` and `WorktreeAddResult { cloned_with, clone_error }` (`upstream:crates/pi-vcs/src/types.rs:110-137`), and `GitRepo::worktree_add_with(path, ref, options)` with upstream's flow and helpers (`upstream:crates/pi-vcs/src/git/mutate.rs:620-860`, `upstream:crates/pi-vcs/src/git/mutate.rs:1747-1960`): `register_worktree`, `seed_worktree_changes`, `worktree_add_cloned`, `index_diff_paths`, `refresh_clean_index_stats`, `collect_clone_reconciliation_paths`, `copy_worktree_path`, `prune_nonrelocatable_clone_dirs` and `cleanup_worktree_add`. The existing `worktree_add(path, ref, detach)` stays and delegates with `clone: Off`. About 490 lines plus about 600 lines of tests, from upstream's sizes (estimate).
- Tests, ported from `upstream:crates/pi-vcs/tests/worktree_clone_carry.rs` and `upstream:crates/pi-vcs/src/git/mutate.rs`: `clone_excludes_self_ignored_environments_and_nested_cmake_caches`, `clone_exclusion_keeps_tracked_data_and_keep_changes_state`, `clone_disabled_or_unavailable_uses_an_ordinary_checkout`, `clone_reconciles_carried_paths_using_target_ignore_rules`, `clone_target_cleanup_does_not_discard_keep_changes`, `clone_target_cleanup_keeps_nested_repositories_and_unlinks_only_symlinks`, `clone_first_worktree_reconciles_source_state_to_target_tree`, `clone_first_worktree_at_source_head_needs_no_checkout`, `worktree_add_keep_changes_carries_dirty_state_on_both_paths` and `worktree_add_keep_changes_carries_staged_only_state_without_phantom_edits`. New: `worktree_add_with_clone_off_matches_worktree_add`, beside the existing tests (`crates/vcs/src/git/mutate.rs:1609-1642`), and `sparse_checkout_or_split_index_falls_back_to_the_ordinary_checkout` (`upstream:crates/pi-vcs/src/git/mutate.rs:768-774`).
- Acceptance: with `clone: Off` the result matches today's `worktree_add`. With a working backend the new worktree has the source's tracked, staged, dirty and untracked state, and `cloned_with` names the backend. Directories holding `pyvenv.cfg` or `CMakeCache.txt` are not carried, and tracked files beneath them are still checked out. A clone failure leaves no partial directory and the ordinary checkout runs. When the target is not the source `HEAD`, paths that differ from the target tree are rewritten and the target's ignore rules decide which carried files stay. Clone-success cases run on the macOS job (`.github/workflows/ci.yml:426-457`, `:569`) and print SKIP on filesystems without clone; the fallback cases run everywhere, Linux included.
- Gate: inert. Nothing calls `worktree_add_with` with clone on until S3.

**S3. Convar and wiring.** `sv_worktree_clone` (bool, default false) sits beside `SV_WORKTREE_BASE` (`crates/envd/src/host_settings.rs:138-148`), with `legacy.path: "worktree.clone"` so the importer maps the v1 key, and is projected through `WorktreeSettings` (`crates/envd/src/host_settings.rs:167-173`, `:228-231`; `crates/driver/src/settings.rs:188-218`). Forge checkout passes `clone: Auto` when it is set. `checkout` takes no settings today (`crates/envd/src/forge_worktree.rs:134-139`), so it gains an argument that `DynForgeAdapter`, its only caller, fills from the convar (`crates/envd/src/forge_adapter/dyn_forge.rs:210-218`, `:410`; `crates/envd/src/forge_worktree.rs:304-306`). `/wt` calls `worktree_add_with` with `keep_changes: true` when it is set, in place of the stash, `git worktree add` and untracked copy (`crates/app/src/chat_services/workspace.rs:35-92`); `create_worktree_at` gains a parameter for the setting. The chat message names the backend that cloned, or why the clone was skipped.
- Tests: these existing tests pass unchanged: `worktree_carries_uncommitted_changes` (`crates/app/src/chat_services/workspace.rs:160-183`) and `checkout_creates_worktree_under_forge_root` (`crates/envd/src/forge_worktree.rs:363-364`). ## Consequences

- macOS users who turn the convar on get new worktrees that keep ignored build caches and start without writing the tracked files. With it off, the default, nothing changes.
- Subagent isolation is untouched, and so is its cost: snapshot hashing and the merge-time re-hash remain. This record promises no speedup there.
- One more crate (README, labeler entry, notices entry), about 1,500 lines of ported Rust and about 600 of tests. The per-file clone FFI then exists in three places (envd, sandbox, `omp-iso`); folding the first two in is left out on purpose (D5).
- Only the macOS job can prove clone success. [INFERENCE] No Linux job has a reflink-capable filesystem, so Linux CI proves the fallback and the capability probe.
- With the convar on, `/wt` carries staged hunks by copying the index, not by `git stash create` and `apply --index` (`upstream:crates/pi-vcs/src/git/mutate.rs:709-757`, `crates/app/src/chat_services/workspace.rs:63-79`); S3's parity test covers it.
- ovnfs stays opt-in through its CLI and skill. Nothing in core mentions it.
- On acceptance, ADR 0007's sentence that btrfs or ZFS snapshots, overlayfs, ProjFS, block clone and a git-worktree or recursive-copy backend are "future targets" (`docs/adr/0007-subagent-filesystem-isolation.md:33-36`) and its OVNFS proposal (`docs/adr/0007-subagent-filesystem-isolation.md:82-84`) are marked superseded by D1, D2 and D4. This record does not edit ADR 0007.
- Attribution: a `THIRD-PARTY-NOTICES.txt` entry and a crate `LICENSE` carrying Can Bölük's copyright line.

## Open questions for the owner

- **O1.** Does ADR 0007's "no gitignored path is safe to copy" (`docs/adr/0007-subagent-filesystem-isolation.md:93`) cover user-initiated worktrees? Recommendation: no. ADR 0007 governs subagent views; clone-first worktrees ship off and the owner confirms in one sentence. If the owner says yes, D2 and D3 are withdrawn, part (a) becomes class b and S1 to S3 are not built.
- **O2.** Default of `sv_worktree_clone` after soak. Upstream defaults it on (`upstream:packages/coding-agent/src/task/settings.ts:86`). Recommendation: keep it off. Flipping it changes `/wt` and forge checkout behaviour and needs its own record, after O8's numbers and one release.
- **O3.** `/wt` through `omp-vcs` when the convar is on. Recommendation: keep the git-binary flow when off and use `omp-vcs` when on, with a parity test for staged and unstaged edits; unify only in a later record.
- **O4.** The isolated view omits symlinks and empty directories: the manifest keeps regular files only and `create_worktree` clones manifest entries only (`crates/envd/src/workspace/operations.rs:1053`, `crates/envd/src/workspace/operations.rs:709-727`), so a tracked symlink is absent from a child's view and cannot appear in its patch. Read, not exercised. Recommendation: file it as a defect against ADR 0007 outside this record, write the failing test first, and treat any fix as a manifest change (`MANIFEST_MAGIC`, `crates/envd/src/workspace/operations.rs:52`) that needs the owner under additive-only.
- **O5.** `cp` and reflink. Upstream `cp` clones through `pi_iso::cow` (`upstream:crates/pi-builtins/src/cp.rs:7`, `upstream:crates/pi-builtins/src/cp.rs:2878`, `upstream:crates/pi-builtins/src/cp.rs:2947`), and ADR 0054's `cp` slice does not say what happens to that (`docs/adr/0054-shell-builtins.md:58`). Recommendation: if `cp` keeps reflink it consumes `omp-iso::cow` after S1 and never depends on `omp-vcs`; ADR 0054 should state which.
- **O6.** Who owns `scheme://` paths inside shell commands, which is `pi-vfs` upstream (`upstream:packages/coding-agent/src/internal-urls/url-filesystem.ts:1-14`)? ADR 0054 declined the crate (`docs/adr/0054-shell-builtins.md:38`) without naming an owner. Recommendation: ADR 0054's owner takes it or drops it with a recorded reason; it is not this record's.
- **O7.** Windows. Recommendation: defer. The trigger is a Windows CI job; block clone is then a small additive module in `omp-iso`.
- **O8.** Measurement. The repo holds no timing for isolation creation, merge or worktree add. Recommendation: add S3's optional P8 workload, and record W7 and worktree-add time on APFS and Linux before any default changes or any change to subagent isolation.
- **O9.** ovnfs. Recommendation: no spike until a trigger in D4 fires. If the owner wants one sooner, one macOS spike with three checks: a Seatbelt-sandboxed child using a checkout on the NFS loopback mount, the default class of `.env`-style files through `ovnfs explain`, and admin protocol drift (`upstream:packages/coding-agent/src/ovnfs/client.ts:21`).
- **O10.** Crate name. Recommendation: `omp-iso`, matching the gap ledger and upstream lineage, with the README stating the scope. `omp-cow` describes it better, and renaming is free until S1 lands.

## Acceptance tests

1. On macOS, `omp-iso` clones a nested tree with a symlink and a skipped top-level entry, refuses a non-empty destination and removes a partial destination on failure (S1).
2. `is_unsupported` is exactly the per-OS errno set and false for `ENOENT`, `EACCES` and `ENOSPC` (S1).
3. On Linux without reflink, `clone_tree` is `Unavailable` and leaves no destination; with reflink the files share extents; cases that need a capability print SKIP otherwise (S1).
4. `worktree_add_with` with `clone: Off` equals `worktree_add`, and the existing `worktree_add` tests pass unchanged (S2).
5. A clone-first worktree has the source's tracked, staged, dirty and untracked state; source-bound environment directories are not carried; sparse checkout, split index and any clone failure fall back to the ordinary checkout with the reason (S2).
6. With `sv_worktree_clone` off, `/wt` and forge checkout are unchanged (S3).
7. With it on, a macOS `/wt` worktree contains the source's ignored `node_modules/` or `target/` and no `pyvenv.cfg` directory; on Linux without reflink it succeeds through the ordinary checkout and says why (S3).
8. The importer maps v1 `worktree.clone` to `sv_worktree_clone` (S3).
9. No subagent-isolation test changes: `worktree_isolation_applies_clean_patch_and_preserves_conflict_recovery` and `p9_control_extension_is_rooted_in_the_isolated_worktree` pass unchanged (D1; `crates/app/tests/it/envd_workspace.rs:215`, `crates/e2e/tests/p9_isolation.rs:261`).

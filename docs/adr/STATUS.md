## Resolved by amendment (2026-10-04)

The owner brought these decisions in line with the code. Each ADR's decision text was edited and an `## Amendment (2026-10-04)` section records what changed and why.

- [0003](0003-one-authoritative-session-tree.md): the journal's closed typed entry vocabulary (12 kinds, `patch@1` among them) is the decision; the tree stays derived and replay deterministic.
- [0006](0006-host-policy-sandbox-stub.md): the eval parent bridge (`ParentSessionHost`) is a bounded exception to 'the stub never calls the host'; the minimized stub for remote targets is deferred to 0039. Nested native-tool calls from eval obey explicit `deny` and the request's roster restrictions without prompting; eval-level approval stays the unit of prompts, and per-call admission is deferred until route- or session-scoped approvals exist. In production only `__workpool__` is bound; completion, agent, concurrency and budget have no production host. Plan mode (2026-10-05): dispatch and the environment's writers both confine writes to the plan file, which `write` can now create at `local://PLAN.md`; children of a plan-mode parent are read-only; pre- and post-tool hooks fire for the outer `eval` call only, not for nested calls, until per-call admission exists.
- [0007](0007-subagent-filesystem-isolation.md): only per-file reflink with a copy fallback is implemented; other backends are future targets and not selectable. Code follow-up done: the inert `sv_task_isolation_mode` convar is deleted. Open gap kept in the ADR: gitignored files are not copied.
- [0023](0023-tiny-local-model.md): the `tiny` role resolves to a configured model (default `commit`, then `smol`, an online model); an in-process tiny generator is a future option. Code follow-up done: stale comments, caller-less title helpers, the caller-less difficulty classifier module and the unread `ai_*_selector` convars are removed.
- [0024](0024-small-permanent-roster.md): the wire roster is latched per session and every restriction refuses at dispatch; the one exception is the hidden `goal` tool, mounted once (monotonically) at the first user-initiated goal engagement. Open: Goal/prewalk/mode prompts still move the system prefix.
- [0028](0028-bash-is-an-in-process-interpreter.md): approval is the sandbox-denial-and-rerun model with a path or network fact as the unit; capability-level, pre-execution approval is not claimed. The overstating comment on the `bash@2` effects declaration was rewritten. 2026-10-06: the sandbox is on by default and the default `yolo` holds only inside an active sandbox; without one, `write` is in force and the shell prompts. An explicit `yolo` is respected and reported as unconfined. 2026-10-07: `sv_sandbox_network_mode` defaults to `scoped` (the session egress broker refuses hosts outside `sv_sandbox_allow_domains`, and the user can approve one rerun, or, since the session network grants amendment, the rest of the session); under an explicit `sv_sandbox_mode off` only a user-set `scoped` compiles a network-only sandbox; a broker that cannot start under the default disables the network with a session-note line, while a configured sandbox fails hard; eval cells and detached processes run with the network disabled; a workflow phase requiring a disabled network is refused under the default posture. Broker refusals from CONNECT/SOCKS authorization and upstream connect carry a typed cause (`policy`, `unresolved`, `non-routable`, `upstream`); only `policy` is an amendable denial and carries the `X-Omp-Policy-Blocked` header, while a fail-closed cause is answered `502` and leaves the command `Failed`. A shell command whose attempt recorded a refusal gets a `sandbox` diag naming the `host:port` (left out when it cannot be quoted), the mode and the remedy the first time the session meets that endpoint and cause (`info` on exit 0, `warn` otherwise), and later only a one-line `warn` when such a command fails; a failed command with a resolver or connection-failure marker and no refusal gets the generic text of the mode in force once per session. 2026-10-07 (approval relay): the amendment prompt goes first to the relay of the connection that issued the command, which only an application connection that advertises `approval-relay` has (never an extension connection), and otherwise to the route an in-process composition binds. A relay whose connection closed never falls back to that route, and named processes carry no relay. A project daemon binds no route; an attached session advertises `approval-relay` and answers the relayed prompt through its kernel route, where it is journaled like an in-process prompt, and a withdrawal or a closed transport withdraws it unanswered (2026-10-07 approval relay amendment). `dyn` admissions, privileged mutations and named processes on the daemon still fail closed. 2026-10-07 (session network grants): a network amendment offers `once` and `session` (a path amendment only `once`), and the environment honours only an offered scope. A `session` grant is kept by the approval binding that decided it (one daemon connection's relay, or the in-process route), admitted live by the broker for that binding's commands only, and cleared when the connection closes, the route is rebound, the conversation is rewound or the host switches to another session (new, resumed, forked or branched, handed off; the driver's session observer revokes it on a rewind and on `Kernel::session_switched`, over the wire with `RevokeApprovalGrants`, `SCHEMA_REV` 20); the approval desk refills it from the journal the session serves. A command may rerun again only for a new endpoint, at most `sv_sandbox_network_session_reruns` times (default 4); a `once` grant still ends the chain. An `sv_sandbox_deny_domains` hit is its own `deny-listed` refusal, never amendable and never prompted, and the network diag names the deny list. 2026-10-07 (typed confinement marker): `ToolSpec::confinement` (`Host` by default, `ExecSandbox` only for `bash@2` and `hub@2`, asserted by the registering host and never by a worker, extension or MCP declaration) replaces the `bash` name check; a defaulted `yolo` kept by an active sandbox covers only `ExecSandbox` tools, and a `Host` tool is admitted as if no sandbox existed, so its exec tier prompts (`eval`, `browser`, `web_search`, `github` and the like now prompt on hosts with an active sandbox), at the kernel, envd `InvokeTool` and `dyn` admission points alike; envd's write boundary refuses an `ExecSandbox` tool while a write scope applies; `/security` shows the mode in force for sandboxed and for host tools. `hub`'s peer and job operations are session-internal, not host effects; its undeclared peer steering and the write boundary's wholesale refusal of `hub` under plan mode would surface only if the session-tool admission bypass closes. Under-declared host effects (`read@3` fetch, `lsp` spawns, RPC and effect-less Python tools) stay auto-approved. 2026-10-07 (memory reflect inference): `reflect@2` declares its one inference request, so it is `exec` tier and prompts outside an explicit `yolo`, and never runs beside another call of its tool batch; the driver binds the session's reflection to its inference, one `@memory` request per call; an embedded `reflect` uses it directly, and on the default attached path the daemon relays each synthesis to the connection that issued the call (`reflection-relay`, `SCHEMA_REV` 21), falling back to the recalled evidence when that connection cannot answer. A `dyn` call to a native target keeps its argument feed alive while the target runs. 2026-10-08 (fetch tier): read-only egress is its own effect domain (`Effects::fetch`, `credentials`), and `ApprovalTier::Fetch` sits between `read` and `write`, so `always-ask` prompts for a fetch while `write`, the default posture and `yolo` allow it (`SCHEMA_REV` 22); no tool declares a fetch yet. 2026-10-08 (undeclared effects): a tool that declares no effects resolves to its host's ceiling instead of `read`: RPC host tools (`HostToolDefinition.effects`, absent means undeclared) and eval-defined tools register `Effects::unknown()` (any command with the network, `exec` tier), Python worker and frozen extension tools get document reads and `**` writes under a `sandboxed` host (`write` tier) and `Effects::unknown()` under a `trusted` one, consistently in the registry spec, the extension host route and the CONTROL tier snapshot; the kernel dispatcher admits host tools with their registered envelope; `debug@2` declares the network. 2026-10-08 (argument-scoped invocation effects): a tool that declares `Tool::ARGUMENT_SCOPED_EFFECTS` is judged per call by `Tool::invocation_effects`, which must stay within its declared maximum (a wider envelope is refused, never replaced by the maximum), on arguments decoded as one JSON object; the environment resolves approval and the plan-mode write boundary from that envelope at `ArgsCommitted`, only once its gate has staged the committed arguments (a commit the gate refuses leaves the call unjudged, pending and withheld), with a pending gate that streams nothing to the executor until then, re-judges a call an admission answer rewrites (and only such a call), and the kernel's native admission receives the same envelope. A `read_only` `computer` program keeps capture, accessibility and clipboard reads and loses input, which its host refuses before each such operation; clipboard reads are now declared desktop authority (`SCHEMA_REV` 23). Its tier stays `exec`: until the owner decides how desktop reads are approved, every desktop authority is `exec`, so the narrowing changes no prompt; every other tool keeps its maximum. 2026-10-08 (host-keyed fetch subjects): under `always-ask` a fetch is asked once per host per session. A declaring tool names the URLs its call fetches (`Tool::fetch_locators`), the environment names the host each reaches with the resolver that performs it (the authored host and port of an http(s) URL, the GitHub host of `issue://` and `pr://` from the URL or the workspace remote, the `ssh://` alias, the MCP server advertising an `mcp://` resource), and the admission query reports the judged envelope and those hosts (`AdmitInvocation.effects = 4`, `fetch = 5`, typed `omp.policy.v1.FetchTarget`, `SCHEMA_REV` 24). The session asks one `network` requirement per host (`tool:<name>` when none was named), and the tool itself only above the fetch tier; every requirement offers `once` and `session`, so a grant for one host never covers another. `dyn` prompts offer the session too, an MCP fetch keyed by its server; ACP shows a `network` requirement as a `fetch` tool call. No built-in tool names fetch locators yet.

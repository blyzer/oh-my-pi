Status: Proposed 2026-11-14; EGM round 1 resolved, rounds 2-3 pending

## Context

- Upstream keeps a deterministic floor under LLM fact extraction. `heuristicExtractFacts` turns eight English first-person patterns into at most five facts (`upstream:packages/mnemopi/src/core/extraction.ts:276-315`); `extractAndStoreFacts` adds metric, date, version and relation patterns (`upstream:packages/mnemopi/src/core/beam/consolidate.ts:675-783`). Both run when no model resolves: `llmMode` is `none`, or `smol` with no `memory` role model (`upstream:packages/coding-agent/src/mnemopi/backend.ts:539,558-563`; `upstream:packages/mnemopi/src/core/extraction.ts:432-443`).
- omp2 has the seam and nothing behind it. `ExtractionLane` has no implementor and `pending_extractions` has no consumer (`extract.rs:30-35`, `store.rs:571-599`; a repository search finds both only in `crates/memory/src`). Nothing outside `crates/memory/src` calls `retain_settled`, `shutdown_flush` or `SessionMemory::enqueue`; `RegisteredMemoryRuntime::session` hands out the top-level handle and has no caller (`crates/envd/src/memory.rs:100-102`). The finalizer slot `set_mnemopi` has no production registrant and nothing calls `finalize` (`crates/driver/src/headless/finalize.rs:100-136`). `HostSettings::from_con` never sets `llm_mode`, so production is always `smol` (`crates/envd/src/host_settings.rs:204-234`; `config.rs:306`).

The sink `BankStore::save_extracted_facts` exists (`store.rs:706-710`), and `complete_extraction` stores a job's facts and deletes the job in one transaction (`store.rs:712-760`).

Upstream has validity on memory rows and triples, not on facts: `valid_until TEXT` compared with an ISO string (`upstream:packages/mnemopi/src/core/beam/schema.ts:414`, `upstream:packages/mnemopi/src/core/beam/helpers.ts:200`); its `facts` table has no such column (`upstream:packages/mnemopi/src/core/beam/schema.ts:346-356`).

Column additions (`migrate_authoritative_tables`, using `add_column_if_missing`) run only when `version < SCHEMA_VERSION`, together with `RESET_REBUILDABLE_INDEXES`, which drops the FTS tables, `memory_embeddings`, `triples` and `memory_links` and zeroes the vector and graph generations (`store.rs:1220-1233,1642-1658`). So no path today adds a column without a bump. Every reader and writer of `facts` names its columns (`store.rs:379,734-735,832-836,957-959,1666`).

## Decision

**D1. Rules are a floor, used only when no memory model is available.** The rule extractor runs when (a) `llm_mode` is `none` and `sv_memory_rule_facts` is on, or (b) the configured lane reports `LaneFault::Unavailable` and the caller passes `FallbackPolicy::Rules`. It MUST NOT process text that a model lane processed or is processing. A model that is available and fails transiently is retried and NEVER replaced by rules (`store.rs:712-715`). Rules MUST NOT call any model, hosted or local (ADR 0023 rule 4, `docs/adr/0023-tiny-local-model.md:36-38`). This reads "no memory model is set" as upstream does (`backend.ts:539,558-563`); see O1.

**D2. Facts may expire.** `facts.valid_until INTEGER NULL` holds the exclusive end of validity in UTC epoch milliseconds (INTEGER, not upstream's ISO `TEXT`, so the comparison is exact and offset-free). Producers are the rule extractor and the optional sixth field of a `FACT` line: RFC 3339, or `YYYY-MM-DD` meaning valid through that UTC day. Five-field lines stay valid; a malformed sixth field rejects the line as a malformed confidence does. With `sv_memory_fact_expiry` on, `search_facts` excludes facts with `valid_until <= now` in its `WHERE` clause, ahead of `LIMIT`, so expired rows cannot use up result slots; read-by-id (`store.rs:955-963`) still returns them. Everything about expiry is behind `sv_memory_fact_expiry`: the column, writing it, the sixth field and the filter. With the gate off no producer writes `valid_until`, `parse_facts` rejects six fields as today, and `search_facts` does not filter.

**D3. The column is additive, added only when the gate is on, and `SCHEMA_VERSION` stays 3.** `BankStore` gains `open_with(path, bank, root, BankOptions)` beside `open` (`store.rs:193`), which keeps its signature and means `BankOptions::default()`. When `BankOptions.fact_expiry` is true, `migrate` runs one new step inside its existing exclusive transaction (`store.rs:1215`), after `SCHEMA` (`:1224`) and on every open whatever the version: `add_column_if_missing(facts, valid_until, INTEGER)` (`store.rs:1360-1371`). With the gate off, the schema text, the migration and the bank file are exactly today's. Why no bump: a bump runs `RESET_REBUILDABLE_INDEXES` on every bank, so every user re-embeds and the vector and graph generations reset, and it makes every older binary refuse the bank (`store.rs:1217-1233,1642-1658`), which breaks rollback and any older omp sharing it (the store is "Multiprocess-safe", `store.rs:1`). A nullable column that no trigger, index or statement of an older binary names needs neither: their INSERT and SELECT name their columns (Context), and they simply do not filter. Concurrent first opens add the column once because the step runs under the exclusive transaction. Once added the column stays; turning the gate off leaves it NULL-filled for new rows and unread. Rule for later changes: a nullable column nothing else touches MAY be added this way; a change to meaning, a derived index or a constraint MUST bump. Upstream's `facts` table has no counterpart, so this is a schema extension the owner asked for (owner decision 2), not a port; the mechanism needs the owner's confirmation (O3), and slice S3 does not merge until O3 is answered.

**D4. Rule output is typed, closed and bounded.** Triples over a closed predicate vocabulary: `name`, `is`, `works_at`, `lives_in`, `uses`, `prefers`, `dislikes`, `instruction`, `version`, `depends_on`, `dev_depends_on`, `requires_runtime`, `decided`, `rejected`, `stopped_using`, `deadline`, `status`. Subjects are `user`, a package or tool name, or `project`. Ids are `rule_` plus 24 hex of `Hash32` over source id, rule id and the triple, so replays are idempotent under `INSERT OR IGNORE` (`store.rs:733-737`). At most 32 facts per source memory; subject at most 128 bytes, object at most 240 (inside the parser limits, `extract.rs:114-119`). Confidence 0.9 structured, 0.7 prose, 0.6 decisions and bounds. Rules take time as an argument and MUST NOT read a clock. `NewFact.timestamp` is the job's `created_at` (`store.rs:533`). Precision over recall: questions, hypotheticals, negations, fenced code and clauses near a secret word produce nothing.

**D5. Structured tool results first.** The extractor takes typed `ToolObservation { tool, target, output }` inputs and parses them with named-field parsers over typed serde structs (`package.json`, `Cargo.toml`, version banners of a closed tool set) before any prose rule; text a parser consumed is excluded from the prose pass. Selection keys on tool and target and MUST NOT sniff content. Free-text fields and credential-like keys are never read. Tool output feeds rules only, never a model lane: `ExtractionRequest.input` stays user-authored only (`extract.rs:22`; `retain.rs:177-187`).

**D6. English and Spanish are data tables.** Families: identity and preference, versions, dependencies, decisions, supersession, explicit bounds. Neutral Spanish, matched accent-insensitively. Dates are ISO and English or Spanish month names; numeric and relative dates are not parsed in v1 (O5).

**D7. Gates: four convars, each default-off or default-unchanged; no `cap-*` feature.** Declared beside `SV_WORKTREE_BASE` in `crates/envd/src/host_settings.rs` (`:139`), read in `HostSettings::from_con` (`:204-234`), and carried to `omp-memory` as `#[serde(default)]` fields of `MnemopiSettings` (pattern `config.rs:196-198`), so `omp-memory` gains no `omp-con` dependency:
- `sv_memory_session_retention` (bool, off): the master gate. Off, no memory host is attached and no retention, extraction or consolidation runs (D11).
- `sv_memory_llm_mode` (enum, default `smol`, today's value): offers `none` and `smol`; `local-memory-model` is offered only in builds with `omp-memory/apple-aux-memory` (S7). `remote` is not offered.
- `sv_memory_rule_facts` (bool, off) → `MnemopiSettings.rule_facts`.
- `sv_memory_fact_expiry` (bool, off) → `MnemopiSettings.fact_expiry` → `BankOptions.fact_expiry`.
They use the `sv_` prefix as omp2-native host policy; the `ai_mnemopi_*` family carries pi-era `legacy.path` aliases (`host_settings.rs:85`). There is no `cap-*` feature because nothing adds build weight: `regex` is a workspace dependency (`Cargo.toml:215`), and the Apple lane reuses the existing `apple-aux-memory` Cargo feature. With every gate at its default, behaviour and the bank file are byte-identical to today.

**D8. Typed lane faults and a bounded worker.** `LaneFault { Unavailable, Rejected, Transient }` travels in a new variant `Error::Lane { fault: LaneFault }` (ADR 0035, `docs/adr/0035-rust-for-the-engine.md:54-55`; no string payload) beside the coarse `AuxiliaryCompletion` (`crates/memory/src/lib.rs:63-65`). `ExtractionLane` keeps its signature (`extract.rs:31-35`). A worker function `drain_once(runtime, lane, policy, budget, cancel)` drains `pending_extractions` and applies the policy: `Unavailable` with `FallbackPolicy::Rules` runs the rules on the job's whole input and completes the job with rule facts only; `Unavailable` without it leaves the job queued; `Transient` leaves the job queued and backs off (5 s, doubling, capped at 300 s, in memory, reset on success); `Rejected` runs the rules if the policy allows, else acknowledges the job with no facts so it cannot loop. Jobs left queued are bounded by working-memory eviction, which deletes them with their episode (`store.rs:1599-1605`). Its production caller is the memory host (D11) in every mode except `none`; until S7 binds a lane, every such mode has no lane, which the worker treats as `Unavailable`.

**D9. `local-memory-model` uses the existing Apple FM backend, one bounded request per chunk.** A module `crates/memory/src/aux_extract.rs` beside `aux_lane.rs`, behind `apple-aux-memory`, implements `ExtractionLane` over `AppleFm::generate` (admission, deadline, cancellation, token cap), not `AppleFmSession::respond`, which has no token cap or cancellation (`applefm.rs:428-435,507-537`). Bounds:
- **Availability.** One `AppleFm::availability_evidence()` probe per drain pass (`applefm.rs:406-424`). `ModelNotReady` (downloading or preparing) maps to `Transient`; every other state except `Available` maps to `Unavailable`. On Linux the stub reports `unsupported_operating_system` (`applefm.rs:77-79`), so the lane is `Unavailable` there and the rules run under `FallbackPolicy::Rules`.
- **Chunk.** The job input is split on paragraph, then sentence, then character boundaries into chunks of at most 4096 bytes. At most 8 chunks per job, so at most the first 32 KiB of a job reaches the model; the remainder is counted as unprocessed and not sent.
- **Request.** `AppleFmOptions::new(chunk).system_prompt(PROTOCOL).temperature(0.0).max_tokens(512)`, `permissive` left false (`applefm.rs:320-354`). `PROTOCOL` is a fixed, golden-tested prompt of at most 2048 bytes (the `FACT` protocol, the D4 vocabulary, and the sixth field only when expiry is on); it lives in a static `.md` file, not in code.
- **Token budget.** By the backend's own estimate (bytes / 4) a request is at most (4096 + 2048) / 4 = 1536 prompt tokens plus 512 answer tokens = 2048 of the 4096-token window, so a real tokenizer may be up to twice as dense as the estimate before the window overflows. An overflow is handled by the fault table, not prevented by measurement (O9).
- **Time.** Each request is bounded by the backend's 30 s deadline and a cancellation token that is a child of the worker's shutdown token. At most 8 requests per job, counting the split retries below, so one job takes at most 240 s. One job is in flight at a time (the backend has one permit). A pass handles at most 4 jobs and starts no request after 300 s, then waits for the next queue notification (`runtime.rs:961-973`) or backoff tick.
- **Output.** Per chunk at most 512 tokens; the joined completion is bounded by `MAX_EXTRACTION_OUTPUT_BYTES` (`extract.rs:13`). Only lines starting with `FACT` and a TAB are kept, so `parse_facts` stays the single parser.
- **Faults per request.** `ModelUnavailable`, `DeviceNotEligible`, `AppleIntelligenceNotEnabled` → `Unavailable`. `ModelNotReady`, `TimedOut`, `RateLimited`, `ConcurrentRequests`, `Cancelled` → `Transient` for the whole job (earlier chunks' lines are discarded; the job stays queued). `Runtime` → re-probe once: `Available` means `Transient`, anything else `Unavailable`. `ContextOverflow` → split the chunk in half once (consuming request budget), then skip it. `GuardrailBlocked`, `UnsupportedLocale`, `UnsupportedGuide`, `DecodingFailure` → skip the chunk. `InvalidInput` → skip the chunk (a programming error, logged at error). A busy permit never blocks: the job stays queued behind the user's chat.
- **Fallback.** `Unavailable` at any point discards the job's model lines and, under `FallbackPolicy::Rules`, runs the rules on the whole input (D1, D8), so a job never mixes producers. Skipped chunks get no facts; the rules do not cover them in v1 (D1; O13). The lane never falls back to another model.

**D10. Facts stay immutable.** There is no mutation path. A newer fact does not expire an older one; the rules emit `stopped_using` and `uses` facts instead.

**D11. Session wiring: a native hook host in `omp-driver` calls `SessionMemory`, and `session.rs` runs the rules itself in `none` mode.**
- *Host.* `crates/driver/src/memory_retention.rs` defines `MemoryRetentionHost: NativeHookHost`. `compose_kernel` attaches it to the admission gate next to the plugin host (`kernel.rs:3098`) only when `sv_memory_session_retention` is on, the new field `KernelOptions.memory_retention: bool` (default false) is true, `options.parent_session` is `None`, and the runtime is active. Only `ChatCommand::compose` sets `memory_retention` (`crates/app/src/chat_cmd.rs:747-760`), so interactive, print, RPC, ACP and share sessions retain and `/btw`, tan jobs, subagents, workpools, adw, cleanse, compress and standalone tools never do. The host declares `turn_end` and `session_shutdown`; it holds one `SessionMemory` from `RegisteredMemoryRuntime::session` (`crates/envd/src/memory.rs:100-102`) and the current journal path from `session_switched` (`hooks.rs:733-747,779-783`).
- *Turn end.* `observe(turn_end)` does a `try_send` of a unit signal onto a bounded `flume` channel of capacity 1 and returns; it never blocks the loop. A retention thread owned by the host coalesces signals, reads the journal with `Journal::scan` (no writer lock), takes the live chain, projects it purely to `OwnedRetentionMessage` (user, assistant and tool-result entries; `stable_id` is the entry id; `retain.rs:31-40`) and calls `retain_settled` (`session.rs:131-158`), whose durable cursor decides whether a window is due (`retain.rs:109-127`). In model modes it then runs `drain_once` on the same thread with the D8 budget.
- *Session end.* `decide(session_shutdown)` asks the retention thread to run `shutdown_flush` (`session.rs:181-209`) and then `MemoryRuntime::enqueue` (consolidation, `runtime.rs:766-778`), waits for it for at most `SESSION_SHUTDOWN_BUDGET`, and returns `NativeReply::defer()` (`hooks.rs:563-567`); the verdict is ignored (`hooks.rs:770-772`). Work still running at the deadline stays detached, as `shutdown_flush` already allows (`session.rs:171-174`); unretained turns are retained on resume because the cursor is durable. The 1.5 s budget is tight for consolidation (O12). `session_switched` must not block (`hooks.rs:778-783`) and arrives whether or not the old session's end ran: the host queues the old session's finish (as above, unless `shutdown_flush` already ran; its `closed` flag makes a second call a no-op, `session.rs:182-187`) on the retention thread without waiting, and then stops retaining for the rest of the process, logging once. Reason: the runtime's session id is the environment's, fixed at start (`crates/envd/src/server/session.rs:39-63`), and the retention cursor is keyed by it (`store.rs:545-550`), so the next journal's user turns would be counted against the previous journal's cursor (O14).
- *`session.rs` in `none` mode.* Both `retain_settled` and `force_retain_runtime` compute `extraction_enabled = llm_mode != None || rule_facts` (replacing `session.rs:151,227`); with `rule_facts` false this is today's predicate. After the retainer returns, when `llm_mode == None && rule_facts`, they call `extract::rules::drain_session(store, session_id, now)`, which reads this session's queued jobs through a new `BankStore::pending_extractions_for_session(session_id, max_jobs)` (same bounds as `store.rs:571-599`), runs the rules, and calls `complete_extraction` per job, so facts and the job's deletion commit together. The job row is written in the retention transaction (`store.rs:527-536`), so a crash between retention and the drain leaves the job queued and the next retention or shutdown of the session drains it. The drain reads only this session's jobs because another process sharing the bank may run a model mode, and D1 forbids rules on its jobs. `now` is read once by the caller and passed in. A drain error is logged with its typed error and does not fail retention. `RetentionOutcome` gains `rule_facts_inserted: usize`.
- *Project daemons.* A session attached to a project daemon has no wire message for memory (research note 2.2); the host is attached only when the runtime is in-process and active, else it logs once and attaches nothing (O2).

## Alternatives considered

| Option | Why not |
|---|---|
| Literal port of the upstream patterns | English only; key/value rows would index as "version version 1.2.3"; no decisions or dependencies. |
| Rules as an `ExtractionLane` emitting `FACT` text | Formats and re-parses on every pass, loses typed fields; `none` mode has no lane. |
| A model for Spanish and technical facts | Against deterministic-first and D1; useless offline. |
| A Python extension | The work belongs in the retention transaction in Rust; an extension runs on the embedded interpreter outside it (ADR 0036, `docs/adr/0036-python-for-extensions.md:37`). |
| Bump `SCHEMA_VERSION` to 4 | Index reset and re-embedding for every user and older-binary lock-out (D3); kept as the alternative in O3. |
| Add the column on every open regardless of the gate | Changes every user's bank file with every gate off. |
| A side table of expiries; expiry encoded in text | A join on every recall; unqueryable. |
| Rules inline in `retain_window`'s transaction | Needs `RetainedWindow` to carry facts computed before the memory id exists (`store.rs:490-496`), and a second persistence path beside `complete_extraction`. |
| Rules after retention through `save_extracted_facts` with no job | Not crash-safe: a crash after the episode commits loses the facts for good, because the cursor has moved (`store.rs:545-550`). |
| A memory Director registered by `compose_kernel` | It journals a `<director>` node, and `from_dom` stops the active chain at an unconstructible node (`crates/contract/src/director.rs:855-857`): turning the gate off later would hide every Director engaged below it. Retention claims no slot, so it is not control. |
| The headless finalizer's Mnemopi phase | No owner calls `finalize` (`crates/driver/src/headless/finalize.rs:118-136`); each of five modes would need its own close call, where `session_shutdown` already reaches every mode. |
| A flag in the agent loop, as autolearn does | The loop is a generic hook surface (`AGENTS.md`, "Locked Deviations"); it would couple `omp-agent` to `omp-memory`. |
| Fill `turn_end`'s `items` with the transcript | Changes an existing hook payload (`crates/agent/src/loop.rs:1846-1856`), which the additive rule forbids. |
| Sniff `Tool`-role text | `RetentionMessage` carries no tool name or path (`retain.rs:43-50`). |
| `AppleFmSession::respond` or the `local` provider route | No token cap or cancellation and a hard-wired scoring prompt; or chat-event streaming for a one-shot job (`crates/driver/src/registry.rs:1589-1604`). |
| A separate `sv_memory_local_extraction` convar | Selecting `local-memory-model` in `sv_memory_llm_mode` is already the opt-in, and the value exists only in builds with the feature. |
| One enum convar instead of four | Kept as O8. |

## Consequences

- A user who turns on `sv_memory_session_retention` gets episodes retained and recallable from interactive, print, RPC, ACP and share sessions, which nothing does today. With rules on and no model, they get recallable facts in English and Spanish, including versions, dependencies and decisions read from tool results; with expiry on, facts can expire. The Apple FM lane is bounded (4 KiB chunks, 8 requests and 240 s per job, 512 answer tokens) and cannot starve chat. With every gate at its default nothing changes, including the bank file.
- Prohibited: rules calling any model or touching another session's jobs; mutating a fact; tool output reaching a model lane; a JS/TS rule engine; falling back from the local lane to any other model; a memory Director.
- Costs accepted: a `regex` dependency in `omp-memory`; four convars; a column added without a version bump, setting the D3 precedent; older binaries ignore expiry; one journal scan per coalesced turn end on a background thread (unmeasured; the P8 recorder can measure it); the predicate vocabulary becomes a contract that the model prompt must follow; the 32-fact cap, confidence bands, 4 KiB chunk, request and pass budgets are starting values; Spanish only; trailing turns and consolidation can miss the 1.5 s shutdown budget (O12); only the first session of a process retains (O14).

## Open questions for the owner

- **O1. What "no memory model is set" means.** D1 reads it as `llm_mode = none`, or a lane that reports `Unavailable` under an explicit `FallbackPolicy::Rules`, as upstream does. The narrow reading (`none` only) leaves the rules unreachable under the default `smol`. Recommendation: D1.
- **O2. Project-daemon sessions.** No wire message carries memory, so a daemon-attached session stays inert (D11). Recommendation: a follow-up ADR adds a memory lifecycle message; the rules need no inference, so a daemon-side host would work once turns reach it.
- **O3. Additive `valid_until` column without a `SCHEMA_VERSION` bump (D3).** This extends the existing `facts` schema, which the additive rule asks the owner to rule on. Recommendation: confirm D3 (column only when `sv_memory_fact_expiry` is on; no bump). Alternative: bump to 4 and accept the index reset and the older-binary lock-out. S3 waits for the answer; S1, S2 and S4-S7 do not depend on it.
- **O4. Date-only bounds are UTC.** "Valid through that day" ends at the next UTC midnight. Alternative: local time.
- **O5. Numeric and relative dates are out of v1.** Revisit when `RetentionMessage` carries message timestamps (`retain.rs:43-50`).
- **O6. ADR 0049 and a vendor name in a core crate.** The lane follows the `aux_lane.rs` precedent because `omp-ai` cannot depend on `omp-memory` (`docs/adr/0049-tiered-integration-architecture.md:15,47,130`: inference transports are Class B). Recommendation: precedent now; move behind a host-injected lane if the owner wants it out of `omp-memory`.
- **O7. Provenance.** The `rule_` id prefix marks rule facts; a `facts.extractor` column is the alternative (another schema change). Recommendation: the prefix.
- **O8. Gate granularity.** Four convars, or one enum. Recommendation: four, each independently reversible.
- **O9. Apple FM device evidence:** guardrail mode (`permissive` stays off), the 4 KiB chunk and the token headroom (the backend estimates bytes / 4, `crates/ai/src/local/applefm/platform.rs:823-833`). Measure with `crates/ai/examples/applefm_smoke.rs` before moving a default.
- **O10. Languages.** Spanish only. Upstream's detector also knows Russian and German (`upstream:packages/mnemopi/src/core/beam/consolidate.ts:555-612`); each language needs reviewed vectors.
- **O11. Default `FallbackPolicy`.** `Rules` when `sv_memory_rule_facts` is on, else retry only. Recommendation: confirm.
- **O12. Shutdown budget.** `session_shutdown` waits 1.5 s (`hooks.rs:571`); `shutdown_flush` allows 30 s (`config.rs:281-283`), and consolidation scans every scoped working row (`runtime.rs:766-778`). If it misses, unconsolidated episodes and their facts are evicted after 24 h (`config.rs:266-268`; `store.rs:1599-1605`). Options: accept; consolidate on the retention thread after each periodic retention; or a longer budget for this host, which would change the shared hook contract. Recommendation: accept for S1, measure, then decide.
- **O13. Chunks the model skipped.** D1 keeps rules off text a model processed; a skipped chunk (guardrail, locale, overflow) therefore yields no facts. Alternative: rules cover skipped and unsent spans. Recommendation: keep D1 for v1.
- **O14. Retention after an in-process session switch.** `/new`, `/resume` and hand-offs keep the environment and its memory runtime, whose session id and cursor belong to the first session (D11). Options: retain only the first session (D11 for v1); restart or re-key the runtime per journal, which changes `omp-envd`'s runtime lifecycle. Recommendation: v1 as D11; a follow-up decides with O2.

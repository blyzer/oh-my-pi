# omp-e2e

`omp-e2e` is the non-publishable joined-system acceptance suite for the journal-first OMP spine. Tests use `omp-agent`, `omp-session`, `omp-journal`, `omp-driver::headless`, and the production environment and document authorities; no test constructs the removed legacy agent, transcript store, settings host, or chat actor.

## Harness contract

Scenario bodies live in `tests/`. `src/support` owns bounded waits, RAII process and daemon lifetimes, scratch roots, production document/environment connections, canonical scripted inference, and `.oms` session reopening. Scripts replace only nondeterministic provider output. The journal, DOM fold, dispatcher, document authority, environment authority, and terminal event path remain production implementations.

Every wait is bounded. Every process, task, socket, and temporary root has an RAII owner. Test builds are LLVM (`[profile.test]` in `.cargo/config.toml`), so a failing proof's panic runs those destructors. As defense in depth for panics that run none (an abort, or a Cranelift test build, which emits no landing pads), owned process groups are also leased in a registry that a panic hook kills from, scoped to the panicking thread (`src/support/owned_groups.rs`). P7 drives the Cargo-built application on a real PTY through the debug protocol. P8 records measurements and locks their schema and arithmetic, but timing values are deliberately non-gating.

## Proofs

- P1: concurrent document leases preserve pinned reads and rebase non-overlapping stale writes.
- P2: `CancelTree` scope semantics and kernel `Up::Interrupt` / `Up::Cancel` preserve journal consistency.
- P3: dispatcher timeout settlement and `<meta><jobs>` / `JobBoard` lifecycle use one detached-job primitive.
- P4: only the live tool schema is advertised and `tool.call@1` records its selected `rev`.
- P5: Frozen, Stable, Dynamic, and Volatile prompt-band hashes preserve the provider cache prefix.
- P6: a killed mid-turn writer loses only a torn tail; `Session::open` reproduces the last committed DOM snapshot.
- P7: the production chat host handles input, streamed cards, resize, replay, and clean terminal restoration.
  Its plugin-approval case launches chat over installed plugins whose commands nobody approved and proves in-chat approval on the PTY: the blocked-launch notice, the `/plugins approve` selector (rows, command tails, `--plugin-dir` footer, arrow + Enter), persistence read back through `omp ext trust --show` while chat runs, a resize that keeps the box intact and the cursor on the selected command, the direct `/plugins approve <plugin> all` form, and clean quit.
  Its daemon-amendment case runs chat on the shipped default posture, attached to the project daemon it spawns itself (the environment socket is keyed by chat's own build and by its sandbox and approval policy, so the test never starts one). A scripted bash call writes `$$` into the protected `.git`; the sandbox denies it and the daemon relays the amendment to chat's overlay, which offers only approve and deny because the amendment offers only `once` (`a`, approve for session, is no answer there). `y` approves: the rerun writes the pid of a live process of the same executable that is not chat, so the daemon ran it. `Esc` denies a second call, which writes nothing and settles `denied`. The journal replays both decided `once` prompts, and quitting restores the terminal. That chat never fell back to an embedded environment rests on that pid and on chat's log, which the case reads from a state directory pinned under its isolated home, with `OMP_LOG` cleared so the default filter keeps the WARN line a fallback writes; the app paints no fallback notice, so the screen checks for one prove nothing today. It needs Seatbelt, so it exists only on macOS, where a failed Seatbelt probe fails it.
  Its native-surface case (`p7_tsp`) drives chat against a scripted fake Tern on the PTY master: the master answers (or withholds) the `hello` query, applies every frame with the reference applier in `omp_tui::tsp::doc`, and acknowledges frames on demand, so the document that applier builds is the oracle. It covers the optimistic start (the first frame precedes any reply), the negotiated handshake (`hello` before the DA1 fence), the regions/composer/status band the presenter mounts, UTF-16 cursor mirroring, `settle`, credit-limited frames released by an `ack`, overlays that suspend and resume the surface, re-entry with `adopt` and a `gone` event that reopens, every fallback (DA1 first, a late DA1, the one-second silent window, a multiplexer, `OMP_TSP=0`), the JSONL recording in both pacing modes, and clean terminal restoration.
- P8: the non-gating performance recorder. `tests/p8_baselines.rs` locks the artifact schema and the statistics arithmetic. The `baseline` bin records the retained-frame, kernel-loop and replay measurements and the audit's envd workloads W1 through W9 (ADR 0045, audit 12.1) against real authorities: embedded (`InProcessEnvHarness` over `EnvClient::in_process`) and attached (a production `envd` child behind a `PartitionedEnvTransport`, with an in-process local host beside it), each cold (a fresh authority for every repetition) and warm (one authority, an unmeasured warm-up first). Every cell is repeated 30 times by default and summarized as p50, p95 and median absolute deviation in `target/e2e-artifacts/p8-baselines.json`, beside the host, commit and build it describes. W1 leases, reads and closes a 1 KiB document 1,000 times through the versioned document API; W2 leases a document, commits a byte edit to it and closes it, ten times a repetition instead of the audit's 200 because the document authority holds every commit that no language server answers for a 500 ms diagnostics settle; W3 runs `true` in a server-owned exec session; W4 consumes the complete exec stream of outputs of 63 KiB, 65 KiB, 7.9 MiB and 9 MiB and fetches the projected artifact; W5 searches a 3,000-file repository with the shell `grep`; W6 invokes registered Python extension tools; W7 creates, uses and destroys 1, 4 and 8 worktree-backed slots; W9 times a cold and a warm attach. W8 is a correctness gate rather than a measurement: SIGKILL of the attached daemon must give every in-flight remote call a typed terminal error within the interrupt grace, leave the local host serving what was in flight on it, leave no call pending and no process behind, and end the router only because its client closed; embedded, cancelling one command must do the same for that command and spare an unrelated one. A failed W8 check fails the recording, so W8 is recorded first. The harness runs every authority with its user roots isolated under a private directory and reaps the extension host and other processes an in-process authority leaves running after it stops (the authority has no public stop for them). `cargo run -p omp-e2e --bin baseline -- --workload W1 --mode embedded --daemon-state warm --samples 3` records one cell group; `--samples`, `--mode`, `--daemon-state`, `--workload` and `--artifact` select the rest. The recorder spawns the extension-host-capable `omp_e2e_host` that Cargo builds beside it, so build both: `cargo build -p omp-e2e --bin baseline --bin omp_e2e_host`.
- P9: isolated environment worktrees and extension Director/Component registration.
- P10: historical tool lifts are idempotent and the lifted live revision executes through `Dispatcher`.
- P11: a spectator converges with a headless collaboration host through a real socket relay (`omp_collab::test_relay`). A viewer and an editor join a session with history, survive a partition, and receive the patches of a guest-driven turn; the host refuses a viewer's mutation (client API, no token, forged token); the relay only carries ciphertext; the room is listed in the local host registry while it lives; departures and room close are announced.
- P12: the production `omp envd` child (attached to a real docserver, with its home and user roots under scratch so the shipped `workspace-write` sandbox applies) relays a sandbox amendment prompt only to the connection that issued the command, on the issuing request. Another connection's forged answer decides nothing; the owner's denial denies; its approval reruns the command once, the `$$` it writes is the daemon's pid, and the daemon never withdraws the prompt that owner answered. Cancelling withdraws the prompt before the exit; closing the issuing connection ends its command without writing and frees the session at once. That close also cancels the command, so the relay failing a prompt closed on disconnect is proven by the `closing_a_connection_disconnects_its_relay` unit test in `crates/envd/src/server.rs`, not by P12. It needs Seatbelt, so CI runs it on macOS: it skips off macOS, and on macOS a failed Seatbelt probe fails it.
- P14: a read-only observer converges with a live session over the owner socket. A production kernel, the socket with its permissions and identity interceptor, and the generated gRPC client prove convergence from a snapshot plus ordered events, a detached observer replayed from the ring on resume, a foreign epoch answered with a resync and a fresh snapshot, a host killed without unlinking its socket replaced on the same path with a new epoch, host-local properties blanked in place for a caller without `observe_host_local`, and all four mutating verbs refused.
- `tool_sources`: production environment source routing and shared document snapshots.

`just e2e-build` compiles the suite. `just e2e` runs P1–P7, P9, P10, P11, P12, P14, and `tool_sources`, then runs the non-gating P8 recorder test. Individual groups are available as `e2e-core`, `e2e-p7`, `e2e-p8`, `e2e-p9`, `e2e-p10`, `e2e-p11`, `e2e-p12`, and `e2e-p14`.
